## Email Automation — close two gaps found while testing the Settings API live

### Backend

- `bank_code` can no longer be duplicated across `rules` in one `PUT /settings` — a
  second rule for the same bank (or a second `bank_code: null` "Other" rule) now gets
  `422 duplicate_bank` instead of silently being stored twice. Found while poking the
  API by hand: nothing stopped it, and `_merge_rule`'s dict-by-bank_code lookup meant
  the two rows would silently fight over which one's stored password won.
- New `GET /api/v1/carmen/bank-codes` — not tenant-scoped, just the current valid
  `bank_code` values for a rule. Backed by the same `banks` table the OCR wizard
  already reads (`services/email_settings_service.list_bank_codes`), replacing the
  hardcoded `SUPPORTED_BANK_CODES` set that `save_settings` used to validate against
  internally — one registry now, not two to keep in sync when a bank is added.
- [`routers/email_automation.py`](../backend/app/routers/email_automation.py) — wires
  the new endpoint behind the same `_caller` auth as everything else in this router
  (admin JWT or a Carmen token), no host/bu params since bank codes aren't per-tenant.
- Tests: `test_email_settings_service.py` (+4 — duplicate bank, duplicate "Other",
  `list_bank_codes`, updated `unsupported_bank` case to mock the new DB-backed check)
  and `test_email_automation_router.py` (+2 — 401 without auth, happy path). All 61
  affected tests green.

### Docs

- `docs/CARMEN_API_SPEC.md` → v2.1 — new §0 for `GET /bank-codes`, `bank_code` row in
  §2's Rule table now points there instead of a hardcoded list, `duplicate_bank` added
  to the Errors table.
- `docs/CARMEN_INTEGRATION.md` §2.3 — same swap, hardcoded bank list → pointer at the
  new endpoint, plus the one-rule-per-bank_code constraint spelled out.

### Found live, not from a test suite

Both gaps surfaced from manually exercising `PUT /settings` against the local dev
server (Bruno collection from the same session) rather than from a written test —
recorded here since neither would have been caught by the existing suite before today.
