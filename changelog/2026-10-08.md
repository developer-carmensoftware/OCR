# 2026-10-08

## Frontend (branch `fix/ca-121-sso-link-same-tab`)

`09:20` **CA-121: a Carmen SSO link opened in an already-open tab now signs in as its own BU (`1c6a16b8`)**
- **Bug** (found by the 2026-10-07 `#/pms` SSO test, T7/T9): a link landing in a tab that already
  runs the app changed only the hash, so no exchange ran. Effects:
  - the tab stayed on the previous BU; on `#/pms`, Create would have made *its* key;
  - the token stayed in the address bar and history;
  - a second link for the **same** BU never stored the token Carmen had just minted. That one
    kills the old token (decision #35), so `email-settings` kept a dead posting credential.
- **Fix:**
  - `main.tsx`'s `hashchange` handler reloads the page when the live hash carries a token, so
    the link arrives as a fresh mount, the path a new tab already takes. A reload rather than an
    in-place exchange, because the GL-master caches (`AccountingReview` `_accCache`,
    `useGlMasters`) are module-level, never invalidated, and would carry the previous BU's chart
    of accounts into the new one.
  - `useCarmenSSO` strips the token first in every case. A link without `bu` now shows "This link
    from Carmen is missing its business unit" instead of keeping its token in the URL. The hook
    starts in the exchanging state, so no page renders as the old session (and no "Access via
    Carmen" flash) before the exchange.
- **Accepted:** a dirty Mapping or Email Settings page shows its "Leave site?" prompt first. If
  the user cancels, they keep their work and the old BU. Wizard drafts survive the reload.
- **Tests:** `useCarmenSSO.test.ts` +3 (`ssoLink`, a link without `bu`, exchanging from the
  first render). Frontend 1030 passed.
- **E2E** (Playwright, local `:8012`/`:3011` + dev DB, real dev Carmen token, BUs `test1` →
  `pms-e2e`). Each case reloaded exactly once and left no token in the URL:
  - another BU's link in the open tab → that BU, exchange 200;
  - the same BU's link again → re-exchanged, BU unchanged;
  - no `bu` → the new error, no exchange;
  - bad token → "Authentication Failed" (401);
  - the old `#/email-settings` link, fresh and in an open tab → `#/CreditCardOCR/email-settings`,
    no extra reload. Its API calls were blocked so no posting token was written to the dev DB.

  - Opening the AI module from Carmen's menu in a tab that is already open now shows the
    business unit you opened it for.
