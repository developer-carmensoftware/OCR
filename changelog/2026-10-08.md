`14:45` **CA-93: the webhook tested end to end, and hardened against what a real sender sends**

- **Why:** to prove the endpoint before Carmen tries it, so a failed call doesn't start a
  back-and-forth. A probe found four variants that would have been refused and one that
  would have been accepted *wrong*: an int `DocDate` such as `20261007` is read by Pydantic
  as unix seconds, which lands on the wrong day silently.
- **Backend (lenient where a sender's defaults differ, strict where a guess could record the wrong day):**
  - **Lenient:**
    - field names in any case (.NET `PostAsJsonAsync` writes camelCase);
    - `"pms"`;
    - a UTF-8 BOM;
    - `bearer`/`BEARER`.
  - **Strict:** `DocDate` must be an ISO date string; an int or an epoch string is answered 422 naming `DocDate`.
  - **Fix:** the 413 message now says 16 KB, not 1 MB.
- **Tests:** `test_pms_webhook.py` has 45 cases:
  - 5 accepted auth forms, and 3 refused ones that write nothing;
  - 10 sender variants, each checking that the stored key, type and payload are identical;
  - 5 Content-Types;
  - exactly 16 KB → 202, and 1 byte over → 413;
  - 12 bad fields → 422 with the field named in `loc`;
  - 4 bodies that are not one JSON object.
- **Real E2E, 25/25 PASS** (local `:8012` + dev DB, BU `pms-e2e`, key created the BU's own way:
  SSO exchange → `POST /pms/keys`). Results:
  - **Day handling:** a new day gives 202 and the row is checked; the same day gives 200 with
    the same id and `updated_at` moves; the same day as a datetime gives 200; another
    DocType gives a new row.
  - **The worst-case sender in one call** (camelCase + `pms` + BOM + `text/plain` + `bearer`)
    → 202 on the right day.
  - **Refusals write no row:** wrong, revoked or missing key → 401; int date, missing date,
    `POS`, `dd/MM/yyyy`, trailing comma → 422.
  - **10 parallel calls for one day** → one 202, nine 200, one row.
  - **The key** has `last_used_at`/`ip` stamped, and `performance_logs` attributes the calls to the BU.
  - **A real .NET client** (PowerShell 5.1 `Invoke-WebRequest`) with the default content
    type, JSON, and `ConvertTo-Json` → 202/200/200.
  - **429 with `Retry-After: 60`** once past 120 per minute.
  - **Cleanup:** both keys revoked, the 5 test rows deleted, tenant kept.
- **Docs:** `PMS_INTEGRATION.md` §3 now lists what we accept and what we refuse. §4 has the real
  422/429 bodies and the pacing note for backfills (≤ 2 per second per source IP). §5 is a new
  **test checklist** for Carmen. Decision-log #41 is amended.
- **Still to do before handing over:** after #284 merges, the same core run on the QA backend
