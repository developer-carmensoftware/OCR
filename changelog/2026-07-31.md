## Uncommitted / in progress

### `14:30` — Credit badge: fix the dead cursor, give it a CTA, add a second door

The quota badge (`UsageIndicator`) is the **only** link to `#/pricing` anywhere in the product —
`grep '#/pricing'` returns one hit outside the pricing flow itself. The only other path is the
`ocr:open-topup` event on HTTP 402, i.e. the user learns plans exist only after being blocked.

And it rendered with an **arrow cursor**. It has always been a real `<a href="#/pricing">`, but
`usage-indicator.css` set `.ui-quota { cursor: default }` and the `cursor: pointer` fix was
written into `pages/pricing.css` — which is imported per-page by `Pricing` / `OrderHistory` /
`CreditOrdersPage` and **never globally**. The badge mounts on Home / CreditCardOCR / APInvoice,
none of which import it. So the pointer only appeared *after* the user had already reached
pricing. The affordance existed exactly where it was no longer needed.

Compounding it: `2026-07-06` removed the wallet `PaymentButton` from those three headers as
redundant with "the clickable REMAIN quota badge — one entry point now". The funnel was narrowed
to one door and the door was left unmarked.

**Frontend**

- `styles/pages/pricing.css`: deleted the stranded `.ui-quota--link { cursor: pointer }`.
- `styles/components/usage-indicator.css`: `cursor: pointer` + `:focus-visible` ring + hover lift
  now live in the globally-imported file, with a comment on why they must stay there. Shape is a
  full capsule (`--radius-pill`), matching the `.home-dark-toggle` pill and `.pricing-history-link`
  it renders beside. Dropped the dead `.col-used` / `.col-total` media queries and the unused
  `.usage-bar-bg` / `.usage-bar-fill` "legacy" block (verified zero references).
- `components/common/UsageIndicator.tsx`: fetch / `ocr:quota-refresh` / `computeUsageStats` shell
  untouched. Gained a CTA half — `Credit 42 │ ◎ Buy ›`. Now uses `useT()`: it was the one
  customer-facing surface with **zero i18n** while `lang` defaults to Thai. `quotaRef` retyped
  `HTMLElement` (it was `HTMLAnchorElement` but the skeleton branch renders a `div`, so it never
  attached while loading).
- **Copy**: `Remain` → `Credit` / `เครดิต`, and the CTA is **"Buy" / "ซื้อ", not "Top up"** —
  `#/pricing` sells subscription plans as well as one-time credit packs, and "top up" names only the
  packs, steering users away from the plans that are the actual product. Noted in a comment in
  `dict.ts` so it doesn't get "simplified" back.
- **Icon does the semantic work**: a lucide `Coins` glyph sits before the verb, so the word carries
  only the action and the badge stays short. Under 480px the word *and* the chevron drop and the
  coin stays — an icon-only CTA still reads as "buy credits", a lone chevron would not.

  `Coins` was chosen for continuity, not decoration: it is already the app's credit glyph in
  `PackList` (the credit-pack cards this badge links to), `CreditsPage`, the admin Credits nav and
  the credits KPI. The badge and its destination now carry the same mark.

  **Icon vocabulary already spoken for** — worth knowing before picking a glyph for anything new:
  `Gem` / `Rocket` are plan tiers in `PlanCard`, `Sparkles` is AI (AISuggestBar, release notes,
  FeatureFlows), and `Zap` / `Gauge` / `Layers` are admin nav items. A shopping cart was considered
  and rejected on different grounds: the flow has no cart (one pending order at a time, one plan per
  order), so the icon would promise an interaction that does not exist.
- `pages/Home.tsx` + `styles/pages/home.css`: `.home-plans-strip` between the module grid and the
  footer — a second entrance. Deliberately **not** a 4th `MODULES` entry; that array is AI product
  modules (ACTIVE/COMING SOON tags, feature chips) and a billing card inside it reads as a
  product. Static copy, no live numbers, so no second `/usage` fetch. This is a new surface, not a
  revert of the 2026-07-06 `PaymentButton` removal.
- `i18n/dict.ts`: `quota.credit` / `quota.getMore` / `quota.aria` + `home.plansDesc` /
  `home.plansCta`, EN + TH. Reused the already-translated-but-orphaned `nav.plansCredits`.

Design was picked by building throwaway variants behind a dev-only switcher and comparing them in
the running app — four rounds, ~17 candidates (affordance-only, adaptive urgency, wallet chip,
denominator, hover-expand, progress ring, card chip, fuel gauge, ticket stub, inverted block, big
number, clip-path wipe, arrow, price tag, split pills, nested pill, two-tone). **All of that
scaffolding is deleted**; `QuotaVariantSwitcher.tsx` no longer exists and the shipped component has
no variant branching. Two findings from it worth keeping written down:

- `position: fixed` inside the header is a trap — `.home-dark-toggle` and `.app-header` both set
  `backdrop-filter`, which makes them the containing block for fixed-position descendants, so a
  fixed element anchors to the header pill rather than the viewport. Portal to `document.body`.
- `clip-path` silhouettes **cut away the `:focus-visible` outline**. Any future clipped shape needs
  a `drop-shadow` focus ring instead, since drop-shadow follows the clipped alpha.

### `14:55` — Credit badge: audit fixes (a11y, skeleton, touch, motion)

Design audit of the above, scored 14/20. Everything below is the remediation; contrast figures are
computed from the OKLCH tokens, not eyeballed.

**Accessibility — five measured WCAG AA failures, all now clear**

| Pair | Before | After |
| --- | --- | --- |
| `CREDIT` label on `--muted`, light | 2.48:1 | **11.36:1** |
| `CREDIT` label, dark | 2.67:1 | **7.99:1** |
| `is-low` value on `--rose-light`, light | 3.89:1 | **5.45:1** |
| CTA hover, white on fill, dark | 3.23:1 | **5.55:1** |
| CTA ink on tint, dark | 4.36:1 | **5.70:1** |

- The label was `0.56rem / 0.1em / --text-4` — both off DESIGN.md's `label` style and unreadable.
  Now `0.68rem / 0.08em / --text-2`, which clears AA in **both** themes with no dark override.
  Value moved to `0.83rem` to match the `data` style and keep hierarchy.
- The low-credit state was the *least* readable thing in the badge. `--rose-hover` is the darker
  step of the same ramp.
- Dark CTA rest ink is a scoped custom property (`--quota-cta-ink`): dark `--primary` reads only
  4.36:1 against the CTA tint, so the badge pins its own value and says why inline.
- **CTA hover now matches `.lang-toggle:hover` / `.theme-toggle:hover` exactly** — `--muted`
  background, `--text` ink, `150ms var(--ease-out-premium)`. It had been inverting to a saturated
  fill over 200ms, which made the one button in the header cluster that isn't a settings toggle
  behave unlike the two it sits between. Both tokens are theme-aware, so a single declaration
  covers light and dark and there is no bespoke hover colour left to drift.
- `prefers-reduced-motion` now gates the framer-motion entrance too (`useReducedMotion`), not just
  the CSS transitions. PRODUCT.md commits to this on all new animation.
- `aria-label` em dashes → commas; added `quota.ariaNoCount` for the degraded state.

**Loading state — no separate skeleton at all now**

It was causing a ~100px layout shift: the skeleton rendered one column while the loaded badge
rendered two, so the header jumped when `/usage` landed and shoved `LanguageToggle` and
`DarkModeToggle` sideways. Introduced when the CTA half was added and the skeleton wasn't updated
with it.

The first fix matched the skeleton's shape to the loaded shape, which still looked wrong in
practice. Root cause: there was no reason for a separate loading render at all. **The destination
is known before the fetch is, and the CTA half is static** — only the count is ever unknown. So the
badge now renders whole, live and clickable from first paint, with a placeholder in the count slot.
That collapses three render branches into one, removes the loading → loaded structural swap
entirely, drops `pointer-events: none`, and lets someone click Buy while the number is still in
flight. `aria-busy` carries the loading state instead of `aria-hidden` hiding the whole badge from
assistive tech.

Two cascade/measurement bugs fixed with it, both invisible in review:

- `.sk-block` is tuned to sit on `--card-bg`. On this badge's `--muted` it nearly disappears in
  dark mode — `--gray-100` is `0.24` against a `0.25` background. The placeholder now shifts one
  step up the ramp (`--gray-200` → `--gray-300`), which reads in both themes from one declaration.
- That override needs specificity **(0,3,0)**: `usage-indicator.css` is imported *before*
  `page-skeleton.css`, so a bare `.ui-quota-value-sk` loses the cascade to `.sk-block` and to
  `[data-theme='dark'] .sk-block` at equal specificity. Chaining `.sk-block` onto the selector
  beats both.
- The placeholder's `ch` width resolved against the inherited 1rem, not the value's `0.83rem`, so
  it was ~25px where the real number is ~21px. Setting `font-size` on the placeholder makes `ch`
  match, and `0.62rem` bar + `0.105rem` margins occupy exactly the value's `13.28px` line box.

`.ui-quota-value` also gained `min-width: 2.6ch` so the residual shift from 1- to 4-digit counts is
~11px rather than ~107px.

**Error and auth states**

- `/usage` failing used to leave `stats` null → `return null` → **the badge vanished**. On the
  wizard pages that is the only route into pricing, so a transient API error deleted the funnel.
  The badge now renders with a degraded count and a working link.
- `if (!isAuthenticated) return` skipped `setLoading(false)`, so under `VITE_DEV_AUTH_BYPASS` the
  badge sat in its loading state forever. Now returns `null` cleanly.

**Touch and shape**

- `@media (pointer: coarse)` gives the badge `min-height: 44px`. DESIGN.md mandates 44px and notes
  the tool is used on tablets; it was ~34px.

**Used-% progress bar deleted**

The audit flagged it as clipped by the capsule radius and it was inset to fix that. Inspecting the
running badge showed the real problem: `a.ui-quota::after` measured **1.34 × 2 px**. `scaleX` is
driven by the used fraction, so on any real plan (1,500 docs against a handful consumed) the bar
collapses to a sliver. It only grows legible as the pool empties — by which point `is-low` has
already turned the whole badge rose. It was illegible precisely when it had something to say, and
redundant once it didn't.

Removing it made a whole chain dead, all now gone:

- `.ui-quota::after`, its inset, and its entry in the reduced-motion block.
- `quotaRef` and the effect that wrote `--used-pct-factor` / `--quota-color`. The ref existed only
  to feed the bar, so the component no longer touches the DOM imperatively at all.
- `usedPercentage` and `color` on `UsageStats` — the bar was their only consumer — and with them
  `totalUsed` / `totalCapacity`, whose `ponytail:` note conceded the figure was approximate because
  credit-consumed counts aren't in `/usage`. That inaccuracy left with its last reader.
- `computeUsageStats` is down to folding the three pools and `isLow`, which is exact.

`UsageIndicator.tsx` 145 → 116 lines, `lib/usage.ts` 37 → 29. The `color` assertion in
`UsageIndicator.test.ts` went with it; a boundary case at `isLow` + 1 replaced it (349 tests).

**Worth knowing:** the badge now has no gradual signal at all — nothing changes until `remaining
<= 5`, which for a bank-transfer purchase needing admin approval is late. Nothing was actually lost
here (a 1.34px bar signalled nothing), but if an early warning is wanted it needs to be built
deliberately, not recovered from this.

**Also removed**: dead `AnimatePresence` (no `key`, no `exit`, so it did nothing) and the
`!important` specificity workaround on the old placeholder class.

Verified: `tsc --noEmit` clean, `eslint` clean (5 pre-existing warnings in `useAPInvoice.ts`),
`vitest` 348/348, and all ten badge colour pairs re-measured at ≥4.95:1.

**Pre-existing flake, not from this work** — `useFileUpload.test.ts` ("previewType=pdf") and
`useAPExtraction.test.ts` ("triggers runOCR automatically") fail intermittently, roughly 1 run in 4.
Reproduced on a stashed (pre-change) tree, and both pass 3/3 when run in isolation. These two files
are the only ones that do `vi.stubGlobal('URL', { createObjectURL, revokeObjectURL })`, which
replaces the **entire** `URL` global — dropping the `URL` constructor for anything else touching it
in that environment. That is the lead worth pulling; stubbing the two methods on the real `URL`
instead of replacing it is the likely fix. Left alone here to keep this change scoped.

## `11:20` — Proforma invoice: WHT 3% deduction line

Raised by accounting. Carmen sells **services** to **Thai juristic persons** (every tenant is
a hotel company on Carmen ERP), so the buyer is legally required to withhold 3% at source under
ท.ป.4/2528 and remit it themselves. The proforma printed `Grand Total ฿1,059.30` as the amount
to transfer, but a compliant corporate buyer transfers **฿1,029.60** — the document stated a
figure nobody could legally pay, and the 3% gap landed on the admin reviewing the slip with no
basis to approve it.

Three things the fix had to get right:

- WHT is a **deduction the buyer makes**, not a charge we add — `Subtotal`, `VAT`, `Grand Total`
  and `credit_orders.amount_thb` are all unchanged. `amount_thb` is the invoiced debt, which was
  already correct.
- The base is the **ex-VAT subtotal**: `990 × 3% = 29.70`, not `1,059.30 × 3% = 31.78`.
- A slip short by exactly the WHT is a **full payment** — the 3% goes to the Revenue Department
  in Carmen's name.

Display-only: no migration, no new column, no backend change. WHT is a pure function of
`billing_documents.subtotal`, so it is derived at render time.

**Frontend**

- `lib/money.ts`: new `WHT_RATE_PCT = 3` + `whtDeduction(subtotal, ratePct)`. `ponytail:` note
  on why the rate is a constant rather than a `system_configs` key (set by law, moves ~once a
  decade) and the promotion path to `billing.wht_rate` if it ever must vary per document.
- `components/pricing/ProformaDocument.tsx`: two rows below `.pf-amount-words` —
  `WHT (3%) Amount (29.70)` and `Payment Amount 1,029.60`. Accounting parentheses on the
  deduction, no `฿` prefix on the payment amount, always rendered on a proforma. Amount-in-words
  stays bound to `doc.total` — it states the invoice amount. Terms gained a 5th item asking for
  the Withholding Tax Certificate (or e-Withholding Tax via bank); without it the withheld 3%
  can't be credited against corporate income tax and is simply lost. Body text stays hardcoded
  English — the printed proforma is a fixed English-only format, never translated.
- `styles/pages/pricing.css`: one `.pf-subrow` modifier (regular weight) next to
  `.pf-amount-words`. No print rule needed — the rows inherit `.pf-totals`' 8.5pt.
- `components/admin/OrderWorkspace.tsx` + `i18n/dict.ts`: "Amount due" hint extended from
  `net {sub} + VAT {vat}` to `… · with 3% WHT deducted: {netWht}` (EN + TH), so a 3%-short slip
  reads as expected instead of suspicious.
- `lib/money.test.ts`: 3 new cases — 3% of net not gross (990 → 29.70, 2490 → 74.70, annual
  26892 → 806.76), satang rounding (925.23 → 27.76), and the printed payment amount
  (`1,029.60`).

**Docs** — `docs/Billing_Purchase_Flow.md` gained a WHT paragraph in the Pricing section.

**Not in scope, flagged for finance:** Carmen AR will now carry a 3% open residual per invoice
that must be cleared against WHT receivable when the certificate arrives. The Carmen AR posting
(`credit_order_service.py:506-510`) still sends `total/net/vat` only. If that reconciliation
turns out to be painful, sending the WHT split to Carmen AR is the follow-up.
