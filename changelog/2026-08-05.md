## Email Automation — ที่อยู่เดียว route ด้วย tax_id (breaking)

### Backend

- `14:40` **`ocr+<tag>@…` ต่อ BU → ที่อยู่เดียวรวมทุก BU** tag ใช้ได้แค่กับ auto-forward
  เพราะ manual forward มาจาก client ของพนักงานที่เขียนทับ recipient ทิ้ง — ครึ่งหนึ่งของ
  arrival mode ที่รองรับไม่เคยมี tag ให้อ่านตั้งแต่แรก · ตอนนี้ route ด้วย **เลขผู้เสียภาษี
  บนตัวเอกสาร** ซึ่ง unique ต่อ BU ทั้งระบบอยู่แล้ว (`409 Tax ID already registered`)
  และเป็นของที่ลูกค้าต้องใส่ก่อนเปิดใช้อยู่แล้ว
- **ลำดับใน pipeline สลับทั้งหมด** — `dedupe(global) → เปิดไฟล์(รหัสผ่านทุก BU) → extract
  → tax_id → tenant → entitled → คิดเงิน → task → map → post` · `_process_attachment`
  หา tenant เอง แล้วส่งต่อให้ `_post_extracted` ทำครึ่งหลังหลังจากรู้เจ้าของแล้ว
- `_already_seen()` ใหม่ ต้องมาก่อน extract ไม่งั้นเมลที่ส่งซ้ำเสียค่า LLM ก่อนโดน `_claim`
  ปฏิเสธ · `_claim()` เดิมยังอยู่เป็นตัวกัน race แบบ atomic หลังรู้ tenant
- `es.resolve_by_tax_ids()` + `es.ingest_pool()` ใหม่ · ลบ `extract_tag()`,
  `es.get_by_tag()`, `es.\_new_tag()`, `_RECIPIENT_HEADERS`, และ `_Skip("tax_id_mismatch")`
  (การ match คือ routing เอง เอกสารบริษัทอื่นไม่มีวันถูก route มาที่ BU นี้)
- `match_rule()` ยังอยู่ แต่ match กับ rule ของ **ทุก BU** รวมกัน — rule บอก *ธนาคาร*
  ไม่เคยบอก BU ("no-reply@ktc.co.th ส่งใบ KTC" จริงไม่ว่าเอกสารเป็นของใคร) ทำให้ยังได้
  prompt เฉพาะธนาคารสำหรับเอกสารที่ยังไม่รู้เจ้าของ
- summary key ใหม่ `unrouted` — เมลที่ไม่มี BU ไหนรับ เราจ่ายค่า extract ทิ้ง ลูกค้าไม่เสีย
