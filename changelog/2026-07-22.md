## Uncommitted / in progress

### `10:50` Department-scoped account codes (Carmen `DefaultAccount`)

Carmen departments can restrict which account codes may be posted under them
(`DefaultAccount` — a *stringified* JSON array; `"[]"` = all accounts allowed).
The app previously discarded this field everywhere, so users (and the AI
suggester) could map items to accounts the department forbids.

- **Frontend**: new `lib/deptAccounts.ts` (parse + filter helpers, vitest'd);
  `DefaultAccount` preserved at both dept-reshape sites (`useMappingData`,
  `useAPSubmission`); all 4 account dropdowns (credit-card main fields,
  payment-type modal ×2, AP line items) hard-filter to the chosen dept's
  allowed list; changing dept auto-clears a now-forbidden account
  (`useMapping`, `useAPInvoice`); `/suggest` payloads now carry
  `allowed_accounts` per department.
- **Backend**: `CodeOption.allowed_accounts` on mapping schemas;
  `gl_suggestion_service` validates (dept, acc) legality incl. GEN-default and
  fallback paths; `ap_invoice_service.suggest_for_items` parses
  `DefaultAccount` server-side and blanks illegal suggested accounts (history
  bypass included). New `tests/unit/test_dept_allowed.py`.
- `11:05` **Audit follow-up** (closed all findings from the post-change audit):
  - **P1** — credit-card mapping router history-bypass now checks `DefaultAccount`
    legality (`_pair_ok`) before bypassing/hinting (`routers/mapping.py`, both
    endpoints); illegal historical pairs fall through to the already-enforced AI
    path. +2 router tests in `test_dept_allowed.py`. Also closes the
    `CustomSearchSelect` topChoice bypass (suggestions are now clean at source).
  - **P2** — account selects flag red (`hasError`) when a previously-saved
    dept+acc pair is no longer legal (MainMappingTable, PaymentTypeModal ×2,
    AccountMappingTable).
  - **P3** — `CustomSearchSelect` gained a `notice` prop; account dropdowns pin
    "N accounts allowed for {dept}" when the list is dept-restricted.
- `11:20` **Mixed-pair suggest bug** (found in manual test): user picks dept `103`,
  leaves acc empty, hits AI Suggest → suggested acc (validated against the AI's *own*
  dept) got applied under the user's dept, landing illegal + red. Fixed with
  `mergeSuggestion()` in `lib/deptAccounts.ts` — keeps user values, drops a suggested
  acc the effective dept forbids — applied at all 5 merge sites: AP `runSuggest`
  (`useAPSubmission`), CC `applyMainSuggestion` + `confirmPaymentSuggestion`
  (`useMappingSuggestions`), CC `handleAcceptAll` ×2 (`useMapping`). +4 vitest.
- `11:28` **Illegal pairs could still proceed/post** (manual-test find #2): red-flagged
  dept+acc pairs didn't block progression. Now gated at all three exits:
  AP `allMapped` (disables Generate AP Invoice, `useAPSubmission`), CC `saveAllSettings`
  (error modal listing offending pairs), CC PaymentTypeModal OK (`saveAmountSelection`
  wrapper — it writes localStorage the wizard reads, so it needs its own gate).
- `11:55` **Payment-modal illegal-pair UX** (manual-test find #3): the OK gate's error
  modal named a row hidden inside the collapsed "additional mappings", confusing users
  ("รายการนี้ไม่มี แต่ทำไมขึ้น"). Replaced with an in-modal flow: OK now shows an inline
  red banner listing offending types, auto-expands additional mappings, and scrolls to

  types visible in the UI so a stale hidden entry can't dead-end the Save.
- `12:05` **Dark-mode hover white-on-white**: dark token block never overrode
  `--secondary`, so hover surfaces using it (`pm-additional-toggle`, pricing) kept the
  light theme's near-white bg under light text. Added the dark `--secondary` override

## Backend

### `18:30` Render OOM incident (2026-07-22 morning) — root fix + caps

Chain: AP extract had no guard for the vision LLM wrapping its JSON in `[{...}]`
→ `'list' object has no attribute 'get'` → varana hotel retried the same PDF 4×
→ repeated whole-file-in-memory processing pushed RAM past the instance limit →
Render restart.

- fix(llm): new shared `parse_vision_json()` in `llm/client.py` — single parse
  path for every vision module (fence-strip → parse → unwrap one-element array →
  non-object raises `LLMParseError` instead of a 500 `AttributeError`). Replaces
  the duplicated parse blocks in `llm_service.py` (credit card) and
  `ap_invoice_service.py` (AP — the one missing the guard). New
  `tests/unit/test_parse_vision_json.py`.
- perf(memory): caps lowered — `MAX_FILE_SIZE_MB` 20 → 5 (`config.py`, `.env`,
  `.env.example`, `render.yaml`), `MAX_PAGES_PER_CALL` 10 → 5 (`pdf_utils.py`;
  `pages.py`/AP service/tests follow the constant). Worst-case per-request memory
  ~4× smaller. Rollback = env edit on Render, no code deploy.
- Memory itself: monitor only — no instance change. If the alert recurs with the
  retry loop gone, upgrade instance RAM.
