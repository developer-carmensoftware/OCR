# 2026-09-21

## `12:10` — Backend: ticket 08 — deterministic KBANK settlement parser (drop the LLM call)

Implemented `.scratch/kbank-settlement-jv/issues/08-deterministic-settlement-parser.md`, the
last of the 8 tickets from the 2026-09-18 KBANK settlement redesign. Deliberately sequenced
last per its own blocking note: the JV shape (ticket 03) and the extraction engine could not
change in the same pass without losing the ability to tell which half caused a wrong figure.

- `services/kbank_settlement_text.py` (new) — `parse(pdf_bytes) -> ExtractedCreditCardData |
  None`. Reads every word on the page via PyMuPDF `get_text("words")`, buckets them into
  printed rows by y-position (±2pt) rather than trusting PyMuPDF's own block/line order —
  which on this report puts the column-header row after its data rows in content-stream
  order, and splits the NET AMT figure on the `TOTAL BY MERCHANT ID` line into its own
  content block, landing after a page-width separator but on the same printed row. Produces
  the exact shape `llm/prompts/kbank_settlement.py` asks the vision model for, including the
  unfiltered anchor row appended to `details[]`, so `credit_card_service
  ._normalize_ar_settlement` needs no change to accept either source. Verified against the
  real sample file (not committed — see privacy note below): reproduces every field the
  vision path currently extracts, and the result survives the real normalizer with zero
  warnings — three-way self-consistent, same as the LLM reading. Requires `REPORT NO.
  KB1P554V2`; returns `None` (never guesses, never raises) on a version mismatch, a missing
  NET AMT or tax invoice number, an encrypted PDF, or anything else unexpected.
- `services/ocr_service.py` — `extract_stateless` tries the deterministic reader (in a
  thread executor, matching the file's existing PyMuPDF calls) immediately before the vision
  call, scoped to `doc_type == AR_RECONCILE and bank_code == "KBANK"` only. `None` falls
  straight through to the unchanged vision path. Charging is unaffected — `consume_document`
  already ran per file, before this point, regardless of which path reads it.
- **Privacy**: the committed test fixture is built in memory (PyMuPDF `insert_text` at
  chosen coordinates) rather than the customer's real PDF — no binary asset added to the
  repo. It deliberately reproduces both structural quirks above (header-after-data
  insertion order; NET AMT as a separate call sharing the total row's y) and carries the
  real worked example's own money figures (needed to prove fidelity against the actual
  sample), with merchant name/ID/account number/tax invoice number all scrubbed.
- Tests: `test_kbank_settlement_text.py` (new, 9 tests) — the full layout with scrubbed
  identity; survives `_normalize_ar_settlement` unchanged; a future report version, a
  missing NET AMT, a missing total row, a missing tax invoice number, an encrypted PDF, and
  malformed bytes all return `None`; a per-terminal `MERCHANT ID` row is never mistaken for
  the `SUMMARY MERCHANT ID` one. `test_ocr_service.py` (new, 3 tests) — the hook itself: a
  readable settlement skips the vision call entirely, a shape mismatch falls through to
  vision unchanged, and the parser is never even attempted outside
  `doc_type == AR_RECONCILE and bank_code == "KBANK"`. Full backend suite: 1395 passed, 79
  skipped (pre-existing, unrelated), 0 failed.
