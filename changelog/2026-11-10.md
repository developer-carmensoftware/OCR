## JV queue filters: five defects found by a second verification pass (branch `fix/credit-card-activity-param-edges`)

`17:10` PR #359 (the filter bar) is merged. A second pass went after what its 58 browser cases could
not see; it found five real defects, all fixed here, each with the case that found it.
- **Backend:**
  - `q` or `bank` containing a **NUL** reached Postgres, which refuses it in a text parameter → **500**.
    Now a 422 at the route (`pattern=^[^\x00]*$`), before any query runs. (`source` / `range` / `filter`
    never reach a query with that text, so they stay "an unknown word, ignored".)
  - `offset` had no ceiling: `offset=9223372036854775808` overflowed `limit + offset` → **500**. Now
    `le=1_000_000` (422 above it). The route docstring's "the All chip's dropdown" is corrected.
- **Frontend (`QueueFilters.tsx`, `emailReview.ts`, `ReviewQueue.tsx`, CSS):**
  - A NUL, tab or newline **pasted into the search box, or carried in a link** (`?q=%00`), became a 422 and
    the "Could not load the queue" card. `cleanText()` strips control characters and caps the length
    where text enters (the box and the address).
  - The search committed **half an IME composition** after the 300 ms debounce (Thai / CJK): nothing is
    searched until `compositionend`.
  - **Tab did not close the menu**: only an outside click and Esc did, so a keyboard user could Tab
    away and leave an orphan menu open. Tab / Shift+Tab now close it and hand focus back to the opener so
    the browser's own Tab lands on the next / previous control (the ARIA menu pattern).
  - At **320 px with 200 % text** the page scrolled sideways: the Upload button's `nowrap` (added for a
    dropdown that no longer exists) and the in-flow menu's `min-width: 13rem` (416 px at 200 %).
- **Tests:** 13 pytest (NUL ×4, offset ceiling ×7 incl. 2⁶³ and 10³⁰, odd Unicode ×6 answered not crashed,
  and the BU day at the edges the browser suite cannot reach: 16:59:59Z vs 17:00:00Z, a year end, a leap
  day — no defect there); 6 vitest (`cleanText`, a pasted NUL, a linked NUL, the IME wait, Tab and
  Shift+Tab); 9 new browser cases X-01 … X-12 in `jv_filters_ui.mjs` (67 now) and two in the new
  `jv_filters_load.mjs`.
- **What else the pass checked and found sound:**
  - **The production bundle with the enforced CSP** (`vite build --mode e2e` + `vite preview` serving
    `vercel.json`'s headers): 47 cases, **0 violations**. The listener was shown to work first (a provoked
    inline script and a foreign image are both reported; the inline script does not run).
  - **Installed stable Chrome** instead of the bundled Chromium: 50 / 50.
  - **Races**: a 14-change burst against responses held 0–700 ms at random, an open menu through a window
    refetch, twelve Pricing ↔ Queue round trips (no listener grows, one change = one request), and the
    list answering 400 / 429 / 500 / dropped / unreadable / empty at first load and mid-session (error card
    + Retry, filters kept, recovery).
  - **Mutations** (reverted): the hashchange cleanup removed → X-05 (`hashchange` listeners 4 → 16); a
    failed fetch painting an empty list → X-07; the window focus closing the menu → X-04.
  - **The real rate limiter** (a backend with the shipped 120 / 60 s limits): a filter change every 2 s
    for a minute is never limited; a 140-request burst gets 33 × 429 with the reason; the page shows the
    error card with Retry and Retry works once the window has passed.
- **Scale, measured** (`setup --big`, local DB, 18,435 visible rows of 20,000; 20 runs each, `/activity`
  with `limit=100`): whole log p50 85 ms / p95 134; Review 49 / 99; source + bank + 30 d 48 / 64; a search
  matching thousands 119 / 155; a search matching nothing 117 / 131; first rows on screen in 970 ms.
  **One cliff: a deep page (`offset=19900`) is p50 1,124 ms / p95 1,865 ms — 14× the first page.**
  `EXPLAIN ANALYZE` puts the SQL at 0.1–0.4 ms for the list and 1.7–23 ms for the counts (a Seq Scan, fine
  at 14k rows), so the time is `list_activity` hydrating `limit + offset` rows per source and slicing in
  Python — the `ponytail:` comment's "if a BU ever pages deep enough" has arrived. **Not changed here.** The
  fix is two-phase: select `(id, when)` for the window, merge and slice, then load only the page's rows
  (touches `list_activity`, covered by the 5,600-combination matrix). Within the 2 s budget set for the
  case; worth doing before a BU reaches ~50k rows.
- **Tooling trap, worth knowing:** a shell whose working directory has a **lowercase drive letter**
  (`c:\Users\…`, which VS Code and some Claude Code sessions hand out) makes `vitest` load two copies of
  `@vitest/runner` (`file:///c:/…` vs `file:///C:/…`): every file fails with `Cannot read properties of
  undefined (reading 'config')` at `describe`. Start from `C:\…` and it is fine; CI is unaffected.
