# 2026-11-10

## PMS: the day's rows come from Carmen's preview (decision-log #54, branch `feat/pms-preview-reader`)

`11:29` Carmen's new preview of a post (`interfacePreviewPostGL`, ask P) now gives the day's rows.
It replaces #53's reader.

**Backend**
- `carmen.preview_pms_gl`: the post's own body.
  - **Answer:** a DataTable with one row per line of the day, keyed as Carmen's engine reads it,
    plus each key's account.
  - **Side effects:** none. It makes no JV and does not write the table.
- `process._process` previews the very Data Bank row a post would read (the newest `Id`, or the
  date alone).
  - `-400 No Data` waits hourly, as the post's does.
  - 401 or 403 is the credential's reason.
  - Any other failure parks the day with no rows, and the `-500` fallback stays.
- `carmen_config`: `rows_key`, `field_for`, `rows_of`, `newest_day` and `other_doc_types` are
  deleted. The app no longer reads a day's `FileData`. New `preview_rows`.
- `mapping.suggest` shows the AI each key under the BU's column names, with no amounts. It no
  longer assumes Comanche's `code · description` and ` - VAT`/` - SERVICE` rows.
- `amount` leaves the review API (`PmsRow`, `PmsNewCode`). The screen never showed it.
- Tests: `test_pms_carmen_config` and `test_pms_process` now run on preview answers, and the new
  `test_pms_mapping` covers the prompt.

**Scripts**
- New `scripts/qa/pms_probe.py <PMS> <day>`: checks a PMS for a BU before it goes live, and posts
  nothing.
  - **With the menu token:** the interface row, the key columns, the Data Bank day, and the
    preview with its new keys.
  - **With a web JWT as well:** whether Revenue's balance account is in the chart (ask N).
- `pms_third_parties_e2e.py` reads Comanche's raw days itself (its staging needs
  `TransactionType`).
