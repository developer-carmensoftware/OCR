## Backend — two credit bugs found by the FRD audit (#327)

`14:57` Found while checking the FRDs against the code; both are fixed test-first.

- **Credit Card OCR under-refund.** `routers/credit_card/ocr.py` charges one credit per file. When
  the task rows could not be written, though, it refunded 1 (`refund_document`'s default) instead
  of n. A 3-file batch that hit a DB error lost 2 credits. It now refunds `len(file_data)`.
- **Admin top-up could credit an order twice.** `topup_order()` refused only `PAID`, so a
  `COMPLETE` (already posted to Carmen AR) or `VOID` order passed to `POST /api/v1/admin/tenants/{id}/credits/topup` was
  flipped back to `PAID` and credited again. Only `in_progress` / `on_hold` orders are accepted
  now; anything else raises 409.
- The ORM's `uq_credit_orders_one_open_per_tenant` now includes `on_hold`, matching the real index
  (migration `20260701071021`). The model is the only change, no migration. `feedback.py`'s
  docstring now names the real correction key (with `bank_code`).
- Tests: `test_extract_refunds_every_file_when_task_rows_fail`, plus `TestTopupOrder` (5 cases).
  Both failed before the fix. Results: backend unit 1546/1546; credit, feedback and activity
  integration 100/100; ruff clean.

## Docs — ISO/IEC 29110: a short RS per timeline item + one Traceability Record (#328)

`15:32` ISO 29110-5-1-2 asks a Requirements Specification for requirements that are uniquely
identified, verifiable and traceable to design and tests. It does not ask for length. The 10 FRDs
(356 pages) are more detailed than that, yet they lacked what the standard checks: feature IDs
restarted at F-01 in every doc, and no test case cited one. Agreed with the user: a short RS per
timeline item, and the FRDs filed as Software Design.

- **`docs/iso/RS-01…RS-08`:** 5–9 pages each, written only from the corrected FRDs.
  - 198 requirements with globally unique IDs: `BANK-`, `AP-`, `ITX-`, `PG-`, `SUB-`, `EML-`,
    `PMS-`, `ATR-`, followed by F / U / I / Q / C plus a number;
  - each one says how it is verified (test / review / demo), with acceptance criteria;
  - version 0.1, Draft.
- **`docs/iso/TR-traceability.md`:** maps each requirement to its FRD section, code, automated
  tests and FRD test cases.
  - 179 requirements have an automated test, 150 have a QA case, 14 are verified by review only;
  - the gap: `fn_scrub_old_filenames` has no automated test.
  - A one-off check confirmed every RS ID is in the TR exactly once and every cited TC exists in
    its FRD. `--check` confirmed every cited file exists.
- **`build_frd.cjs` changes:**
  - `iso-wp:` (RS / SD / TR) sets the code, the name, the header and the file name;
  - FRDs carry `iso-wp: SD`;
  - `related()` reads `docs/frd` and `docs/iso`;
  - `<!-- widths!: … -->` takes exact column percentages, so ID columns no longer squeeze;
  - non-ISO output is still byte-identical to `main`.
- **Builds:**
  - `Desktop\OCR-ISO29110-Docs` holds 8 RS + 10 SD + 1 TR, with 0 layout issues;
  - the corrected Carmen-format FRDs are in `Desktop\OCR-ISO-Docs`, the old ones moved to
