## LLM Usage Cost: Direct OpenRouter Cost Capture & Deprecate Pricing Sync (branch `feat/llm-openrouter-direct-cost`)

OpenRouter returns exact `usage.cost` directly in its response. Capturing this eliminates the need for periodic `pricing-sync` background catalog scraping and provides exact pricing (including provider caching discounts).

- `18:00` **Backend (`backend/app/llm/client.py`, `llm_usage_logger.py`):**
  - Updated vision and text LLM callers to extract `response.usage.cost` (or from `model_extra` / dict) and pass directly to `log_llm_usage(..., cost_usd=cost_val)`.
  - Updated `log_llm_usage()`: when `cost_usd` is provided, records it verbatim into `llm_usage_logs.cost_usd` without calling `get_pricing()` or calculating from DB. Falls back to catalog lookup if omitted.
- `18:02` **Migration (`supabase/migrations/20261123000000_unschedule_pricing_sync.sql`):**
  - Unscheduled `pricing-sync` from `pg_cron` (`cron.unschedule('pricing-sync')`).
- `18:03` **Tests:**
  - Added unit test `test_log_llm_usage_direct_cost_usd` verifying `cost_usd` is saved verbatim and bypasses `get_pricing`.
  - All 43 usage/client tests and 277 regression tests passed with 0 failures.
- `19:00` **Review fixes:** cost extraction moved to one `_usage_cost()` helper in `llm/client.py` (finite, non-negative numbers only). `log_llm_usage()` now falls back to the catalog, with a warning, when the provider cost is malformed, negative, or 0 with tokens used, instead of dropping the whole usage row. Tests added.
- `19:30` **DB (`supabase/migrations/20261124000000_llm_cost_usd_precision.sql`):** `llm_usage_logs.cost_usd` widened from `numeric(10,6)` to `numeric(12,8)`. A typical small call costs about $0.0000027, which the old column stored as $0.000003 (~10% off), so the exact provider cost was not exact in the database. Existing rows keep their rounded values. Checked on a throwaway partitioned Postgres: parent, existing and newly created partitions all report `numeric(12,8)`. ORM column updated to match.
