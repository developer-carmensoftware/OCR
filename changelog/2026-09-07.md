# 2026-09-07

## One voice in the review queue's Detail column, one name for the feature

`10:20` A wording pass over every string the queue can print, read end to end for the first
time. The column is fed from four places nobody had compared: `reasonFor`'s flag ladder, the
`review.rc*` dictionary, `error_message` written by `email_ingest_service.py`, and
`cc_input_tax.py`'s skip reasons. Three of the findings are defects rather than taste.

1. **The dialog said it twice.** `stopText` was written so a detail *replaces* the phrase —
   its own docstring names the vacuous head as the thing it removed. `ReviewDocument.tsx`
   kept a second copy that appended unconditionally, and since §13 made `duplicate_document`
   and `carmen_rejected` park at `pending_review`, the two met on screen daily:
   *"already handled · already posted to Carmen"*, and *"Carmen refused it · Carmen: Period
   2026-08 is closed"* — `_carmen_verdict`'s "say it once" broken by its caller.
2. **Two prefixes for one outcome.** `_post_input_tax` wrote `"JV posted; input tax not
   recorded: …"` and `build_input_tax_payload` wrote `"input tax skipped: …"`, both into the
   same cell — which is already prefixed by `Posted automatically ·`, so the old head
   restated the row it hung off. The Carmen branch nested a second colon:
   *"JV posted; input tax not recorded: Carmen: …"*.
3. **"Forwarding" named the wrong system.** Settings Step 3 uses that word for the rule the
   customer sets up in **their own** mailbox, so *"Forwarding is switched off right now"*
   sent them to Outlook to look for our switch.

Full reasoning and decisions 89–95: [`docs/email-automation/07-human-in-the-loop.md` §19](../docs/email-automation/07-human-in-the-loop.md).

### Frontend

- `lib/reviewReasons.ts` — `stopText` moves here from `QueueRow` and becomes the only thing
  that decides what a stopped row says. Structural param type, so both `ReviewDocument` and
  `ReviewDocumentDetail` satisfy it. `full` is the single flag the two surfaces differ on:
  the dialog appends the detail a cell keeps on its tooltip, and never repeats a detail the
  phrase was already replaced by.
- `components/credit-card/QueueRow.tsx` — the pending-with-a-reason branch calls `stopText`
  instead of printing the phrase alone, so Carmen's verdict now appears on the row that can
  still act on it rather than only on the dead one. The `received` branch gains a title
  saying nothing will retry it (`_claim` returns `None` on the dedupe hit, so it never is).
- `pages/ReviewDocument.tsx` — the reason banner calls the same helper. Removes the
  duplication above.
- `i18n/dict.ts` (EN + TH) — sentence case on every phrase the column can print. Three
  reasons re-nouned to match the settings field their Fix button opens:
  *Sender is not one of your email addresses* (**Your email addresses**), *No filename
  pattern matched* (**Filename patterns**), *The Carmen posting credential is no longer
  accepted* (**Posting credential** — also drops "expired", which a revoked token is not).
  Column header `Message` → **`Detail`**. New `review.rcStuckHint`.
  `notif.reason.carmenRejected` *declined* → *refused*, so the bell and the queue use one
  verb for one event; the two blocks now carry a comment naming each other.
- `pages/EmailSettings.tsx` — heading `Email Automation` → **`AI JV Automation`**, the name
  every message that sends a reader here now uses.
- `pages/ReviewQueue.test.tsx` — assertions updated; one case added, that a pending
  `carmen_rejected` row prints Carmen's verdict rather than the phrase.
  `components/common/NotificationBell.test.tsx` — the verb.

### Backend

- `services/email_ingest_service.py` — `Already posted to Carmen` / `A copy is already
  waiting for review` capitalised (they *are* the cell, not a tail on one). The input-tax
  note drops its `JV posted;` head and uses one prefix, `Input tax not recorded`, with an em
  dash before `_carmen_verdict` so the colon does not nest. `ingest_paused` names AI JV
  Automation.
- `services/cc_input_tax.py` — the four skip reasons take the same `Input tax not recorded`
  prefix, so both halves of the note read as one outcome.
- `services/email_settings_service.py` — the two enable-blocker messages name AI JV
  Automation, matching the heading they render under.

## `13:33` — Detail column: one meaning for rose, no row for a rule doing its job

Two things the wording pass above read past, both reported off the screen. Design:
[`07-human-in-the-loop.md` §20](../docs/email-automation/07-human-in-the-loop.md), decisions
#96–#97.

### Frontend

- `components/credit-card/QueueRow.tsx` — `reasonFor` drops tone `bad`. `Mapping missing` and
  `Amounts do not reconcile` were rendering in the same rose as `Carmen: Period closed` two
  rows below, on a row whose own pill says *Review* in amber. Rose in that column means one
  thing, **did not post**; a parked document is the one row nobody has given up on. Every
  non-clean pending reason is amber now, `Ready to post` stays green, and `.rq-reason--bad`
  belongs to the resolved-failure branch alone. The flag ladder still decides which phrase
  prints. No CSS change.
- `lib/reviewReasons.ts` + `i18n/dict.ts` (EN + TH) — `no_rule_match` removed from
  `REASON_KEY` and `FIX`, and both `review.rcNoRuleMatch` strings deleted. Unreachable after
  the backend change below; retires the *Filename patterns* third of decision #93.
  `admin.email.reason.no_rule_match` stays — different page, still live.
- `pages/ReviewQueue.test.tsx` — `no_rule_match` off the *Open settings* `it.each`;
  `mapping_missing` added to the phrase cases; one case pinning the colour, which nothing did.

### Backend

- `routers/credit_card_activity.py` — new `_visible()`, on **both** `_email_stmt` and
  `_counts_stmt`, so `no_rule_match` is in no view of the customer's app: not listed under
  `All` or `Today`, and out of `counts` and `total` rather than sitting in a bucket with no
  chip. Reverses §14 #65 — the rows are still written and `#/admin/email` still lists them by
  reason, which is where a too-narrow filename pattern is actually diagnosed, and 46 of one
  dev BU's 140 rows were the customer's own rule doing exactly what they wrote it to do.
  `NOISE_REASONS` is one code now (`unreadable_document`): a file the rule *refused* was never
  a document, one it **accepted** and we could not open is a statement we failed to read, and
  that one stays under `All`.
  ⚠️ `IS DISTINCT FROM`, not `!=` — `NOT (status = 'skipped' AND reason_code =
  'no_rule_match')` is NULL for a `skipped` row with no reason code, which would have deleted
  the exact row `_chip_expr`'s `else_` goes out of its way to keep visible.
- `tests/integration/test_credit_card_activity_api.py` — `_hidden()` models the filter in the
  mock DB for both the GROUP BY and the window, so a hidden pair contributes nothing by
  default; `test_the_noise_is_still_in_the_log` inverts into
  `test_a_filename_rule_refusal_is_in_no_view_at_all`; three noise fixtures move to
  `unreadable_document`; one new compiled-SQL test for the NULL-safety and for the filter
  being on both statements.
