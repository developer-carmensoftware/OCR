## `13:40` Fix follow-up (root cause): bank-blind row filter dropped fee-invoice line rows

### Backend

- `13:40` The actual cause of the empty `details`: `llm_service.extract_from_image` runs a **bank-blind** row filter (`[r for r in details if not _is_zero(r.pay_amt) and not _is_wht_row(r)]`) *before* the bank-aware `_normalize_fee_invoice`. Fee-invoice line rows carry `pay_amt=null` by design, so this filter deleted every one of them before the normalizer could compute `pay_amt` from the footer VAT. (Round-1 masked it: the old wrong-value bug misplaced the line amount into `pay_amt`, making it non-zero, so rows accidentally survived the filter — fixing that removed the accidental survival.) Extracted the filter into a testable pure helper `_clean_llm_rows(details, *, is_fee_invoice)` that skips the blank-`pay_amt` drop for fee invoices while still dropping WHT rows for all banks and 0.00/blank filler rows for statement banks. The bank is resolved via the existing `detect_bank_code` on the extracted fields.
- `13:40` Promoted the fee-invoice code set to `FEE_INVOICE_CODES` (`utils/bank_detect.py`, the shared bank-knowledge module both services already import) — single source of truth; `credit_card_service` now imports it instead of its private `_FEE_INVOICE_CODES`.
- `13:40` New `tests/unit/test_llm_row_clean.py` (4 cases: fee-invoice blank-pay_amt line rows survive, WHT dropped, statement zero/blank dropped, statement non-zero kept).
