## Uncommitted / in progress

### `09:30` — `order_reviewer` role: order queue without the admin dashboard

Reviewer accounts were going to have to be `admin`, which meant full access to every
admin page plus quota editing and credit-balance adjustment. Split the review console
off onto its own permission so a reviewer account can only do the one job.

**DB** — `supabase/migrations/20260730000000_order_reviewer_role.sql`

- New permissions `orders:read` / `orders:write`; new system role `order_reviewer`
  holding only those two.
- `super_admin` / `admin` also granted `orders:*`, `viewer` granted `orders:read` —
  nobody loses access they had.

**Backend** — `app/routers/admin/credits.py`

- Slip-review queue, AR customer profiles, Carmen AR posting and KPI endpoints moved
  from `quotas:*` → `orders:*` (14 endpoints).
- Balance / topup / adjust / ledger (the `#/admin/credits` page) stay on `quotas:*` —
  that's the line an `order_reviewer` must not cross.

**Frontend**

- `AdminAuthContext.login()` now returns the resolved `AdminUser` so the caller can
  route on permissions.
- `AdminLogin` lands an admin without `tenants:read` on `#/order-review` instead of
  `#/admin`.
- `AdminRouter` (`main.tsx`) hard-redirects the whole `#/admin/*` tree to
  `#/order-review` for the same case — one check instead of per-nav-item filtering.

**Tests** — `tests/integration/test_admin_credits_api.py`

- `test_order_reviewer_can_work_the_queue_but_not_credit_balances` asserts an
  `orders:*`-only principal gets 200 on the queue and 403 on all four credit endpoints.
- Shared `make_admin_test_client` default perms extended with `orders:*`.

Creating a reviewer: `#/admin/admin-users` → add user → tick **Order Reviewer** only.
Existing admins must re-login — perms are baked into the admin JWT at login.
