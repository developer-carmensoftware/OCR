# 2026-09-10

## `#/email-settings` rebuilt as the reference for Carmen's own screen

`12:00` Carmen's draft of the customer-facing settings screen is a conventional card form
with `SAVE SETTINGS` / `RESET` at the bottom. Ours was a different idea of the same thing —
three numbered steps, chip lists with a per-item Add button, one collapsed rule list with an
edit form, and no Save button at all (every control PUT on change). Both being different was
the problem: our copy exists so the contract can be exercised end to end, and it is the thing
handed over as "here is the screen", so it should be the layout they are building rather than
an argument with it.

**Frontend**

- `pages/EmailSettings.tsx` rewritten to Carmen's layout on our `ui-*` kit (`PageHeader`,
  `Card`, `Switch`, `Button`, `Badge`): a URI/BU strip, a **Service status** card (Ready
  badge, ingest address + COPY), an **Automation settings** card (two toggle cards, two
  textareas, one card per rule with `ADD RULE`), a **Posting credential** card, and a sticky
  Save/Reset bar. That kit's CSS already loads app-wide from `index.css`, so the page's own
  sheet dropped from 420 lines to ~250 and `.email-setup__input` — a local copy of
  `.admin-form-input` — is gone.
- `hooks/email-settings/useEmailSettings.ts` is now a dirty form: `draft` / `patch` / `save`
  / `reset` / `dirty` replace the five write-through setters. One `PUT` per editing session
  instead of one per keystroke, which the 20/min rate limit cares about. The list fields live
  in the draft as **raw text** — splitting per keystroke eats the separator the user is
  halfway through typing — and one `splitList()` parses all three at save.
- **`auto_post` is still sent only when that switch is what moved.** It is the one
  merge-on-omit field (§2.7), and a Save button lengthens rather than removes the race with a
  colleague editing the same BU on Carmen's screen. `seedDraft()` is now the single place
  that decides what the form carries, and therefore the only way `doc_type` could go missing
  from a full-replace save again — the case the existing tests were written for.
- Owner emails and tax IDs become textareas (comma or newline), every rule is expanded and
  editable, `Active` is a switch on every rule including a new one, and field errors render
  under the input named by `field` rather than in a block at the foot of the step.
- Dropped: the Gmail confirmation block. The poll follows Google's link itself, so it was a
  card-sized explanation of something that needs no one. What survives is a single amber line
  in Service status, shown only if Google ever goes back to printing a code.
- Added a `beforeunload` guard while the form is dirty — the page has no in-app nav links, so
  that covers the realistic way to leave it.
- `components/admin/ui/Switch.tsx` gained an optional `ariaLabel`. The two toggle cards put
  the caption on the far side of the card, which left `role="switch"` with no accessible
  name; the review switch is the one control that lets a document post unseen, so it is not
  one to leave unnamed. Additive — every existing caller passes `label` and is untouched.

**Tests** — `EmailSettings.test.tsx` and `useEmailSettings.test.ts` rewritten against the new
surface, keeping every `doc_type` guarantee and adding: Save is disabled until something
changes, nothing reaches the server before it, Reset restores what the server last confirmed,
a rejected save keeps what was typed, `pdf_password` untouched is sent as `null` not `''`,
and `splitList` drops a trailing separator. 718/718 pass; `tsc`, `lint`, `npm run styles` and
`npm run contrast` clean.

**Docs** — `docs/CARMEN_INTEGRATION.md` §2.8 "Reference screen layout": the section order,
what each card holds, which three blocks are ours and skippable (posting credential, live
status/blockers, document type), and the two save rules that matter more than the layout.

No `VERSION` bump and no release note: the route is linked from nowhere and reached by typing
the hash, so this is internal.
