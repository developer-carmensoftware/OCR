`10:48` **Refactor Phase 4: the frontend moves into `features/` + `shared/`, with a `@/` alias.**
*(branch `refactor/phase4-frontend-features`, stacked on the Phase 3 branch)*

A move only: no module changes which file it loads, and no test was edited beyond its import lines.

- **Frontend**: 283 files move.
  - `features/<admin|ap-invoice|billing|credit-card|email-settings|home>/` each hold that feature's
    pages, components, hooks, lib and api.
  - `shared/` holds what two or more features (or `main.tsx`) use.
  - The placement comes from the import graph, not from folder names. Five files the plan had filed
    under one feature are used by two or more, so they went to `shared/`: `apTax`, `reviewReasons`,
    `orderHelpers`, `api/ocr`, `api/credits`.
  - `AdminAuthContext`, `AdminProtectedRoute` and, until Phase 6 splits it, `adminClient` are in
    `shared/` because the app shell needs them to gate `#/admin*`.
  - `OrderReviewShell` moved to `features/admin` because it wraps an admin page.
  - `i18n/`, `styles/`, `test/`, `assets/` and `main.tsx` stay put.
- **How it was done, in 5 commits**:
  - (1) `@/` resolves in vite and vitest (tsconfig already declared it), and every `../` import becomes `@/`.
  - (2) a pure `git mv`, so `git log --follow` survives.
  - (3) every import is re-pointed from the old layout, plus one hand fix: the bank-logo `new URL()`
    template the codemod cannot see.
  - (4) ESLint `no-restricted-imports`: nothing outside `features/admin` may import it statically
    (type-only imports allowed). `main.tsx` reaches the dashboard only through `lazy(import())`.
  - (5) docs.
- **Guards**:
  - The `vi.mock` path guard now checks `@/` specs too. Otherwise it would have passed vacuously.
  - vitest's coverage scope follows the files (`**/hooks`, `**/lib`, `**/api`). It covers the same
    67 files at the same percentages as before, checked in a separate worktree.
- **Docs**:
  - `CLAUDE.md`'s hook-directory convention is replaced by the `features/` + `shared/` layout,
    the placement rule and the admin import rule.
  - Paths in `docs/`, code comments and the cc-jv contract's comments are updated. `graphify update` has been run.
- **Verified**:
  - `tsc` and ESLint pass: 0 errors, and the same 6 pre-existing `exhaustive-deps` warnings.
  - prettier is clean. vitest: 802/802.
  - `vite build`: the same 80 JS chunks, 2,008,908 B vs 2,008,940 B (−0.002%). Only three chunk
    *names* changed, because rolldown names a chunk after its entry file.
