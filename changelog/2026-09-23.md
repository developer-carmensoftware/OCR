# 2026-09-23

### `09:35` — Ticket E: redesign the Description field's settlement extras

Raised right after Ticket D shipped, with a screenshot: for a settlement-capable bank the
merged Description field stacked four pieces into the form's narrow `200px / 1fr` value
column — the input (showing raw `{Tag}` syntax once inserted), the "Applies to KBANK
documents" caption, an "Insert" row of three chip buttons, and a boxed "READS AS" preview
line. Functionally correct (Ticket D's own Playwright pass proved the mechanism), but
cluttered — user's words, "รกและใช้งานยากมาก."

First direction (quiet text-link chips, Carmen Blue on hover, no border/background, tooltip
showing the literal tag) was rejected on two grounds: the visual treatment, and a real gap
it exposed — **nothing stopped inserting the same tag five times.** The user's mental model
was "adding the TAG," a discrete action with a one-shot result, not a link.

- `components/credit-card/TopLevelConfigSection.tsx` — the settlement-extras block moves
  out of the Description field's cramped value column to a full-width sibling
  (`grid-column: 1 / -1`), breaking out of `.form-grid`'s `200px / 1fr` constraint the same
  way a wider control already would. `TEMPLATE_TAGS` now carries a label key per tag
  (`ar.tagSettlementDate` / `ar.tagTaxInvoiceNo` / `ar.tagBankName`) instead of the raw
  `{Tag}` string standing in for its own label. Each button reads whether its tag is
  **already present in the current text** (`current.includes(tag)`) — derived at render
  time, not tracked as separate state — and is `disabled` with a check icon when it is,
  Plus icon when it isn't. Deriving rather than tracking means deleting the tag from the
  text by hand re-enables the button with no extra bookkeeping, and it self-corrects
  regardless of whether the tag arrived by click or by typing.
- `styles/pages/ar-reconcile.css` — replaced `.ar-tags-label`, the bordered-chip `.ar-tag`,
  and the separate boxed `.ar-example` with pill-shaped buttons (`--radius-pill`,
  `--emerald-text` / `--emerald-light` for the disabled/"added" state) and a plain
  `→ rendered text` line directly beneath, connected rather than boxed off. Added
  `@media (pointer: coarse) { .ar-tag { min-height: 44px } }`.
- `i18n/dict.ts` — dropped the now-unused `ar.template` / `ar.templateTags` /
  `ar.templateExample` keys (the redesign no longer shows a literal "Insert:" label row or
  a separate "renders as" heading); kept `ar.templateEmpty`. Added `ar.tagSettlementDate` /
  `ar.tagTaxInvoiceNo` / `ar.tagBankName` (the human-readable labels) and `ar.tagInsert` /
  `ar.tagAdded` (button `title` text) in both `en` and `th`.
- The "Applies to KBANK documents" caption is **not** duplicated in the new block — it was
  never duplicated to begin with (it belongs to the Description field itself, one line,
  unchanged); the user's note to remove it turned out to describe the target state already.
- `scripts/style-coverage.mjs` — its hardcoded `SURFACE` list still named
  `pages/ARReconcileSettings.tsx` and `components/ar-reconcile/ARMappingTable.tsx`, both
  deleted in Ticket B, which crashed `npm run styles` outright (`ENOENT`) rather than
  running. Removed the two dead entries so the gate runs again; left the surface list
  otherwise unchanged; `TopLevelConfigSection.tsx`/`Mapping.tsx` were not added to it — they
  lean on their parent page's own CSS import for `.section`/`.form-grid`, a pre-existing
  pattern this ticket didn't touch and isn't the place to relitigate.
- `TopLevelConfigSection.test.tsx` — the 4 existing "settlement tag extras" tests updated
  to query the human-readable labels instead of literal `+ {Settlement_Date}` text. Two new
  tests: disabling a tag already present (and that clicking a disabled button is a no-op —
  the setter is never called), and a stateful-harness test proving the actual round trip —
  click inserts and disables, deleting the tag from the text by hand re-enables it — using
  a real `useState` wrapper rather than the file's stateless `setup()` helper, since a
  mocked setter can't demonstrate a state transition.
