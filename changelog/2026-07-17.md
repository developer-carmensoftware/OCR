## `14:30` Two signal-quality fixes found during the dead-code sweep

Neither was a bug; both were tools whose output nobody could act on.

### Infra

- `14:30` **`.gitattributes` (new) — `* text=auto eol=lf`.** `npm run format:check` failed on
  **192 files** on any Windows checkout and passed in CI: `core.autocrlf=true` writes CRLF while
  prettier defaults to `endOfLine: lf`. Content was byte-identical, so the check was pure noise —
  and a real formatting error would have hidden among the false ones. Now green locally (0 files)
  and matched to CI. `*.ps1` pinned to `eol=crlf` (`run_dev.ps1` stays native).
  - Applying it needed `git add --renormalize .`, which reported **zero content change** — git had
    been storing LF all along, so nothing in history moved. Binaries are untouched (`text=auto`
    detects them: `i/-text w/-text`).
  - Note for anyone pulling this: `git status` will list every text file as modified until you run
    `git add --renormalize .` once. That is the index catching up to the new attribute, not a diff.
- `14:30` **`.gitignore` — added `frontend/rd-diag.json`.** react-doctor's generated report was
  committed once (`f5b3888`, 2,795 lines) and deleted again (`bb27f38`) with nothing stopping a
  third round-trip. It regenerates from the skill on demand; a snapshot in git only goes stale.
  `doctor.config.json` is config and stays tracked. Corollary worth remembering: the `VAT_NOTE`
  dead export deleted below was already sitting in that report on 2026-06-25 — the finding was
  correct, it just had nowhere to live once the file went away.
