# 2026-09-16

## A blank clearing account no longer posts a JV that never clears

`11:20` Found while building something else (see the next entry): a bank saved with a
blank clearing account posts a JV that balances, shows no unmapped payment types, and
never zeroes the control account it exists to clear. Nothing was checking for it —
`is_balanced` has nothing to object to, and every payment type really is mapped; the debit
leg just has no dept/acc. The error stays invisible until somebody reconciles the control
account by hand.

**Backend**

- `ar_reconcile_jv.control_leg_missing(rows)` — true when the debit leg (the row with no
  `key`) has no dept or no account, or when there is no debit leg at all. One
  implementation, called from the auto-post gate, `approve_document`, and
  `jv_for_document`'s output, so "blank clearing account" is caught the same way
  everywhere. No new DB read — a pure function over the rows `build_ar_jv_rows` already
  built.
- `ARPreviewOut.control_missing` (new field, default `False`) — `jv_for_document` sets it;
  the review screen reads it to block Approve, `_review_flags` reads it to add a new
  `clearing_account_missing` flag that parks a document instead of letting it auto-post.
- `readiness()`'s `mapping_complete` blocker now says "No report has arrived yet to map"
  instead of "0 of 0 mapped" for a bank with genuinely no mapping rows yet (true before its
  first `PUT /settings`, since `get_settings` passes no `mappings` at all in that branch).
  A separate small fix, found in the same pass and too small to land on its own.

**Frontend**

- `ReviewDocument.tsx`: `arBlockReason` gained an `arJv.control_missing` check, ranked with
  `unmapped` — both mean the JV cannot post at all — plus a new `arSettingsFix` link, the
  same shape as the existing `prefixFix` link for an unset journal book, pointing at
  `#/CreditCardOCR/ar-settings` when that is what is blocking Approve.
- `QueueRow.tsx` + `emailReview.ts`: new `clearing_account_missing` reason, ranked beside
  `mapping_missing` (`review.reasonClearingAccountMissing`).
- 3 i18n keys, EN+TH: `arControlMissing`, `actionFixClearingAccount`,
  `reasonClearingAccountMissing`.

Release note pending (user-visible: a settlement report with no clearing account set now
waits for review instead of posting a JV that silently never clears its control account —
fixed at `#/CreditCardOCR/ar-settings`). No `VERSION` bump — batched per release, per the
changelog convention.

## The review modal goes back to a pure preview

`11:35` Question that started this: does `#/CreditCardOCR/ar-settings` still need to exist,
or can everything finish in the review modal now that `ARReviewPane` maps payment types
inline (2026-09-11)? Traced it and found the enable toggle, bank picker and readiness chain
have to live outside any modal regardless — a document can only reach the modal *after*
those gates already passed. A first attempt went the other way anyway: it shrank the
settings screen and moved the clearing account and the JV description template into the
modal alongside the payment-type mapping.

**Reverted the same day, and further than that.** Having seen it built, too much
settings-shaped data ended up crammed into the review modal. Decision: one edit surface,
not two — `ar-settings` keeps everything, including the bulk mapping table, and the modal
goes back to being a pure preview of the JV that will post. That undoes 2026-09-11's own
inline-editing addition (`2731543`) along with today's unshipped attempt.

**Backend**

- `PATCH /api/v1/ar-reconcile/mappings`, `upsert_mapping_rows()` and `ARMappingPatchIn` are
  gone. Their only caller was the modal editing that no longer exists.

**Frontend**

- `ARReviewPane.tsx`: every Dept/Account cell (control leg, mapped legs, new/unmapped
  types) is a value again, not a `CustomSearchSelect` picker. Dropped
  `overrides`/`onOverride`/`onUndo`/`guessedKeys`, the background AI-fill effect, and the
  `onState` live-unmapped tracking that fed only it. Kept 2026-09-11's actual improvements:
  the column order matching `JvEditor`, and the collapsible disclosure for a Summary
  merge's folded-in lines.
- `ReviewDocument.tsx`: reads `arJv.unmapped` straight off the fetched document again, the
  way it did before 2026-09-11. `approve()` lost the whole AR mapping-save step
  (`patchARMappings` + refetch + re-validate); nothing left in this modal writes anything.
- A blank cell now reads "Not mapped" and is fixed on `#/CreditCardOCR/ar-settings`, which
  is where the previous commit's block-reason link already points.

## Design pass on the door to ar-settings

`11:52` `/impeccable` critique of the AR path scored it 28/40; `detect.mjs` came back
clean. The weak heuristics were Consistency, Flexibility and Minimalist, and all three
landed on one element — the link to `ar-settings` under the JV table, which had just been
promoted to a `btn btn-outline btn-sm` pinned right. That overcorrected. It put a bordered
button directly above `.rd-actions`' Approve at the same edge, so the last thing under the
reviewer's eye before the button that posts was a button that *leaves* — an in-app hash
navigates in this tab (`fixLinkProps`), so pressing it loses the open document. It also
borrowed `.rd-alert-fix`'s grammar, where "outline btn-sm pinned right in a text row" means
*this row is an alert and here is the fix*, and it out-weighed its own caption
(0.75rem/600/`--text-2` bordered, over 0.76rem/400/`--text-3` prose).

- `.rd-ar-hint` is a flush-left column now, and the door is `.rd-ar-hint-btn` — a local
  ghost (muted fill, no border, no shadow) rather than a `.btn` variant. Left breaks the
  right-edge stack so it is no longer a decoy in the commit zone; a column rather than a
  wrapping row keeps it flush at every width and lets the Thai label, half again the
  English one, grow without moving anything. No new global `.btn-ghost` for one call site,
  and no new icon — the app has no gear glyph and `ChevronRight` already means *expand* in
  the table right above it. No local `:focus-visible` either: base.css's global rule is
  already the identical declaration at this element's radius.
- `.arv-flat` collapses the disclosure gutter when nothing in the table can open — every
  Detail document, and any Summary day that settled one scheme. It was ruling an empty
  1.9rem column down the left edge, so the table read as indented from its own caption.
  Zeroed rather than removed: that column is one `<td>` in five row species and `tfoot`'s
  `colSpan={4}` counts it.
- `.rd-ar-hint p` and `.arv-grouping` move to `--text-2`. Both are ~12px at weight 400,
  which is the case `DESIGN.md` names as needing a darker ink than Tertiary; `npm run
  contrast` cannot catch it, since it audits token pairs and not the size they are set at.
  The same violation in `.arv-note`, `.arv-toggle-count`, `.arv-src` and `.arv-row-zero td`
  is left for a separate pass — `.arv-note` is the worst of them, carrying "not mapped —
  pick Dept/Account to post it" on a row that blocks Approve.
- `review.arMappingLivesElsewhere` reworded EN+TH from a dash-terminated fragment into a
  complete sentence, since it no longer runs into an inline link.
- Dead CSS removed: `.rd-ar-hint a:hover` (left from the inline-link version, outranking
  `.btn-outline:hover` and happening to set the same colour) and a `margin-left: auto` the
  paragraph's `flex: 1 1 24rem` had already made a no-op.

Known and deliberately not addressed: when `control_missing` blocks Approve there are still
two doors to `#/CreditCardOCR/ar-settings` with different labels (`.rd-ar-hint-btn` and the
footer's `.rd-blocked-fix`), while the `unmapped` blocker gets no footer link at all; the
door is one-way; and `dirty` has no writer on the AR path, so the discard-confirm guard is
unreachable there. The ghost's fill measures 1.07:1 against the card — the label carries the
legibility at 11.35:1 (light) / 8.03:1 (dark), which is what "quiet" bought.

Verified in the browser against the dev server across light/dark × Detail/Summary × EN/TH:
gutter 0px when flat and 30px when a merge exists, caption and button both flush at the
table's left edge with Approve 892px away, focus-visible confirmed via real keyboard Tab.
