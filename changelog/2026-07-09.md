# 2026-07-09

## `00:00` Admin dashboard bilingual EN/TH rollout

Reported bug: the lang toggle (EN|ไทย) on the admin page did nothing when clicked.
Root cause: the toggle mechanism worked fine, but only one string
(`admin.overview.description`) was ever wired to `t()` — every nav label, KPI, table
column, form field, and toast across the admin dashboard was hardcoded English. Per
user direction, this also reverses the prior design decision that admin was
English-only; admin is now bilingual via the same `dict.ts`/`useT()` system already
used for the customer-facing purchase flow and `CreditOrdersPage.tsx`.

### Frontend

- `00:00` `i18n/dict.ts`: added ~230 `admin.*` keys (en + th) covering
  `AdminLayout.tsx` nav/chrome, all 14 previously-untranslated admin pages
  (`Overview`, `AdminLogin`, `Anomalies`, `Sessions`, `Jobs`, `Performance`, `Usage`,
  `LLMLogs`, `Errors`, `Credits`, `TenantRanking`, `Tenants`, `QuotaModules`), and
  `admin.common.*` for strings shared via `TenantSelector.tsx` / `MetricChartImpl.tsx`
  / `MetricChart.tsx` / `DateRangePicker.tsx`. Replaced the stale
  "titles/nav/tables stay English" banner comment.
- `00:00` Wired all of the above (14 pages + `AdminLayout` + 4 shared components) to
  `useT()`/`t()`, mirroring the pattern already used in `CreditOrdersPage.tsx`. Module-level
  label consts/columns (`AdminLayout`'s `NAV_SECTIONS`, `QuotaModulesPage`'s `TABS`,
  several `DataTable` column defs) moved inside their components so they can call `t()`.
- `00:00` `CLAUDE.md`: corrected the "English is the default UI language" bullet — admin

Verified: `tsc --noEmit` and `eslint` clean across all changed files; grepped for
leftover hardcoded `label=`/`title=`/`placeholder=`/`aria-label=` strings (none found
outside intentionally-untranslated data/brand terms).

## `18:40` Dark mode contrast fix: badges/toasts with unreadable text

Root cause across all three spots: a theme-aware background var (correctly darkens
in `[data-theme='dark']`) paired with a hardcoded literal text color tuned only for
the light background — the two converge to near-identical lightness in dark mode.

### Frontend

- `18:40` `pages/Home.tsx`: `ACTIVE_TAG` (module-card-tag "Active" pill) — `color`/`border`
  switched from literal `oklch(...)` to `var(--emerald)`/`var(--emerald-mid)`.
- `18:40` `styles/pages/admin.css`: `.status-badge.ok/.error/.warn` (admin Tenants/Jobs/
  Sessions/Performance pages) — literal text colors switched to `var(--emerald)`/
  `var(--destructive)`/`var(--amber-text)`, matching the already-correct pattern in
  `styles/components.css`.
- `18:40` `styles/base.css`: added `--success-foreground`/`--info-foreground` overrides
  to the `[data-theme='dark']` block (previously only `--amber-text` was overridden there)
  — fixes unreadable success/info sonner toast text in dark mode with no `sonner.css` change needed.
