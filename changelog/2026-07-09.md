## `00:00` Admin dashboard bilingual EN/TH rollout

Reported bug: the lang toggle (EN|ไทย) on the admin page did nothing when clicked.
Root cause: the toggle mechanism worked fine, but only one string
(`admin.overview.description`) was ever wired to `t()` — every nav label, KPI, table
column, form field, and toast across the admin dashboard was hardcoded English. Per
user direction, this also reverses the prior design decision that admin was
English-only; admin is now bilingual via the same `dict.ts`/`useT()` system already
used for the customer-facing purchase flow and `CreditOrdersPage.tsx`.

## `18:40` Dark mode contrast fix: badges/toasts with unreadable text

Root cause across all three spots: a theme-aware background var (correctly darkens
in `[data-theme='dark']`) paired with a hardcoded literal text color tuned only for
the light background — the two converge to near-identical lightness in dark mode.

## `21:15` CA-34 Admin User Management (list/create/edit/deactivate + role assignment)

Jira CA-34, child of epic CA-21. Backend RBAC schema (`admin_users`/`roles`/
`role_permissions`/`admin_user_roles`) and permission seed rows already existed but had
no CRUD surface — this closes that gap. `super_admin`-only (the seeded `admin`/`viewer`
roles are deliberately excluded from `admin_users`/`roles` permissions). v1 writes only
global role grants (`tenant_id=""`); per-role tenant scoping is supported by the schema
but not exposed in the UI. Deactivation is not instant — it blocks future logins only;
an already-issued admin JWT (8h TTL) has no revocation path and stays valid until it
expires (known/accepted limitation, no revocation list built).

### Backend

- `21:15` `models/schemas/admin_users.py` (new): `AdminUserCreateRequest`,

- `21:15` `services/admin_user_service.py` (new): list/get/create/update admin users,
