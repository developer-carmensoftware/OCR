## `21:15` CA-34 Admin User Management (list/create/edit/deactivate + role assignment)

Jira CA-34, child of epic CA-21. Backend RBAC schema (`admin_users`/`roles`/
`role_permissions`/`admin_user_roles`) and permission seed rows already existed but had
no CRUD surface — this closes that gap. `super_admin`-only (the seeded `admin`/`viewer`
roles are deliberately excluded from `admin_users`/`roles` permissions). v1 writes only
global role grants (`tenant_id=""`); per-role tenant scoping is supported by the schema
but not exposed in the UI. Deactivation is not instant — it blocks future logins only;
an already-issued admin JWT (8h TTL) has no revocation path and stays valid until it
expires (known/accepted limitation, no revocation list built).

## `23:40` Dark mode fix: square seam on step-wizard "done" checkmark

Reported bug: the completed-step checkmark circle in `StepWizard.tsx` (AP Invoice /
Credit Card wizards) showed a stray rectangular seam overlapping the icon, only in
dark mode. Isolated via one-change-at-a-time testing (box-shadow removal did not fix
it; ruled out).

### Frontend

- `23:40` `styles/components.css`: `.step.done .step-num` — `border-color: transparent`
  → `border: none`. Root cause: a transparent border on a `border-radius` element with
  a gradient background is a known Chromium/Windows rendering bug that paints a visible
  seam along the border track; removing the border entirely (rather than making it
  transparent) avoids the seam.

## `16:15` OCR speed: shrink + JPEG re-encode images before vision-LLM calls

Lowered the pre-LLM image resize threshold (4096px → 2200px) and switched the
re-encode format from PNG to JPEG q92 to cut upload bytes/latency without a
visible OCR-quality loss, for both Credit Card and AP Invoice (which never
resized images at all before this). Along the way, fixed a latent bug where the
MIME type sent to the LLM was always derived from the upload's filename
extension rather than the actual re-encoded bytes — harmless while resizing was
rare (old 4096px threshold), but would have surfaced routinely once resizing
became the common case for typical phone-camera photos (3000-4032px).

### Backend

- `16:15` `utils/image_processing.py` `resize_if_needed()`: new signature
  `(image_bytes, max_dimension=2200, jpeg_quality=92) -> tuple[bytes, str]`.
  Passthrough path now returns a Pillow-detected mime instead of leaving mime to
  the caller; resize path flattens alpha/palette-transparency onto a white
  background (not a naive `.convert("RGB")`, which can leave transparent regions
  black) *before* resizing (Pillow silently drops to NEAREST resampling on
  P/1-mode images otherwise), then re-encodes as JPEG. CMYK passes through
  unmodified, matching the existing `convert_heic_to_jpeg` precedent.
- `16:15` `services/llm_service.py` `extract_from_image()`: new
  `image_mime_type` kwarg — takes priority over `get_mime_type(filename)` when
  provided, so the declared MIME always matches the actual bytes.
- `16:15` `services/ocr_service.py` `extract_stateless()`: unpacks the
  `resize_if_needed` tuple and threads the mime through; PDF branch untouched
  (mime stays `None` → falls back to `application/pdf`).
- `16:15` `services/ap_invoice_service.py` `extract_ap_invoice_data()`: the
  non-PDF branch now calls `resize_if_needed` at all (previously sent raw
  upload bytes unresized/unbounded); swapped the now-unused `get_mime_type`
  import for `resize_if_needed`.
- `16:15` `tests/unit/test_image_processing.py` (new): unit coverage for
  `resize_if_needed` — RGBA/palette/CMYK/16-bit-TIFF/WebP-alpha inputs that
  would otherwise crash a raw JPEG save, the white-composite-not-black
  transparency case, boundary/override behavior, and a mime-matches-actual-bytes
  round-trip assertion.
- `16:15` `tests/unit/test_image_resize_pipeline.py` (new): service-level tests
  that call the real `ocr_service.extract_stateless` /
  `ap_invoice_service.extract_ap_invoice_data` with only `call_vision_llm`
  mocked, since the router tests mock past this boundary entirely and would not
  catch a mime-threading wiring bug.
