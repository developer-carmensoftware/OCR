`10:20` **Payment-type mapping: one dialog for every bank and document type.** *(`836891ad`, on
`feat/detailed-cc-ar-reconciliation`)*

The "Map Payment Types" modal had grown in layers: the fee-invoice list, a "Show additional mappings" collapse, and a settlement section appended below. On KBANK with Summary selected, that produced:

- every settlement key listed twice;
- a header counter "(7/10 mapped)" counting the wrong list;
- two AI Suggest buttons and stacked red banners;
- Cancel that reverted only fee-invoice edits.

It is rebuilt as a bank-agnostic component, modelled on SaaS mapping screens (A2X, Brex, Ramp, Polaris IndexTable).

- **Frontend: `features/credit-card/components/payment-mapping/`.**
  - **`PaymentMappingDialog`** renders `MappingSet`s. A tab appears only when a bank has more than one list.
  - Each set gets one progress count and bar, one AI Suggest, and one message bar:
    - amber when types need an account;
    - red only for a pair Carmen's `DefaultAccount` refuses;
    - green when everything is mapped.

  - Row order is fixed when the dialog opens, and the "Needs mapping" filter keeps its rows until the filter changes, so rows don't jump while being mapped.

  - Full screen on phones. Esc cancels.

  - **`BulkApplyBar`**: select rows, then apply one department and account. The account list follows the department.
  - **`types.ts`**: `MappingSet`/`MappingItem`/`statusOf`/`statsOf`. No bank knowledge.

- **`hooks/mapping/mappingSets.ts` (`buildMappingSets`)** is the only place that knows which lists a bank has:
  - a settlement layout adds the in-use Detail/Summary set;
  - the fee-invoice list always exists for other banks, and only when non-empty for a settlement bank.

  - `open`/`cancel`/`done` draft every set at once, and settlement edits now revert on Cancel (`useSettlementMapping.snapshot/restore/dropSnapshot`).

`11:07` **Mapping page: Branch No defaults to head office (00000), and the wizard's input tax posts
the document's branch.** *(on `feat/detailed-cc-ar-reconciliation`)*

Reported: Branch No on `#/CreditCardOCR/mapping` has to be retyped every time. It is **not a save
bug**. `PUT /config/accounting` stores `bu_accounting_configs.branch`, GET returns it, and the page
prefers it (dev `carmen` has `00000` stored). The problem is a gap in the design:

- Branch No was the only Company Info field with no automatic value. Name, Tax ID and Address come
  from `BANK_INFO`. Branch came from the saved BU row or else from the last scanned document's
  branch in localStorage, which `clearAppStorage()` wipes on every 401 or logout and which
  BAY/PAYPAL/SIAMPAY never fill.
- So every new BU, and every BU whose config row was created first by the email or review path,
  opened with a required field blank. `saveAllSettings` then refused the GL save until someone
  typed `00000` by hand. `nopackage1` has `0000` stored, typed that way.
- Everything downstream already treats a missing branch as head office: `_HEAD_OFFICE` in
  `input_tax.py` and `extracted.branch_no or config.branch` in the email pipeline.

Changes:

- **Frontend: `hooks/mapping/useBankConfig.ts`.** The branch is the saved BU value, else `00000`.
  The last-scanned-document fallback (`ocrBranch`, from `b6dd20b3`) is deleted. It copied one
  document's branch into a BU-wide fallback, and KTC's `branch_no` is the merchant's own branch.
- **Frontend: `components/InputTaxReconciliation.tsx`.** The ACTX `BranchNo` is now `document →

`13:13` **Correction feedback no longer drops the whole batch over Branch No.** *(on
`feat/detailed-cc-ar-reconciliation`, follows the entry above)*

Found in that Playwright run. Editing Branch No in the wizard sent `field_name: "BranchNo"` to
`/feedback/corrections`, and it got a 422. `BankCompanyName` had the same gap. The server validates
the batch as a whole, so every other correction made with it was lost too. The browser then logged
"✓ Logged ?/1", because the code never checked `res.ok`.

- **Backend: `models/enums.py`.** `FieldName` gains `bank_company_name` and `branch_no`. These are
  the extraction's own names, so the per-field error-rate hints (`correction.py` →
  `prompts/__init__.py`) line up with the prompt. `correction_feedback.field_name` is `varchar(100)`,
  so no migration.
- **Frontend: `api/feedback.ts`.**
  - The map gains `BankCompanyName`/`BranchNo`.
  - `logCorrections` now sends only fields in the map. Before, an unknown key went through as-is,
    so the next new header field would have taken the batch down the same way.
  - A non-OK response logs an error instead of "✓ Logged".
- **Tests:**
  - New `api/feedback.test.ts` (3): the snake_case names, an unknown field left out, nothing sent
    when nothing is known (including `constructor`, which a plain `in` check would have let through).
