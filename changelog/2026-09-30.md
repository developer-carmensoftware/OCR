# 2026-09-30

`10:20` **Payment-type mapping: one dialog for every bank and document type.** *(on
`feat/detailed-cc-ar-reconciliation`)*

The "Map Payment Types" modal had grown in layers: the fee-invoice list, a "Show additional mappings" collapse, and a settlement section appended below. On KBANK with Summary selected, that produced:

- every settlement key listed twice;
- a header counter "(7/10 mapped)" counting the wrong list;
- two AI Suggest buttons and stacked red banners;
- Cancel that reverted only fee-invoice edits.

It is rebuilt as a bank-agnostic component, modelled on SaaS mapping screens (A2X, Brex, Ramp, Polaris IndexTable).

- **Frontend: `features/credit-card/components/payment-mapping/`.**
  - **`PaymentMappingDialog`** renders `MappingSet`s. A tab appears only when a bank has more than one list.
  - Each set gets one progress count and bar, one AI Suggest, and one message bar:
    - amber when types need an account;
    - red only for a pair Carmen's `DefaultAccount` refuses;
    - green when everything is mapped.
  - Search and filter chips (All / Needs mapping / Suggested).
  - Row order is fixed when the dialog opens, and the "Needs mapping" filter keeps its rows until the filter changes, so rows don't jump while being mapped.
  - Done on an illegal pair switches to that list and scrolls to the row.
  - Full screen on phones. Esc cancels.
  - **`MappingTable`**: the column header sits on the rows, and there is an inline add row. A duplicate is refused in place instead of via a toast.
  - **`BulkApplyBar`**: select rows, then apply one department and account. The account list follows the department.
  - **`types.ts`**: `MappingSet`/`MappingItem`/`statusOf`/`statsOf`. No bank knowledge.
  - `MappingRow` now reads as a table line: a neutral mono code, a status dot and edge, and status in words for screen readers. The solid red/green badges are gone.
- **`hooks/mapping/mappingSets.ts` (`buildMappingSets`)** is the only place that knows which lists a bank has:
  - a settlement layout adds the in-use Detail/Summary set;
  - the fee-invoice list always exists for other banks, and only when non-empty for a settlement bank.
  - A new document type is one more producer here.
  - `open`/`cancel`/`done` draft every set at once, and settlement edits now revert on Cancel (`useSettlementMapping.snapshot/restore/dropSnapshot`).
- **Root cause of the duplicate list (`useMapping`).**
  - Saved entries whose `source` is `settlement_*` no longer load into `paymentAmount`/`customPaymentTypes`.
  - A settlement type removed in the dialog used to come back untagged on save; now it stays removed.
  - When the settlement hook has nothing to give, the loaded settlement entries are sent back unchanged, because the PUT replaces the bank's entries and absent means deleted.
- **Shared rules.** New `applyPaymentMappings`/`addPaymentType` (fee invoice) and `applyToMany`/`acceptAllSuggestions` (settlement). A settlement row now clears an account its new department forbids, the same as a fee-invoice row.
- The page's credit row summarises the dialog's first list (e.g. "3 of 3 need an account · Settlement report · Summary"). Unmapped is amber, no longer red.
