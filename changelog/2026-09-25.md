# 2026-09-25

`10:12` **Email ingest: the mailbox queue is our own `$OcrDone` flag, not `\Seen` — opening
the mailbox no longer loses mail.** *(uncommitted)*

Fixes F-1 and F-4 from the multi-BU QA run
([`docs/email-automation/qa/2026-09-24-multi-bu-report.md`](../docs/email-automation/qa/2026-09-24-multi-bu-report.md)).

- **F-1 (HIGH):** the poll's queue was `SEARCH UNSEEN`, and `\Seen` is something anyone can
  set. During the QA run 39 appended mails were marked read by a reader outside the poller and
  never produced a row. In production, support opening `AIAGENT@` to look into a complaint would
  have erased exactly the document in question. `email_imap.fetch_unseen` → `fetch_pending`
  (`UID SEARCH NOT KEYWORD $OcrDone …`, all three searches incl. the `SMALLER` fallback and the
  beyond-window count); `mark_seen` → `mark_done` stores `(\Seen $OcrDone)` — `\Seen` kept only
  so the label reads as handled to a person. Deleting a mail or removing its label still loses it.
- **F-4 (LOW):** `fetch_confirmations` fetched `(RFC822)`, which on Gmail sets `\Seen`, so a
  confirmation for a tag nobody was waiting on was consumed instead of left for the document poll
  (its docstring promised the opposite). Now `BODY.PEEK[]`, same `$OcrDone` queue.
- An odd `FETCH` response shape was skipped with no trace; it now logs a warning naming the UID
  (the mail stays pending, as before).
- **Transition:** new `scripts/imap_mark_done_backfill.py` (dry run by default) flags mail older
  than the hold window done, so the first poll does not raise `email_ingest_beyond_window` for
  the mailbox's whole history. In-window mail is left pending on purpose: already-decided mail
  dedupes on `email_documents` for free, and whatever F-1 hid is found and processed. Dev dry run:
  209 → done, 86 in-window left for the poll. **Run it against prod before this deploys** —
  see [`05-operations.md`](../docs/email-automation/05-operations.md).
- `scripts/reset_email_test.py --unread`, `reset_tenant_email.py`, `email_ingest_e2e.py` now
  clear/check `$OcrDone`; clearing only `\Seen` would replay nothing.
- **Tests:** unit — the queue never mentions `UNSEEN`, `mark_done` sets both flags, the
  confirmation sweep peeks, the odd-FETCH skip is logged.

No release note: no customer-visible behaviour change.
