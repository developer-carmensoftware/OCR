# 2026-09-25

`10:17` **Email ingest: a document's own verdict outranks a dead Carmen credential; settings
saves keep rule fields they don't know.** `fb02bbc`

Fixes F-6 and F-5 from the multi-BU QA run
([`docs/email-automation/qa/2026-09-24-multi-bu-report.md`](../docs/email-automation/qa/2026-09-24-multi-bu-report.md)).

- **F-6 (MEDIUM):** the GL suggester runs before the tax-ID and "already posted" checks on
  purpose (parked documents still get suggestions), but it re-raises a 401/403, so on a BU whose
  token had died a foreign-TIN document parked as `carmen_unauthorized`. The reviewer was sent to
  fix a credential and never told the document was not theirs. `_run_document` now reads the tax
  ID with the accounting config, decides the verdict (`tax_id_mismatch`, else
  `duplicate_document` "Already posted to Carmen") before the suggester, and raises it after. A
  401/403 from the suggester still flags the token (new `_flag_dead_token`, shared with the
  handler) but no longer replaces the verdict. With no verdict nothing changes. Module docstring
  and `02-architecture.md` Diagram 6 follow the real order (the diagram also stopped claiming
  suggestions are saved at ingest; they are saved when a human approves).
- **F-5 (LOW-MED):** `email_settings_service._merge_rule` rebuilt each rule from the five fields
  it knows, so a key written by a newer version (`doc_type`, on the unmerged
  `feat/detailed-cc-ar-reconciliation`) was deleted by the next save from an older one. A rollback
  after AR merges would have turned settlement rules back into fee-invoice rules. It now starts
  from the stored rule. The AR branch edits the same function; the merge is trivial.
- **Tests:** unit +3. A foreign TIN or an already-posted document with a suggester 401 keeps its
  reason and still flags the token; an unknown rule key survives a save. All three fail on `main`.

No release note: no change for a BU whose credential is alive.
