`10:43` **fix(preview): PDF iframe shows blocked (🚫) icon instead of rendering**
- Root cause: lint autofix in `f5b3888` added `sandbox="allow-downloads allow-same-origin"` to the PDF `<iframe>`s; Chrome's built-in PDF viewer (PDFium, a scripted internal page) refuses to render in a sandboxed iframe without `allow-scripts` → blocked placeholder. New-tab (no sandbox) still worked.
- `allow-scripts` alone fixed Chrome but **Edge still blocked it** ("This page has been blocked by Microsoft Edge") — Edge refuses its built-in PDF viewer in any sandboxed iframe.
- Fix: removed `sandbox` entirely from both PDF iframes — `DocumentPreview.tsx` (OCR wizard + customer preview) and `OrderWorkspace.tsx` (admin slip viewer). Restores pre-`f5b3888` behavior; works in Chrome + Edge. Safe: framed content is our own trusted PDF (same-origin blob / time-limited Supabase signed URL), not arbitrary HTML. Added a `ponytail:` comment at each so it isn't re-sandboxed by a future lint pass.
