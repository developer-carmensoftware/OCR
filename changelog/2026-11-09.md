## JV queue: search + one `+ Filter` button, chips inline, same two-chip strip (branch `feat/jv-queue-filters`)

`14:30` The `#/CreditCardOCR` filter was one dimension (status): tabs `Review | All` plus a
dropdown on All. Nothing could filter by source, bank or date, and there was no search.
**The §24 concept is kept on purpose: two chips (`Review n · All`), no Posted / Not posted chip.**
- **The bar went through three shapes in one day; only the last one shipped:** four status chips
  (rejected: contradicts §24) → the All dropdown back + a popover of 17 pills + a chip row +
  a badge (rejected as bulky: three stacked rows, ~100px, the same fact shown three times) →
  **one row: search · `+ Filter` · chips**, modelled on Stripe's filter chips and Linear / Polaris
  index filters.
- **Frontend:**
  - `QueueFilters.tsx` `FilterBar`: the search box (debounced 300 ms), a `+ Filter` button, and a chip
    per *applied* attribute — `Status: Posted ✕`, `Source: Email, Manual ✕`, `Bank: KBANK ✕`,
    `Date: Last 7 days ✕`. The chip is the control and its result: its label reopens its value list
    (checked value shown), ✕ or Backspace drops it. `Clear` appears only while a chip exists and
    keeps the search text.
  - `+ Filter` opens a small menu: attributes first (Status › Source › Bank › Date, with the current
    value on the right), values only after one is picked — single-select (radio) for Status / Bank /
    Date, multi-select (checkbox, stays open) for Source; a bank is shown with its name; the Bank
    list says "PMS days have no bank" where the choice is made. Arrow keys, Enter, ←/Backspace to go
    back, Esc closes and returns focus to whatever opened it.
  - Posted / Not posted are the Status attribute; they light the All chip. Today is a Date value
    (`?filter=today` still opens All → Today). The All-chip dropdown, the pill popover, the badge and
    the second chip row are deleted.
  - The view is written to the hash (`?filter=&q=&source=&bank=&range=`, `replaceState`) and read back
    on mount. A narrowing that empties a BU that has rows says "No documents match", not "No scans yet".
  - ≤720px: the search and `+ Filter` share a row; the menu opens in the flow at full width.
- **Backend:** `GET /api/v1/credit-card/activity` takes `q`, `source` (comma list), `bank`, `range`
  (`today|7d|30d`). One `Narrow` is applied to the list **and** the counts statements of all three
  sources, so the Review count and the Pager describe the pile the table shows. A bank filter excludes
  PMS days. LIKE wildcards in `q` are escaped.
- **Guard: a PMS day has no bank, so the two are never asked for together** (strict: any PMS among the
  sources locks the Bank filter, and a bank locks the PMS option; no source + a bank still means
  "documents with that bank", which leaves PMS out). Three layers:
  - **UI:** the Bank row of `+ Filter` is `aria-disabled` with *PMS has no bank* on it while PMS is a
    source; the PMS option is disabled with *Remove the Bank filter first* while a bank is set. Dead
    rows are shown, not hidden; Arrow keys step over them; click and Enter do nothing; nothing is ever
    deleted behind the user's back. `pick()` re-checks, so the lock does not live only in markup.
  - **URL:** `reconcileNarrow()` runs on a pasted / bookmarked / hash-changed link: the bank goes, PMS
    (the explicit choice) stays, before the first request.
  - **API:** `parse_narrow()` raises the existing typed `ValidationError` (HTTP 400, no
    `HTTPException`) for `source` containing `pms` with a bank — in any case, padding or order, with or
    without an unknown source beside it. `source` is now normalised (`strip().lower()`) before it is
    compared.
- **Bug found by the new matrix, fixed:** searching a PMS day read `cast(payload as text)`, so it
  matched the hook's **field names** too — typing "type", "name", "interface" or "doc" listed every PMS
  day the BU has. It now matches the words the row shows: `PMS`, interface name, doc type, and the date
  as sent and as printed (`DD/MM/YYYY`).
- **Accessibility defects found by axe and fixed:** the menu's *Back* button and its "PMS days have no
  bank" note sat **inside** `role="menu"` (`aria-required-children`, critical — a menu may hold only
  items), and the button's `aria-label` ("Back") did not contain its visible text
  (`label-content-name-mismatch`, serious). Both now sit outside the menu element, and the name is
  `<attribute> – Back`.
