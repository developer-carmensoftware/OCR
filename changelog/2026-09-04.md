## The queue's empty states stop being placeholders

`09:40` Reported on the screenshot: the caught-up screen *"ดูไม่เป็นทางการ และยังไม่เหมือน
ระบบ SaaS อื่น ๆ"*. It read:

> **All clear**
> Statements forwarded to aragent+1ad4e0b6@carmensoftware.com appear here.

Five faults, four of them the repo's own rules:

1. **The address was prose.** 40 characters of identifier set in body copy, unspaced and
   unbreakable, wrapping mid-address — while `NotSetUp`, two branches away in the same
   file, gives that same string a mono field and a copy button.
2. **One screen answered three questions.** `clearFilter = review || success || today` sent
   all three to one card, so an empty **Posted** chip said "All clear". It has not posted
   anything; that is not all clear. The comment at `dict.ts:803` shows this was already felt
   and answered by making the sentence vaguer, which is why it had stopped saying anything.
3. **No next step** — against `DESIGN.md:333` (*"an instructional empty state that teaches
   the next step"*). Since yesterday's `All` chip this was also a genuine dead end: the dev
   BU with **101 never-charged rows** lands on Today, is told there is nothing, and had no
   way to reach its own log.
4. **Two unrelated empty states on one page** — that card, versus a bare grey
   `<p>Nothing here yet.</p>` for Not posted and All.
5. **A shadow on a card with nothing to click** — against `DESIGN.md:238`'s Flat-By-Default
   rule (*"a shadow is a promise that something is interactive"*).

### Frontend

- `pages/ReviewQueue.tsx` — `AllClear` and the bare paragraph are replaced by one
  `QueueEmpty`, driven by an `EMPTY` map that sits beside `FILTER_LABEL`. Five states, each
  with its own title, body, icon and tone. `clearFilter` is deleted: a boolean could not
  express "the tick is earned" once there were five chips, and in the map each state's tone
  sits next to its words so the two cannot drift.
- **The tick is kept only where it is earned** — `review` and `today`, the two states that
  mean nothing is owed. `success`, `unposted` and `all` get a neutral glyph in a muted well.
  Bare glyph for a semantic colour, glyph-in-a-well for a neutral one, is the convention
  `orders-empty-icon` already set on the order history.
- **The ingest address is gone from this screen** (kept on `NotSetUp`, unchanged). It is
  also what lets each body be specific again: the old sentence was vague because it had to
  stay true with `auto_post` on *and* off, and none of the five replacements names
  forwarding or approval at all, so none of them can go stale that way.
- **One action, `View all activity`**, shown when `filter !== 'all' && counts.all > 0` —
  the only route the page did not already offer. Deliberately not a second
  `Upload documents`: that button is primary in the bar directly above, and repeating a
  primary CTA inside an empty state is what makes a screen read as filler.
- The icon markup moved into a wrapper `<span>` so a tone can draw a well, which an SVG
  cannot draw for itself; colour still reaches the glyph through `currentColor`. Applied to
  the error state here and to `ReviewDocument.tsx`'s `.rd-gone` card too, so the page has
  one icon idiom rather than three.
- `styles/pages/review-queue.css` — `.rq-empty-icon` base is now the wrapper
  (`display: grid`), `.rq-empty-icon--calm` is the new muted well. `--text-4` is correct
  there and only there: `DESIGN.md:176` calls that tier decorative-only and the glyph is
  `aria-hidden`; the body copy beside it stays on `--text-3`. `npm run contrast` already
  covers the pairing — `text-4 on muted`, 3.23:1 against a floor of 3.
- `box-shadow` moved off the shared `.rq-empty, .rq-intro` rule onto `.rq-intro` alone,
  which always carries a button. `.rq-empty-tab` deleted — nothing renders it now.
- `i18n/dict.ts` — out: `review.allClearTitle`, `allClearBody`, `allClearBodyNoAddress`,
  `emptyTab`. In: five `empty*Title` / `empty*Body` pairs plus `review.viewAllActivity`,
  both languages.

## A manual scan names who ran it

`09:55` Requested: *"scanned and posted by hand" ตรงนี้อยากให้เป็น "scanned and posted by
{username}" ไปเลย เข้าใจกว่า.* Correct — "by hand" answers *how*, which the reader can already
see from the row, and not *who*, which is what they were reading the Message column for.

**No migration.** `credit_cards.carmen_user_id` is already stored (33 of 42 submitted rows on
dev carry it), and `tenant_lookup.username_map()` already bulk-resolves that opaque id to a
username out of `ocr_sessions` — it is what the admin user-usage page reads. One extra query
for the whole window, and every existing row is covered.

### Backend

- `routers/credit_card_activity.py` — `list_activity` resolves the scanners of the manual
  window in one `username_map()` call and hands each name to `_manual_row`.
- `schemas/email_automation.py` — `ActivityRow.posted_by_name`, **deliberately not reused
  from `reviewed_by_name`**, which it would otherwise fit. That is a stored ledger column on
  `email_documents`, written once and kept for ever, and nobody *reviewed* a manual scan.
  This one is resolved at read time and goes null once the session behind it is scrubbed at
  90 days. Two different guarantees; one field holding both is how a reader ends up trusting
  the weaker one.

### Frontend

- `QueueRow.tsx` — the manual branch names the person when we have one and keeps the old
  wording when we do not. `review.postedManuallyBy` (`scanned and posted by {name}` /
  `สแกนและลงบัญชีโดย {name}`) joins the existing `review.postedManually`, which survives as
  the fallback: printing a raw user id at somebody is worse than the vaguer sentence.

### Tests

- Backend: a manual row names its scanner; an unresolvable one names nobody and leaves
  `reviewed_by_name` null too. `_db` grew a sixth `db.execute` response for `username_map` —
  always supplied, consumed only when a manual row actually carries an id, so the positional
  `side_effect` cannot shift under the existing tests.
- Frontend: the named row and the fallback row, both asserted on the rendered sentence.
