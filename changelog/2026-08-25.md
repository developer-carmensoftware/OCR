  credential path nothing served). Safe because `Settings.Config.extra = "ignore"`:
  an env var still set on a live service is ignored, not a boot failure.
- **Removed unread settings** `app_host`, `app_port`, `admin_jwt_ttl_hours`
  (`config.py`). `run.py` hardcodes port 8010 — `APP_PORT` had been documentation of a
  var nothing read. Purged from `.env.example`, `CLAUDE.md`, `README.md` and the SRS
  env table.
- **Removed `get_all_tenants()`** (`app/database.py`) — zero references.

## Refactor audit — Tier 3a: the JV body is now pinned across both implementations

`11:00` **The risk this closes.** `cc_jv.py` builds the Carmen `gljv` body for email
automation; `lib/ccJv.ts` + `useOcrSubmission.ts` build the same body for the wizard.
The Python docstring said the two were *"kept deliberately in step"* — by hand. Both
suites tested their own side and **nothing tested that the two agreed**, so a drift
would have posted wrong money with every test still green.

- **`contracts/cc-jv.contract.json`** — one fixture, read by both suites:
  `backend/tests/unit/test_cc_jv.py::test_contract_fixture` and the new
  `frontend/src/lib/ccJv.contract.test.ts`. Four cases: a two-payment-type bank
  statement, a gateway fee invoice (net = 0, so the Bank Account leg must be *shown*
  in Step 3 but *dropped* from `Detail`), unknown-bank-code + empty-description
  fallbacks, and a Buddhist-era date. All four assert a balanced JV.
- **New top-level `contracts/` directory.** The fixture was first put in
  `test-fixtures/`, which turns out to be **gitignored** (*"Local test fixtures"* —
  developer-generated mock invoices). It would never have reached CI. A cross-language
  contract is not a local fixture and neither side owns it, so it lives at the root.

**Three real divergences found while writing it** — all pinned, none were bugs:

- `JvhDate`: Python emits `+00:00`, JS emits `.000Z` for the same instant. The test
  compares instants, never strings.
- `UserModified`: `''` from the wizard, `'OCR-EMAIL'` from ingest. This difference is
  the *point* of the field (CARMEN_INTEGRATION.md §4.3), so it sits outside the shared
  `expected` and each side asserts its own value.
- Zero-padding is load-bearing: `new Date('2026-8-5')` parses as **local** time and
  lands on the previous day in UTC, while `datetime(2026,8,5)` does not move. Both
  producers pad today (`normalizeDateStringToCE`, `formatDateToDDMMYYYY`), so it is
  unreachable — now documented in the fixture and in `jvhDate()`.

### Frontend — one extraction, so the test covers shipping code

- **`buildGljvPayload()` moved out of `useOcrSubmission.ts` into `lib/ccJv.ts`**, next
  to `buildJvRows` and mirroring the Python module's shape. Without this the contract
  test would have asserted against a *copy* of the payload logic rather than the code
  that actually posts. `useOcrSubmission` keeps the snake_case/camelCase config
  normalisation (that is about where config came from) and passes one clean shape.
- `parseJvhDate()` moved with it as `jvhDate()`; the duplicate `JvRow` interface in
  `useOcrSubmission.ts` is now a re-export of the one in `ccJv.ts`.

**Verified by mutation, both directions:** breaking the tax-leg description in
`cc_jv.py` reddens the backend suite (3 failures) and leaves the frontend green;
breaking it in `ccJv.ts` reddens the frontend suite (4 of 6) and leaves the backend
green. Each implementation is independently pinned to the contract.

50 files** (up from 501/49).

## Refactor audit — Tier 2: deduplication

`11:20` Third of four refactor PRs from the maintainability audit. Frontend nets
**−17 lines** while *adding* three new files (338 lines), so roughly 355 lines left the
pages; backend is exactly **196/196** insertions/deletions, confirming a pure rename.
The main JS bundle drops **202.0 kB → 187.7 kB** (gzip 50.5 → 47.3).

### Frontend — `useTableData`, the fetch every admin table was hand-rolling

- **New `hooks/admin/useTableData.ts`** — companion to `useTableQuery`. Owns
  `{ rows, total, loading, reload }`, the failure toast, and the effect. Eight pages
  carried a byte-identical `useState`×3 + `useEffect` block, each with its own
  `eslint-disable react-hooks/exhaustive-deps`; **7 of those 8 disables are gone**
  (PerformancePage keeps one, for its unrelated debounce effect).
- Converted: Jobs, LLM Logs, Performance, Sessions, Anomalies, User Usage,
  Extractions, Tenants.
- **Fixes a race none of the eight handled.** Typing in a search box fires one request
  per keystroke and nothing ordered the responses, so a slow early one could land last
  and repaint the table with rows that no longer matched the filters. The hook keeps a
  monotonic request id and lets only the newest write. Fixed once instead of eight times.
- Behaviour note: ExtractionsPage started `loading` at `false` where the other seven
  started `true`. It now matches them — a loading state on first paint instead of a
  flash of "empty".

### Frontend — one admin route registry instead of two hand-synced lists

- **New `pages/admin/routes.tsx`** — `NAV_SECTIONS` carries `hash`, `icon`, `labelKey`
  *and* `component`, and `ADMIN_ROUTES` (hash → page) is derived from it. Previously the
  sidebar tree in `AdminLayout` and a 19-branch `else if` chain in `main.tsx` listed the
  same 18 hashes independently. Verified before merging that the two lists already
  agreed exactly — 18 for 18, nothing orphaned either way.
- **New `pages/admin/AdminRouter.tsx`** — the hash routing moved out of `main.tsx`. This
  is what keeps the dashboard lazy: `main.tsx` now knows only that `#/admin*` belongs to
  one lazily-loaded component, so the nav tree, its icons and the 18 `lazy()` thunks all
  left the main bundle (−14.3 kB).
- `AdminLayout` 260 → 94 lines; `main.tsx` 292 → 202. **Adding a page is now 2 edits,
  not 4** — CLAUDE.md updated in the same commit.

### Frontend — duplicated helpers, and one that must NOT be merged

Three merged; **two of the three were behaviour differences, not copies**:

- `fmtDateTime` — `OrderActions` used `toLocaleString()` while the rest of the dashboard
  uses `lib/date`'s `toLocaleString('sv-SE')`. The same dashboard rendered two date
  formats. Now one (`YYYY-MM-DD HH:mm:ss`).
- `daysAgo` — `EmailAutomationPage`'s copy went through `toISOString()`, so at UTC+7 any
  call before 07:00 local returned **the day before** the one the user meant. Now uses
  `PeriodPicker`'s local-date version. A real off-by-one, not just duplication.
- `timeAgo` — the notification bell's copy had no null/NaN guard; now uses
  `orderHelpers`', which does.
- **`fmt` and `formatThb` were left alone deliberately.** They look interchangeable but
  are not: `fmt` runs input through `parseNum` (strips commas), `formatThb` uses
  `Number()`, which returns `NaN` for `"1,234.56"` and renders `"0"`. `fmt` has ~20 call
  sites in the AP-invoice and credit-card wizards passing extracted strings. Merging
  them would have silently zeroed money on screen.

### Frontend — one accessor for `accountingConfig`

- `readAccountingConfig()` / `writeAccountingConfig(patch)` in `lib/storage.ts`, which
  already owned `appKey` and the key list. The `AccountingConfig` type moved there too
  (re-exported from `useAccountingConfig` for existing importers). Six call sites across
  four hooks each had their own `JSON.parse(localStorage.getItem(...) || '{}')`, their
  own inline cast and their own `try/catch`.

### Backend — the underscore stops lying

- Seven modules reached across into another module's `_private` names. Renamed to public:
  `_num`/`_r2` (`cc_jv`), `_wrap_network_error` (`carmen_service`), `_estimate_cost`/
  `_get_pricing` (`pricing_cache_service`), `_decode_jwt_claims` (`performance`),
  `_validate_token`/`_validate_uri` (`auth`).
- `carmen_service._get_client` became **`get_http_client`**, not `get_client`: the latter
  already exists in `llm/client.py` as the `AsyncOpenAI` factory, and two `get_client`s
  meaning different things is worse than the underscore.
- The one survivor, `from app.config import settings as _cfg_early`, is a local import
  alias rather than a reach into another module's internals — left as is.
- **`ap_invoice_postprocess_service` kept its `_num`/`_r2`.** A first pass renamed those
  too, since they share a name with `cc_jv`'s. They are a different function — `r2` there
  rounds with a `1e-9` epsilon, `cc_jv`'s with `0.0` — and nothing outside the module
  imports them, so they are correctly private. Reverted.

### Noted, not done

`services/usage_service.py` still describes itself as a *"backward-compat re-export shim —
Phase 10 will remove this file"*, and still re-exports three private names. It is not dead:
four app call sites and several test patch targets depend on it. Removing it means
repointing those and rewriting the patch targets — its own change, not this one.
