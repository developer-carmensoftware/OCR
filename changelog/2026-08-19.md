# 2026-08-19

## Uncommitted / in progress

`09:10` **Maintenance pass — codebase review, then the deletions and tests it turned up.**
Months of feature work without a structural look-back. The review verdict was that the
codebase is in good shape (no dead modules, no orphaned CSS, hook-subdir convention actually
followed, CI stronger than most repos this size) — so this is a short list of things that had
stopped paying rent, not a restructure. Branch `chore/maintenance-pass-tier1-2`.

### Frontend

- **Tailwind removed entirely.** A sweep of every `className` in the frontend found exactly
  one Tailwind utility in use — `AdminProtectedRoute.tsx`'s loading `<div>`. Everything that
  looked Tailwind-ish (`kpi-grid`, `sk-w-68`, `w-120`, `text-center`) is the app's own CSS;
  the `grid`/`flex` grep hits were substrings of custom class names. Dropped `tailwindcss` +
  `@tailwindcss/postcss`, deleted `styles/tailwind.css` and its `index.css` import, reduced
  `postcss.config.js` to autoprefixer. That one div now uses inline styles with
  `var(--text-4)` — which is theme-aware, unlike the `text-gray-400` it replaced. Removes the
  `@source '../**/*.{js,ts,jsx,tsx}'` scan from every rebuild.
- `lib/dates.ts` merged into `lib/date.ts` — one file exported a single `fmtDateTime`
  alongside a six-function `date.ts`. Eight admin pages repointed; `ExtractionsPage`'s
  `const fmtDate = fmtDateTime` alias inlined.
- `index.css` — **documented, did not "fix", the CSS conflicts the review found.** Three
  shared classes are defined twice with materially *different* designs, and `pages/admin.css`
  + `pages/ap-invoice.css` are imported globally from `index.css` despite the "pages/" name,
  so they silently win same-specificity conflicts app-wide. `.status-badge`
  (components.css:1357 vs pages/admin.css:715) traces back to two Badge components —
  `components/common/Badge.tsx` and `components/admin/ui/Badge.tsx` — emitting the same base
  class with disjoint variant vocabularies (`info/success` vs `ok/warn/error`). `.lang-toggle`
  and the `.mapping-modal*` family are the same shape of problem; the modal ones are further
  superseded by `.pm-*` in `payment-modal.css` except for a dark-theme rule that outranks it
  on specificity. Each needs the page checked in light *and* dark before a rule is deleted —
  a visual call, not a mechanical one, so the analysis is now a comment block at the exact
  place load order is decided.

### Backend

- **The CI mypy step was reporting nothing and had been for months.** It ran
  `mypy app/tools/`, but `app/tools/` no longer exists; `continue-on-error: true` swallowed
  the resulting path error. The hand-written path list also duplicated pyproject's
  `[[tool.mypy.overrides]]` and had drifted from it. CI now runs plain `mypy app/` and lets
  pyproject own the strict list — one source of truth. Baseline is 52 errors, the large
  majority `Column[...]` false positives from SQLAlchemy 1.x-style model declarations
  (clearing those means migrating `app/models/` to 2.0 `Mapped[]` — noted, not done).
- With the step actually running: removed 12 now-unused `# type: ignore` comments
  (`warn_unused_ignores` was already on and had never been able to say so), and replaced the
  `not (x in seen or seen.add(x))` dedupe idiom in `config.py` and `utils/pages.py` with
  `list(dict.fromkeys(...))` — same behaviour, stdlib, one boring line, two fewer errors.
  65 → 52.
- `services/quota_service.py` → **`services/module_gate.py`**. The quota engine went away
  with migration `20260813000100`; all that survived is `assert_module_enabled()`, so the
  filename had been lying about its contents. The test file was already called
  `test_module_gate.py` — the rename is what the codebase already expected.
- Deleted the dead `[tool.pytest.ini_options]` block from `pyproject.toml`. `pytest.ini`
  takes precedence, so that copy had never been read — and had already drifted (no
  `addopts = --capture=no`, the documented Windows-teardown workaround).

  `rate_limit_service` 100%, `task_service` 100%, `correction_service` 100%,
  `audit_service` 97%, `credit_order_service` 91%, `pricing_cache_service` 82%.
  Priority was money and security: `credit_order_service` moves credits and had no dedicated
  test at 623 lines, and the rate limiter guards admin-login brute force. The rate-limiter
  tests inject a fake monotonic clock — no sleeps, no flakes.
- Guards worth naming, because they are the ones a refactor would quietly break: the
  double-fulfilment check must fire *before* any grant (a double-click otherwise

  pricing-DB failure must not be cached as "known missing"; audit logging must never raise
  into the request it is describing.
- **CI coverage floor 50% → 72%.** Measured 76% after the backfill; set 4 points below so
  routine PRs do not fail on platform coverage variance.

### Frontend — CSS consolidation (the item deferred earlier today, now done)

`14:20` The three duplicated selectors turned out not to be duplicates: each was **one rule
split across two files**, with each half supplying properties the other lacked, so deleting
either side would have changed rendering. Resolved by reading the built bundle to see which
declarations actually won, then collapsing each pair to exactly that set.

- `.status-badge` and `.lang-toggle` — merged into single rules in `components.css`. Verified
  byte-equivalent: a script comparing computed declarations before/after the build reports
  `.lang-toggle` IDENTICAL across 15 selectors, and `.status-badge` differing only by
  `align-items`/`gap`, which were inert (the sole `display` declaration is `inline-block`) and
  by a dark `.neutral` rule rewritten as a `border-color` override that computes the same.
- The two Badge components are now one. `admin/ui/Badge.tsx` had a single consumer
  (`EmailAutomationPage`), so it folded into `common/Badge.tsx`; both tone vocabularies stay,
  since the admin pages set `status-badge` as a raw classname rather than only through <Badge>.
- `mapping-modal*` removed from `PaymentTypeModal.tsx` — the `.pm-*` rules in
  `payment-modal.css` had already superseded them. Checked first that
  `[data-theme='dark'] .mapping-modal-content`'s `--card-bg` and `.pm-dialog`'s
  `--data-card-bg` are the *same value in both themes*, so dropping the override changes no
  colour. That freed ~129 lines of dead CSS, including `@keyframes modalSlideUp` and
  `.modal-mapping-*`/`.transaction-item`, which had zero TSX usages left.

**Two real bugs surfaced while doing it**, both the same shape — a shared control styled from
a page stylesheet:

- **`.btn-confirm` had no base rule outside the Mapping CSS chunk.** Eight call sites across
  admin credits, maintenance, `CustomModal`, `APGroupModal` and the order tables rendered an
  unshaped button unless the user happened to visit `#/mapping` first in the same session and
  left that chunk in the document — while `base.css`'s `[data-theme='dark'] .btn-confirm` and
  the `.modal-* .btn-confirm` colour rules were global all along and silently depended on it.
- **`.btn-cancel` was overridden in `mapping.css` with a hardcoded `background: white`** and no
  dark counterpart: a white pill with light-grey text once the theme flipped.

Both fixed by moving them to `components.css`. `.btn-confirm` is now an alias on `.btn-primary`
rather than its own button — it is a colour-only modifier sitting on `.btn` (the same vocabulary
`.btn-outline`/`.btn-danger` use), so the two can never drift. A first attempt gave it invented
colours (`--primary` border, a custom blue glow) instead of the design system's `--primary-dark`
+ `--shadow-sm`, which read wrong next to the other admin buttons; corrected. The one call site
missing the companion `.btn` class (`PaymentTypeModal`'s OK) now has it.

`index.css`'s header comment now records why `pages/admin.css` and `pages/ap-invoice.css` being
imported globally is a trap, and lists the four controls not to move back.
