# 2026-09-01

## One pagination control, and the reader picks the page size

`10:45` Every list in the app had its page size **measured off the viewport**
(`useFitRows`) rather than chosen. Two separate widgets rendered the result: `Pager` under
the five customer-facing lists, and DataTable's own inline block under the eleven admin
pages. Neither offered a "Rows per page" control, and on a 4K panel a table would fetch
40 rows nobody asked for.

Measuring also carried a live hazard. In server mode the measurement fed the fetch, and
the rows it asked for changed the space left below the table — 15 rows leave room that
measures as 17, 17 leave room that measures as 15 — so DataTable needed a monotonic
high-water guard to stop the tab fetching forever (shipped as a bug on 2026-08-24). A
number the reader picked cannot oscillate, so the guard and its regression test go too.

### Frontend

- **`Pager` is now the only pagination control**, and grows an optional `onLimitChange`:
  present renders `Rows per page: [15 ▼] 1–15 of 393 ‹ ›`, absent keeps today's bar. A
  native `<select>` over `[15, 25, 50, 100]` — 100 is the lowest backend cap among the
  lists that get it (`/credit-card/activity` and `/credits/orders` are both `le=100`), so
  no option can 422.
- **DataTable renders it too**, deleting its own 27-line block. Sixteen screens that had
  two pagination vocabularies now have one. An explicit `pageSize` (only
  `ExtractionsPage`'s nested table) still fixes the size and hides the control.
- **The choice is remembered** — new `hooks/useRowsPerPage.ts`, one global
  `localStorage['rowsPerPage']`. Deliberately **not** `appKey()`: like `theme` and `lang`
  it is a UI preference, not tenant-scoped business data, so it survives logout and is
  never wiped. `useTableQuery` seeds its default from it *synchronously*, so an admin
  table's first fetch already asks for the right size instead of fetching 25 then 50.
- **Visibility rule changed** from `total <= limit` to `total <= 15`: at 20 rows the
  arrows are dead but "show me 15" is still a real choice.
- **A page turn keeps its rows.** Skeletons now render only when there is nothing to keep
  (`loading && rows.length === 0`); otherwise the table carries `aria-busy` and dims.
  Every arrow click used to blank the table and repaint it.
- **Deleted**: `hooks/useFitRows.ts` + its two test files, and
  `DataTable.fetchloop.test.tsx` — the loop it guarded against cannot occur any more.
- `common.rowsPerPage` added (EN + TH); `admin.common.table.range` / `.prev` / `.next`
  removed with the block that used them.

### Frontend — one fewer request per page turn

- **`useReviewQueue` no longer refetches the review status on every page turn.**
  `Promise.all([getReviewStatus(), listActivity(…)])` ran on `[filter, limit, offset,
  nonce]`, so each arrow click cost two round trips and one of them could not possibly
  return anything new — status is configuration (`enabled` / `entitled` /
  `ingest_address` / `blockers`), not content. Split into two effects: config on `[nonce]`,
  content on `[filter, limit, offset, nonce]`.
- The property its docstring guards is preserved: `loading` stays true until status has
  landed, so the "not set up" screen still cannot flash on a BU with documents waiting.
  Each call keeps its own error flag now, ORed — otherwise a list success would clear a
  status failure and the page would paint a state it could not actually determine.

### Backend

None. Every endpoint already answers the `Page<T>` envelope and takes `limit`/`offset`.
Noted but not touched: `credit_card_activity.list_activity` fetches `limit + offset` rows
from *each* of its two sources before merging in Python, so limit=100 at offset 300 reads
400 per side. It already carries a `ponytail:` comment pointing at a `UNION ALL` if a BU
ever pages that deep; at 342 rows in the largest business table it stays cheap.

### Verification

`npm run test` 591 passed / 52 files · `npm run build` clean · `eslint` 0 errors.
New `components/common/Pager.test.tsx`; DataTable's paging block rewritten off the stored
choice; `ReviewQueue.test.tsx` now asserts one `getReviewStatus` across a chip change that
fires two `listActivity` calls.

No `VERSION` bump or release note — a UI change to an existing capability, batched per
release.

## Polish pass on the review dialog

`11:30` The rebuilt review screen (2026-08-31) was structurally right and unfinished in
the details. This is the pass over layout, states and contrast — no change to what the
dialog does or to what it posts.

### Frontend — the dialog was missing its chrome

- **`ReviewDocument` now behaves like a dialog.** It carried `role="dialog"
  aria-modal="true"` and none of what that promises: focus never entered it, Tab walked
  out into the queue behind, focus never came back on close, and the page underneath
  scrolled. `CustomModal` — the confirmation this same screen opens — has done all four
  since it was written. Added here rather than shared: CustomModal traps a fixed set of
  three controls it renders itself, while this one's focusable set changes as rows,
  pickers and the input-tax panel appear. The trap stands down while the account dropdown
  or the date popover is open (both portal outside the dialog) and while a confirmation
  is up (it runs its own).
- **Closing no longer silently discards a review in progress.** A stray click on the
  scrim and a reflex Escape are the two cheapest gestures on the screen, and both threw
  away corrected amounts and re-mapped GL accounts without a word. Both now route through
  `requestClose()`, which asks only when something would be lost. The background AI fill
  for an unmapped payment type deliberately does not count as the reviewer's work.
- **A disabled Approve says why**, at the button, naming the fix rather than the fault:
  *Choose an account for every line that carries an amount* / *Debit and credit differ by
  12.34*. `JvState` gained `reason`; the button points at the sentence with
  `aria-describedby`, so a screen reader is given it along with the disabled state.
  `review.jvBlankAccount` already existed and had never been rendered.
- **Loading is a skeleton in the shape of the dialog**, not a spinner the content lands
  around — the same `.rq-skel` rows the queue behind it uses.
- **The dialog animates in** on the same 180/240 ms and the same curve as every other
  modal, with a `prefers-reduced-motion` crossfade.
- **The Approve label stopped moving.** It read `Approve JV · updates 2` while the
  sentence above it already said *2 GL rules change when you approve* — the same number
  twice, on a primary button that changed width as the reviewer edited.
  `review.approveWithRules` deleted (EN + TH).

### Frontend — layout

- **`grid-column: span 2` → `1 / -1`** on the wide fields of `.rd-doc` and `.itx-grid`.
  Inside `repeat(auto-fit, minmax(11rem, 1fr))` a two-column span cannot fit the tail of
  a four-column row, so Description wrapped and left a hole where it had been.
- **`.jv-table` is `table-layout: fixed`**, like the queue's table. The column widths were
  declared on the header row and were not binding under auto layout, so a long description
  won the space and the money columns changed width from one document to the next.
- **The JV table stacks on a phone instead of dropping its description column** — which
  is where the AI tag and the Undo button live, so the old `display: none` was the only
  way to reach either. One stacked card per row, the same `data-label` path the queue's
  table already uses.
- **The modal header stopped wrapping** (the close button could drop to a second line) and
  now carries the **attachment filename**, which nothing else on the dialog said. The
  document number and date it used to show were a second copy of the two editable fields
  40px below them.
- Footer spacing is one `gap` instead of three per-element margins, so its height no longer
  depends on which of the error / blocked / rules lines is showing.
- The "already handled" state drops its card frame inside the dialog (it is the queue's
  empty-state card, reused) and centres in the space instead of pinning to the top.
- Touch targets under `(pointer: coarse)`: the input-tax toggle and the close button reach
  44px; the Undo tag keeps its size and grows its hit area.

### Frontend — contrast (WCAG AA)

- **`--text-4` is a large-text-only tier** (3.36:1 on the card face, as `base.css` says),
  and eleven small-text call sites on this sheet were using it: both field-label styles,
  the JV echo, the tax ID, the queue's filename line, tab counts, the message column.
  Moved to `--text-3` (4.65:1); read-only values moved to `--text-2` so a label is never
  darker than the value it names.
- **`.mapping-alert.is-danger` was `--destructive`** (bare `--rose`) on `--rose-light` =
  3.86:1 — fixed at the root in `components.css`, so every caller gets it, not just the
  Carmen rejection this dialog shows.

### Frontend — tokens and cleanup

- **`--scrim`** added (light + dark). `.modal-overlay` and `.rd-overlay` carried two
  different raw colours, so a dialog over a dialog changed the darkness of the page as
  well as adding a layer. `.rd-overlay`'s `z-index: 9000` is now `var(--z-modal-backdrop)`.
- Twelve `review.sec*` keys from the pre-redesign block headers deleted (EN + TH); the
  stale `useFitRows` comment on `.rq-table` removed with the hook it described.

### Verification

`npm run test` 593 passed / 52 files · `tsc --noEmit` clean · `eslint src` 0 errors
(5 pre-existing warnings in `hooks/ap-invoice/`). Two new tests: the discard guard fires
on a dirty close and stays quiet on a clean one; the blocked reason renders and is wired

## The activity table: column order, and which statuses reach the reader

`12:05` Follow-up to the polish pass, from a question about column order that turned into a
question about what the page is. §9 (2026-08-31) made it "the module's history" and set the
default filter to `all`; §6's heading, empty states and reason line were all written for the
inbox and never rewritten. Design record: [`07-human-in-the-loop.md`](../docs/email-automation/07-human-in-the-loop.md) §11.

### Frontend — the page opens on the work

- **Default filter `all` → `review`** (`useReviewQueue`). The heading counts `review`, the
  empty state says "you're all caught up", and the reason line exists to triage a queue —
  only the filter disagreed, and it was the one that decided what the reader saw. On the dev
  DB `all` is 61 skipped rows out of 154. The strip now reads
  `Needs review · Posted · Not posted · Skipped · All` — the four buckets a document
  actually moves through, with `All` last as the escape hatch from them rather than a peer.
- No backend default changed: `GET /activity` still answers `all` and still falls back to it
  on an unknown filter, so a stale bookmark lands where it always did.

### Frontend — the columns

`Source · Document · Received · JV no. · Status · Message · Actions`
→ `Status · Document · Message · Received · JV no. · Actions`

- **Source is not a column any more**, it is a ✉/⬆ icon on the filename line with an
  `sr-only` word. `MANUAL_FILTERS = ("all", "success")` means a manual scan can only appear
  under two of the five chips, so under `review` / `failed` / `skipped` the column said
  "Email" on every row *by construction* — which is exactly the argument §9 #19 used to
  delete Source as a concept, turned back on itself.
- **Status leads.** The pill is what distinguishes one row from the next once statuses are
  mixed (§9's whole premise) and it sat fifth, behind 18.5rem of `Received` + `JV no.`
- **The two mostly-empty columns moved right.** `JV no.` is an em dash on every non-posted
  row; Actions renders nothing for six reason codes. They cost least at the far edge.
- **`Received` prints `14:22` today and `31/08/26` otherwise**, full stamp on the `title`.
  The old `31/08/2026 14:22` bought 9.5rem to print today's date on every row that matters.
- Fixed-width columns **39.5rem → 28.5rem**. `Document` and `Message` — the two cells that
  were truncating — took the 11rem.

### Backend — `attention` beside `counts`

- **`GET /api/v1/credit-card/activity` returns `attention`**, same keys as `counts`: how many
  rows under each chip someone in the BU could clear themselves. The chip renders an amber
  dot plus an `sr-only` sentence (never colour alone).
- **Why it has to exist now.** Decision #25 established that `status` is the wrong key for
  actionability — `status = "skipped" if charged is None else "failed"` is a *billing* split
  — and fixed the Actions column for it. The chips stayed keyed on status, which was
  harmless while `skipped` was in the default view. It no longer is, so without the marker
  the 2026-08-28 `sender_not_allowed` incident has its exact conditions back: rows one field
  away from fixed, and nothing pointing at them.
- `FIXABLE_REASONS` in the router mirrors `FIX` in `QueueRow.tsx`. Nothing can assert that
  across the language boundary, so each names the other in a comment.
- The counts query is now `GROUP BY status, reason_code` with a filtered count for age —
  **one round trip, as before**, not two.

### Frontend — a stuck document stops looking like a filtered one

- **`received` gets its own pill ("Unfinished", amber) and its own message.** It is the state
  every row is *claimed* into — the backlog cap writes no ledger row at all — so one still
  sitting there means the pipeline picked a message up and never finished it. It wore the
  same calm grey `Skipped · no reason recorded` as a filename rule doing its job.
- `attention` counts one older than `STUCK_AFTER` (1 h), because `received` carries no
  `reason_code` and age is the only thing that separates stuck from in flight. A document
  being extracted during a poll run does not flicker a dot on.

### Considered and not done

- **An Amount column** — the gross is on the §6 mockup as a triage signal and is not one
  here; it stays on the Document cell's second line.
- **Re-keying the chips by `reason_code`** — the dot answers #25's problem without giving the
  strip a second vocabulary the API does not speak.
- **§6's `[Recently posted ▾]` panel**, still unbuilt: with `review` as the default the chip
  strip sits directly above the empty state, so `Posted 61` is already the evidence it wanted.

clean · `eslint src` 0 errors (5 pre-existing warnings in `hooks/ap-invoice/`) ·

## `14:20` Review screen — six things from using it

### 🐛 The dropdown that would not close

Open a GL picker, click anywhere else in the dialog, and it stayed open.

`.rd-modal` carried `onMouseDown={e => e.stopPropagation()}`, added so a click inside the
dialog would not trigger the overlay's close. **React's `stopPropagation()` stops the native
event too**, so `mousedown` never reached `document` — and both `CustomSearchSelect` and
`DateInput` close themselves from a `document` listener. Every picker in the dialog was
affected, the date picker included; nobody had hit it because until this rebuild the dialog
had no pickers.

Fixed at the overlay, not in the pickers: close only when the press landed on the backdrop
itself (`e.target === e.currentTarget`). One condition, no propagation blocking, and every
`document`-level listener inside the dialog works again. The regression test asserts the
property that actually broke — a `document` mousedown listener sees a click inside the modal.

### Prefix is a picker, Description is editable, and both persist

`fetchGLPrefixes()` already existed and proxies Carmen's `glPrefix`; it joins accounts and
departments in `useGlMasters` so the three lists are fetched once per page rather than per
modal open. Prefix now uses the same `CustomSearchSelect` the JV rows use.

**What made this more than a text input:** `approve_document` loads the accounting config
**server-side** and hands it to `build_gljv_payload`, so Prefix and Description are read from
the config, not the request — a browser edit reaches Carmen only if it is written first.
Confirmed with the user: persist, like a mapping correction. They join the existing
"N GL rules change when you approve" counter and its save-before-post.

Two things that would have silently half-worked:

- **The input edits the description's base.** What posts is `base - docDate`; the date is
  appended per document. Saving the rendered string would bake one document's date into the
  BU's rule, so the tail renders beside the field instead of inside it.
- **The write goes to whichever description wins.** `description_for` prefers
  `bank_descriptions[bank]` over the BU-wide `description`. Writing the BU-wide one while a
  per-bank entry exists looks like the edit did nothing — the per-bank value keeps
  overriding it on every future document. The request carries `bank_code` so the server
  writes the one that actually applies.

### `PUT /accounting/mappings` → `PATCH /accounting`

The partial writer shipped this morning was named for mappings; the moment it writes
`file_prefix` that path is a lie. One partial-write route, PATCH because that is what it
does. `set_mappings` → `patch_config` (mappings + header columns, `None` meaning "not
mentioned", the idiom `save_accounting_config` already uses for `bank_descriptions`).
`PUT /accounting` stays the full replace and stays unused by this screen — the whole reason
the partial writer exists (`fill_missing_mappings`: *"would delete their work between two
clicks"*).

### The queue row names the mappings the AI invented

`reasonKey(flags)` read only `flags` and returned a fixed string: "GL mapping guessed", then
made the reviewer open the document to find out which one. The row has carried `guessed` and
`unmapped` since this morning, so it now says *"GL mapping guessed: Input Tax, JCB"*, capped
at three with the full list in the `title`. `mapping_missing` was not in the ladder at all
and is now, above `unbalanced` — a gap cannot post, where a guess posts wrongly.

`glFieldLabels.ts` holds the config-key → readable-name map; `MainMappingTable` had its own
copy and now imports it, because two copies is how two screens end up calling one rule
different things.

`seed_review_demo.py` wrote `flags: ["mapping_guessed"]` with no `guessed` key — which is why
the demo row showed the badge nowhere. It writes both now.

### Input tax details, and the JV header

- The details were four short facts in a `repeat(auto-fit, minmax(11rem))` grid with two
  span-all cells, which wrapped into a tall ragged block. They read as a sentence, so they
  are set as one: two flex lines of `label value` separated by `·`, Branch still the only
  input. Roughly half the height.
- **Description is back on the header's own row** — it had `rd-f--wide` and dropped to a line
  of its own while three short fields sat above it.

### `15:20` Why some fields had a box and some did not

Reported as an inconsistency, and it was one: in a single JV row the Dept and Account
pickers sat in permanent boxes while the amount inputs beside them, equally editable, were
flat. Same for the JV header — Doc no., Doc date and Description flat, Prefix boxed.

**Cause: `CustomSearchSelect` painted its border, background and colour as an inline
`style`**, so no stylesheet could reach them. The review screen's rule is flat until hover
or focus (a grid of boxes says "form to fill in"; this screen is a document to check) and
the picker was the one control that could not follow it short of `!important`.

- The four inline declarations move into `.custom-search-select-input` in `components.css`,
  with the state arriving as `data-open` / `data-suggested` / `data-error`. Same values, so
  the mapping page renders exactly as before — nothing else in `styles/` referenced the
  class and there were no dark-mode overrides depending on the inline win.
- The review screen then gives its pickers the same flat treatment as its other fields,
  guarded by `:not([data-error]):not([data-suggested])` so an empty account still shows red
  and an AI suggestion still shows violet.
- **Flat costs the picker the only thing that said it was a picker** — it has no chevron of
  its own. The wrapper draws one and the input leaves room for it, so the control's kind
  survives losing its box.

### `16:05` The Description cell only half-filled with the row's tint

`.jv-desc` was `display: flex` **on the `<td>` itself**. That takes the element out of table
layout: the browser generates an anonymous table cell that stretches to the row, and the flex
box — the element the background is painted on — is only as tall as its own text. In a normal
row nothing showed it, because there is no background to see. In a tinted `jv-row--needed`
row, where the pickers make the line taller than one line of text, the rose stopped partway
down and the cell held two colours.

The cell is a table cell again and the flex moved to a `.jv-desc-in` span inside it. The
mobile rule loses its `display: flex` too — at that width the row is a flex column, so the
cell only ever needed its `order`.

Frontend **602 passed**, `tsc` clean, 0 lint errors, contrast all-pass.

### `17:00` "Loading your GL accounts" is not a thing to say to a reviewer

Once the document landed, the JV pane replaced itself with a centred spinner and that
sentence — a statement about two fetches of ours, in the middle of the space the table was
about to occupy, so the dialog reflowed under the reader a second time.

- **`JvEditor` waits as the table it will be** — same `<thead>` (declared once now and shared
  by both branches, so the `table-layout: fixed` widths cannot differ), skeleton rows, a
  skeleton total row. Row count is what `buildJvRows` will produce: three consolidated debit

## Fields on the review screen are a shape, not a line

`18:15` The underline treatment shipped this morning is replaced by a faint ink wash. Two
things were wrong with it.

**The visible one**: on the input-tax sentence — `VENDOR ___ · TAX ID ___ · TAX PROFILE
___ · BRANCH ___` — four rules of four different widths at four different baselines read as
debris rather than as fields. A line has to sit under something to look like anything, and
mid-sentence there is nothing to sit under.

**The invisible one**: it never existed in dark mode. `[data-theme="dark"] input` in
base.css is `(0,1,1)` and `.rd-f-input` was `(0,1,0)`, so dark overrode the background AND
all four border colours — every field on that screen was a filled, fully boxed form
control, which is the exact reading the underline was chosen to avoid. Nobody had noticed
because the design was authored in light.

### Frontend

- **One wash, `--field-rest` / `--field-hover` on `.rd-modal`.** `--text` at 5% is a real
  step on a card at L 1.0 *and* a real lift on one at L 0.225 — one declaration, no
  per-theme branch, which is what `--muted` could never be (a 2.5% step in light, so hover
  did nothing there at all). It marks the field's **extent**, not its bottom edge, so an
  empty branch box is on the screen and a row of them reads as cells.
- **Every field rule is scoped to `.rd-modal` / `.jv-table`** — `(0,2,0)` beats that dark
  override, and the screen now looks the same in both themes. `.jv-amt`'s flat-until-touched
  had the same latent bug and gets the same fix.
- Applied to all of it: header fields, the date trigger (drops its 1.5px underline), both
  pickers of a JV row, the amount, the line description, the four input-tax fields. Nothing
  else carries it — `jv-echo` codes and the `—` on the empty side of a leg stay bare, which
  is what makes the wash mean "you can type here".
- **The input-tax panel is two rows again.** Each label and its field are one `.itx-f`
  unit, so a wrap can only fall between fields, never between a label and its box — the
  previous version put TAX ID's box a line below its own label. Widths are sized to content
  (vendor 17rem, tax ID 9rem, profile 11rem, branch 5.5rem) and out-specify
  `.rd-modal .rd-f-input { width: 100% }`, which had been stretching all four to full width.
- **Spacing is three steps and only three**: 0.4rem inside a unit, 0.5rem between units
  (doubled around the `·`), 0.6rem between lines. It was 0.4 / 0.6 / 0.5 — the gap inside a
  unit and the gap between two units were near enough equal that a label read as belonging
  to whichever box was nearest. `.itx-k` also gets `margin-right: -0.07em` to take back the
  trailing letter-space, which had made no two label-to-field gaps measure the same.
- `.itx-line` is `align-items: center`, not `baseline`: baseline aligns the *text* inside
  boxes of different heights and leaves the boxes staggered. `.itx-taxid` drops its 0.8rem
  font-size for the same reason.
