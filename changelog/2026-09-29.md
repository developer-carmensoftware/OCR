`09:41` **Top-up packs: a card per pack with its saving, motion from the system's own
vocabulary, and the fixes a Playwright pass turned up.** *(branch `design/topup-pack-rail`, follows
#268)*

Supersedes #268's compact 4-up cards. The design went through two rejected rounds first: a joined
rail, then a hover highlight that glided under the pointer (off-system, since motion here conveys
state). Both are in the branch history.

- **Frontend: `PackList.tsx` + `styles/pages/pricing.css`.**
  - Each pack is its own card, spaced and lifted like `.plan-card`: 1rem gap, `--radius-lg`,
    `--shadow-card`, and the same pointer-gated hover (−2px, `--shadow-card-hover`, `--border-hi`).
    The whole card is the button and presses to 0.98.
  - No icon. From 561px the card shows centered credits, the price, the per-doc rate, then a
    **Save N%** chip on its own line. The chip is each pack's per-doc saving against the dearest
    pack, derived from the catalog, so a reprice moves it.
  - "Best value" is a solid `--emerald-fill` pill, so it never reads as another save chip.
  - Rows ≤560px.
- **Motion.** Entrance uses the plan grid's own variants, now in `features/billing/motion.ts` and
  shared by both.
  - Revealed on scroll, on a `.pack-cell` wrapper, because framer's inline transform on the card
    itself would override the CSS hover lift.
  - Gated by the page's `useEntrance('pricing')`: first view only, and never with reduced motion.
- **Fixes from the Playwright pass.**
  - **Order amounts show satang.** `฿1,059.3` becomes `฿1,059.30` in the pending-order banner,
    order history, admin order table, workspace list and KPI cards. `formatThb(x, true)`; the
    default stays whole for catalog prices. +1 test.
  - **Save chip on its own line in every language.** It used to wrap only when it didn't fit, which
    left Thai cards a line taller than English at 4-up.
  - **Load errors say it once.** "Failed to load plans: Failed to load plans (500)" becomes "…: HTTP
    500". The Thai message no longer carries an English sentence inside it. Same for order history.
- **Found, not code:**
  - `20260928000000_reprice_pack_micro` was applied to the shared DB from #268's branch before #268
    merged. `supabase db push` from `main` fails with `LegacyDbPushMissingLocalError` until #268 is
    in.
  - That migration didn't set `credit_packs.updated_at`, so the row still reads 2026-09-24. The
    next reprice migration should `set updated_at = now()`.
- **Verified:**
  - build, vitest, lint, prettier, contrast and backend pytest;
  - Playwright against a real session on `#/pricing` (1440/900/800/400, EN/TH, dark, reduced

`14:05` **Credit Card: a JV whose input tax never followed is no longer lost when the session
expires.** *(branch `fix/cc-input-tax-after-session-drop`, from `main`)*

Reported by a user: a JV was posted from the manual wizard, the session expired before step 4, and
the input-tax (ACTX) record was never filed. No Restore prompt appeared, and nothing else in the
app knew. There were three causes:

1. the draft prompt only shows on `#/CreditCardOCR/manual`, but re-entry from Carmen lands on the
   queue;
2. the wizard stayed on step 3 until the success modal was clicked, so a draft restored after the
   session dropped with that modal open was a dead end (duplicate submit, and step 4 unreachable);
3. `credit_cards` recorded only the JV.

- **Frontend: the wizard.**
  - `useOcrSubmission` moves to step 4 the moment Carmen accepts the JV; the modal's button only
    closes it.
  - Restoring a draft that carries a JV id lands on step 4, which also rescues drafts the old
    build saved at step 3. The prompt says "posted as a JV, but its input tax was never recorded"
    instead of "never submitted".
  - Step 4 sends the card id with the ACTX.
- **DB: `20260929000000_credit_cards_input_tax`.** `credit_cards.commis_amt`, `tax_amt` (the two
  sums the ACTX claims, stamped with the JV; header totals, not line items) and `input_tax_at`.
- **Backend.**
  - `proxy_gljv` stores the sums.
  - `proxy_create_input_tax` takes `credit_card_id`: it stamps `input_tax_at` on `Code == 0`, and
    returns 409 when the record is already filed. The card lock is now one `_lock_card` shared with
    gljv.
  - Activity rows carry `input_tax_owed`.
  - New `POST /api/v1/credit-card/activity/{id}/input-tax` (`file_input_tax_for_card`) builds the
    ACTX server-side from the card with the existing `build_input_tax_payload` twin and files it
    under the user's own token.
- **Frontend: the queue.** A posted manual row that owes VAT reads "· input tax not recorded" and
  has a **Record input tax** button in place of Open JV. The button confirms first ("only if nobody
  has keyed it by hand"), then refreshes the table. EN/TH.
- **Not covered:** documents posted before the migration have no stored sums, so they show no note
  and have no button. Those, including the reporter's own, are keyed in Carmen by hand, or restored
  from a draft still in the same browser.
- **Verified:** backend pytest 1428 (+16 new; the tenancy suite needs a DB and was not run), vitest
  832 (+4), tsc, eslint, prettier, ruff.
- **Pending release note (batch with the next release):** "Credit Card: if your session ends
  before you record the input tax, the document now shows 'input tax not recorded' on the Credit
  Card page, with a button to record it."
