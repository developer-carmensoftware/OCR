# 2026-08-28

## Email automation: a `sender_not_allowed` row that names what arrived

`16:10` Reported as "email automation is completely unusable — every mail is skipped even
though the rules are set right". Four documents forwarded to
`dev.carmen4.com / carmencloud` were skipped with `sender_not_allowed`. The gate was
correct; the diagnosis was impossible.

**Root cause was configuration.** `owner_emails` held one address for a mailbox spelled
slightly differently — a single dropped character — and a second forwarding mailbox had
never been registered at all. `sender_allowed` runs *before* `match_rules`, so the
correctly-configured KBANK and BAY rules were never reached, which is why "the rules are
right" and "everything is skipped" were both true at once. (The BU's actual addresses are
deliberately not recorded here; the settings row has them.)

**The defect was legibility.** `email_documents.error_message` said only "No registered
address of this BU appears in From/To/Cc" and never named the addresses the message
carried, `skipped` rows raise no notification by design, and `#/admin/email` offers
nothing to compare against the registered chips. A one-character typo was therefore
indistinguishable from a broken feature — and cost a day.

### Backend

- **`email_imap.people_addresses()`** — the bare addresses in a message's From/To/Cc,
  lowercased and de-duplicated via stdlib `email.utils.getaddresses`. Used only to name
  what a refused message carried.
- **`fetch_unseen` now comma-joins the `people` headers** instead of joining on a space.
  Load-bearing, not cosmetic: `getaddresses` parses an address *list* and returns
  `[("", "")]` for headers run together on whitespace. Harmless to `sender_allowed`,
  which is a lowercase substring match either way.
- **The refusal names the addresses** (`email_ingest_service._run_document`): *"None of
  this BU's registered addresses appear in From/To/Cc — this mail carries `<the addresses
  the message actually had>`"*, capped at five so a forwarded chain's Cc list cannot fill
  the dialog. No frontend change — `#/admin/email` already renders `error_message` in the
  expanded row.
- `test_people_addresses_names_what_a_refused_mail_carried` pins the incident's real
  headers (Thai display name, plus Gmail's `"addr@x" <addr@x>` quoted form). It fails if
  the comma join is reverted. Email suites 141 passed.

Deliberately unchanged: the gate still refuses on a miss rather than warning, is still
checked ahead of `match_rules`, and still reads only From/To/Cc — not the envelope
`Delivered-To`, and not the rules' own `bank_sender_email`. Neither would have caught a
typo, and both quietly weaken an opt-in control.
