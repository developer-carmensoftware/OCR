## Frontend: the page background no longer overflows by the scrollbar (branch `fix/bg-blob-width`)

`14:30` Found by running the JV filter suite in a real (headed) Chrome window: G-07 failed with
`overflow 3` at 375 px, while headless passed.
- **Cause:** `.bg-blob-mid` (the decorative wash on every page) was `width: 100vw`. `vw` counts the
  scrollbar, and headless Chrome has overlay scrollbars that take no width, so no earlier run saw it.
  Now `width: 100%`, which excludes the scrollbar.
- **Impact:** phantom only — `scrollWidth > clientWidth` — because `body { overflow-x: hidden }` clips it;
  nobody could scroll to it. It is what a reflow audit would flag.
- **QA:** `jv_filters_ui.mjs` gains `HEADED=1 SLOWMO=<ms>` (headless stays the default). Whole suite
  headed 67/67 with the fix. A headless run after it overlapped a branch switch in the shared
  worktree and missed V-03 once (66/67); V-03 then passed 3 of 3 alone (same seed). No full
  headless pass on this exact commit yet.
- **Not changed:** `tutorial.css` `.tut { width: 100vw }` (a modal below 62 rem).
- **Tooling trap:** `npx supabase` now fetches CLI 3.x, which rejects the repo's `[inbucket]` section;
  `npx supabase@2.121.0 start` brings the local stack up. A first headed run lost its DB mid-run (the
  containers were gone) and failed 24 cases with 500s — an outage, not a product result.
