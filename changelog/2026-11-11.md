## Frontend: the page background no longer overflows by the scrollbar (branch `fix/bg-blob-width`)

`14:30` Found by running the JV filter suite in a real (headed) Chrome window: G-07 failed with
`overflow 3` at 375 px, while headless passed.
- **Cause:** `.bg-blob-mid` (the decorative wash on every page) was `width: 100vw`. `vw` counts the
  scrollbar, and headless Chrome has overlay scrollbars that take no width, so no earlier run saw it.
  Now `width: 100%`, which excludes the scrollbar.
- **Impact:** phantom only — `scrollWidth > clientWidth` — because `body { overflow-x: hidden }` clips it;
  nobody could scroll to it. It is what a reflow audit would flag.
- **QA:** `jv_filters_ui.mjs` gains `HEADED=1 SLOWMO=<ms>` (headless stays the default). Whole suite
  headed 67/67 with the fix. A headless run after it overlapped a branch switch in the shared
  worktree and missed V-03 once (66/67); V-03 then passed 3 of 3 alone (same seed). No full
  headless pass on this exact commit yet.
- **Not changed:** `tutorial.css` `.tut { width: 100vw }` (a modal below 62 rem).
- **Tooling trap:** `npx supabase` now fetches CLI 3.x, which rejects the repo's `[inbucket]` section;
  `npx supabase@2.121.0 start` brings the local stack up. A first headed run lost its DB mid-run (the
  containers were gone) and failed 24 cases with 500s — an outage, not a product result.


## LLM: the key pool moves past a refused key (branch `fix/llm-pool-dead-key-and-pms-suites`)

`15:33` Found by the QA E2E before the CA-119 handoff (next entry).
- **What QA showed:** OpenRouter calls failed in 0.3–0.6 s with no provider (`outbound_call_logs`,
  status 500 = our label for any exception).
  - At 14:51, three PMS days ran at once. HotelTime's call (key1, 14 s) succeeded; Cloudbeds' and
    Comanche's failed, twice each.
  - At 15:29–15:31 the days were hooked one at a time. Cloudbeds passed, then Comanche and
    HotelTime 2026-10-05 failed even with nothing else in flight.
- **Not proven yet:** the status code. The DB keeps only our label; Render's log line
  `Text LLM call failed: Error code: …` names it.
  - **Leading reading:** the OpenRouter account behind QA's key is nearly out of credit. Its 402
    ("would exceed your available credits given your current in-flight requests") reserves
    prompt + `max_tokens` (16,000 for PMS), so calls pass or fail by what is in flight. This is
    the 11-06 pattern on dev.
- **What this branch fixes (`llm/client.py` `_call_with_pool`):** the pool failed over only on 429,
  so a key refused outright took down every call routed to it.
  - Least-loaded routing sends a call that overlaps another to the second key.
  - That is what happened on dev on 11-06, when the pool held a spent key.
  - Now a 401, 402 or 403 moves the call to the next key at once, and the key stays out of later
    rounds.
  - When every key is refused, the last refusal is raised without backing off.
  - A 400 still fails at once, since every key would refuse it.
  - It covers vision (CC/AP extraction) and text (AI Suggest, PMS).
  - **It does not help a pool whose only key, or every key, is on a dry account.** QA may be that
    case: the fix there is credit, or a funded key in `-xntb`'s `OPENROUTER_API_KEYS`.
- **Checked:**
  - Three new cases in `test_llm_client.py`. The two failover cases fail on main.
  - Live: a pool of [funded key, invalid key] took three overlapping calls. Main passed 2/3, this
    branch 3/3 (twice), logging `key2 refused (HTTP 401); failing over`.
  - Backend CI mirror green: ruff, format, bandit, pytest, coverage 83%.
- **Release note (for the batch):** "AI suggestions no longer go missing when one of several
  OpenRouter keys is out of credit."
