# 2026-07-20

## `16:00` Maintenance mode — global + per-tenant kill switch

Runtime-toggleable maintenance mode so a version update with a breaking migration can take
users offline briefly without shipping raw errors to in-flight wizards. Flag lives in
`system_configs` (no migration — table already existed), so a toggle takes effect in ≤10s
without a restart. Uncommitted / in-progress.

### Backend

- `16:00` **`services/maintenance_service.py` (new).** Reads `maintenance.enabled` /
  `maintenance.message` from `system_configs` + per-tenant overrides from
  `tenant_config_overrides`, cached in-process 10s. Semantics are **OR** (global OR the
  tenant's own override), not the usual override-replaces-global. `is_maintenance()` is
  **fail-open** — a DB read failure returns not-in-maintenance so a config-read outage can't
  brick the whole API.
- `16:00` **`middleware/maintenance.py` (new)** + registered in `factory.py`. Returns 503
  `{code: "maintenance"}` + `Retry-After` + `X-Maintenance: 1` for blocked requests. Allowlist:
  `/api/v1/health` (or Render restart-loops), `/api/v1/admin/*` (admins can toggle it back off),
  `/api/v1/maintenance/status`, docs. Reads tenant from JWT itself → order-independent.
- `16:00` **`GET /api/v1/maintenance/status` (new, public)** — the single source the frontend
  gate polls. **Admin `GET/PUT /admin/maintenance` + `PUT /admin/maintenance/tenant/{id}`**
  added to the existing admin maintenance router (`configs:write` guarded).

### Frontend

- `16:00` **`MaintenanceGate.tsx` (new)** mounted at root in `main.tsx` — full-screen EN/TH wall,
  triggered instantly by the `ocr:maintenance` event any 503 fires (`lib/api/client.ts`),
  confirmed on boot + polled every 30s so it clears itself when the backend returns.
- `16:00` **Admin page `#/admin/maintenance` (new)** — global switch + message + per-tenant
  toggles. 4-point wiring per CLAUDE.md (lazy, AdminRouter, NavItem, i18n en+th).

### Infra

- `16:00` **`deploy.yml`** — opt-in maintenance via `workflow_dispatch` input. Plain push
  deploys stay zero-downtime; a manual run with `maintenance=true` raises the flag (psql) before
  `db push` and lowers it after health passes (`always()`, so a failed deploy never sticks ON).

## `17:30` Maintenance mode — scheduled window (add-on)

Admin can now schedule a maintenance window ahead of time instead of flipping the switch at 2am.
Same `system_configs` store, still no migration.

### Backend

- `17:30` **`maintenance_service.py`** — new `maintenance.window_start/window_end` (UTC ISO).
  `is_maintenance` now computes `enabled OR (start <= now < end)` against the **live clock**, so the
  window auto-activates at start and auto-reopens at end with **no cron** (reuses the 10s cache).
  `set_schedule()` + `end_now()` (clears switch + window — covers "finished early" and "cancel").
  `get_status()` gained `active` (effective) + window fields.
- `17:30` **Endpoints** — `PUT /admin/maintenance/schedule` (validates `end > start`, 400 otherwise),
  `POST /admin/maintenance/end`; public `GET /maintenance/status` now returns `window_start/end` for
  the user-facing banner.

### Frontend

- `17:30` **`MaintenanceGate.tsx`** — advance-notice **banner + countdown** ("Scheduled maintenance
  … · in 2h 5m", dismissible per-window via localStorage) when a future window exists; overlay gained
  an "expected back by HH:MM" line. All times rendered in ICT.
- `17:30` **`MaintenancePage.tsx`** — Scheduled-window section: native `datetime-local` start/end +
  message, Save schedule + **End now**; effective status badge (Active / Scheduled / Off). EN/TH keys added.

### Tests

- `17:30` `test_maintenance_service.py` — added window cases (future/current/past) + `end_now`; 6 passed.

### Fixes

## `20:55` Maintenance — review remediation

Detail pass before merge; found and fixed one real bug plus tech-debt.

- `20:55` **Bug fix (P0): per-tenant maintenance reload loop.** `MaintenanceGate.probe()` hit
  `/maintenance/status` without the auth token, so the poll only ever saw the *global* flag. For a
  tenant-scoped block, the 503 event raised the wall but the tokenless poll read `active:false` and
  fired `location.reload()` every 30s. Probe now sends the bearer token → status is tenant-aware,
  boot-detects per-tenant maintenance, and recovers without looping. Verified via ASGI: a tenant JWT
  returns `active:true`, no token returns `active:false`.
- `20:55` **Hardening: fail-open covers the whole compute.** Moved the active computation inside
  `is_maintenance`'s try/except so any error (not just the cache refresh) fails open instead of 500ing.
- `20:55` **Dead-code removal.** Dropped the caller-less manual on/off cluster after the always-bounded
  redesign: `setGlobalMaintenance` (FE), `PUT /admin/maintenance` + `set_global` + `GlobalMaintenanceRequest`
  (BE). The `maintenance.enabled` read path stays (deploy.yml writes it via psql). Unit suite green.
