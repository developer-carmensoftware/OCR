## Config: `OPENROUTER_API_KEYS` alone counts as a configured key (branch `fix/openrouter-key-pool-guard`)

`OPENROUTER_API_KEYS` pool set, six checks that ask "is a key set?" still read `OPENROUTER_API_KEY`.

      AI (`credit_card_ocr/suggest`) and shows suggestions. No page errors.

## Frontend: a CI-only flake in the PMS review dialog's account picker (branch `fix/search-select-pending-effect`)

`14:56` PR #345's CI failed twice, a different test each time. First was `PmsReviewDocument.test`,
"picking another account drops the AI tag; Undo puts the AI's back", with no option `4010001`.
The rerun failed `QueueRow.test`, "files a later month of the claim window when one is picked",
with no `10/2026`. The same code had passed on main and on #347. Both pickers are
`CustomSearchSelect`.
- **Cause:** `CustomSearchSelect` copied its value into the search box in a passive effect. On a
  slow runner that effect could still be pending when the test clicked the field. It then ran
  first in the click's render and replaced the click's empty search with the value, so the list
  opened filtered to the AI's one code.
- **Fix** ([`7afda98b`](../../commit/7afda98b)): a layout effect, so the search box holds the value
  before anything can be clicked. This follows the #316 precedent.
- **Proof:** with React's scheduler slowed by a throwaway setup file, main's code failed both
  tests from 30 to 60 ms with CI's exact errors. With the fix both pass at 30, 60 and 120 ms, and
  the review dialog's passes up to 250 ms. Lint, format, type-check, 1103 tests and the build pass.
