## Security hardening, round 2 — PR 1: web and database surface (branch `feat/security-headers-rls`, not merged)

`10:07` Decision-log #50. Admin MFA is deferred by the user; everything else from the 10-29
audit is planned in three PRs. This is the first.

- **Frontend headers** (`frontend/vercel.json`):
  - **enforced now:** `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`,
    HSTS. Carmen opens us by link, never in a frame;
  - **CSP in `Report-Only`:** the inline theme script is allowed by its sha256. It is enforced in
    a later PR, after one QA round, since the slip viewer's presigned host is still unknown;
  - `src/test/securityHeaders.test.ts` fails if the inline script changes without its hash.
- **API docs:** `/docs`, `/redoc` and `/openapi.json` now only appear where
  **`EXPOSE_API_DOCS=true`**. Off by default, so prod publishes no API map.
- **DB (migration `20261030000000`):**
  - RLS enabled + forced on every public table that lacked it: 14 on dev, among them
    `email_documents`, `email_ingest_settings` and `consent_logs`;
  - `anon`/`authenticated` lose every privilege in `public`, default privileges included. A fresh
    `db reset` used to hand them **1078** table privileges; now it hands 0.
- **CI guard:** `supabase/tests/database/security.test.sql` (pgTAP) runs as `supabase test db` in
  the Migrations job. It fails on a table without RLS or a grant to the Data API roles.
- **Tests:**
  - backend `TestApiDocsExposure` (off → 404, on → 200);
  - frontend 1092 pass, `tsc -b` clean;
  - pgTAP 2/2 on local Supabase. Red check: RLS off on one table plus a grant to `anon` → both
    fail.
- **E2E `scripts/qa/security_headers_ui.mjs` 7/7.** Setup: built app + `vite preview` serving
  `vercel.json`'s headers + branch backend on dev.
  - 18 screens (customer and admin) with **0 CSP reports**, and the listener proven to hear one;
  - the app refuses to render in a frame.
  - ⚠️ The first run started 4 real extractions on BU carmen (dev) by choosing files. 2 credits
