### `04:10` — Frontend: ticket 0 — the credit-card mapping screen speaks Thai

Prerequisite for the `cc_ar_reconcile` collapse (see the planning note below). The four
components behind `#/CreditCardOCR/mapping` carried **zero** `useT` calls — every label,
tooltip, placeholder and status line was hardcoded English — while the AR settings screen
they are about to merge with is fully bilingual. Translating after the merge would have
meant resolving the same conflicts twice.

- `i18n/dict.ts` — 71 new `cc.*` keys in both `en` and `th`: top-level config
  (`cc.cfg*`), company information (`cc.company*`), the account-code mapping table
  (`cc.map*`), the payment-type modal (`cc.pt*`), and the save-validation modals
  (`cc.val*`, `cc.saveSuccess*`). Every English string is unchanged in wording, so this is
  invisible to an EN reader.
- `components/common/MappingRow.tsx`'s `deptPlaceholder` / `accPlaceholder` **defaults**
  (`'Dept...'` / `'Acc...'`) were reaching the screen untranslated — `PaymentTypeModal` is
  the one caller that never passed them. Found by the browser pass, not by any test. Fixed
  at the caller (`cc.ptDeptPh` / `cc.ptAccPh`, deliberately short so the modal's narrow
  columns still fit) rather than by making the shared component a `useT` consumer.
- `PaymentTypeModal` had two callbacks using `t` as the payment-type parameter name,
  shadowing the `t` from `useT()`. Harmless today — neither calls `t()` — but the next edit
  that does would get "t is not a function" at runtime with nothing failing first. Renamed
  to `pt`.
- `components/credit-card/TopLevelConfigSection.tsx`, `CompanyInfoSection.tsx`,
  `MainMappingTable.tsx`, `PaymentTypeModal.tsx` — literals swapped for `t()`. The
  description-hint ternary in `TopLevelConfigSection` collapses from four branches to three
  (`ownDescription` truthy and both-falsy produced the same sentence); behaviour identical.
- `hooks/mapping/useMapping.ts` — `COMPANY_REQUIRED_FIELDS.label` → `labelKey: TKey`,
  because the same list names the fields in the form *and* names them again in the "fill
  these in" modal, so one translated string has to reach both. `topLevelRequired` likewise.
  Both validation modals and the save-success modal now go through `t()`.
- `lib/glFieldLabels.ts` — `glFieldLabel(key)` → `glFieldLabel(key, t)`, same for
  `glFieldList`. Three new keys (`cc.glCommission` / `cc.glTax` / `cc.glNet`) hold the
  wording. Passing `t` in rather than duplicating the list into the `cc.*` namespace is
  what keeps this the only copy — which is the whole reason the file exists. Callers
  updated: `MainMappingTable`, `QueueRow` (×2), `useMapping`. Note `QueueRow`'s
  `reason.fields.map(glFieldLabel)` had to become an arrow — point-free would have passed
  the array index as `t`.
- **No new test.** `i18n/dict.test.ts` already gates EN/TH key parity, non-empty values,
  and — the one that matters here — that both languages use the same `{placeholder}` set
  per key. `tsc` fails the build on a missing TH key independently.

Verified: `npx tsc --noEmit` clean, `npm run build` succeeds, `npm run test` 64 files /
761 tests pass (including `ccJv.contract.test.ts` and `PaymentTypeModal.test.tsx`),
`eslint src` 0 errors (6 pre-existing warnings in `JvEditor.tsx` / `useAPInvoice.ts`,
untouched), prettier clean.

Browser pass (Playwright MCP against the dev servers, session via
`scripts/seed_browser_session.py`, revoked after):

- **EN is byte-identical to before** on the page and in the save-validation modal
  (`"Please fill in File Prefix, Tax ID before saving"`) — the regression that mattered.
- TH renders across the page shell, the company block, the mapping table, the payment-type
  modal and its 15 additional rows. Interpolation checked live: `"ใช้กับเอกสารของ BAY"`,
  `"(จับคู่แล้ว 15/15)"`.
- The `labelKey` refactor verified at both ends from one list — the same field shows as
  `เลขประจำตัวผู้เสียภาษี` on the red required label *and* inside the modal sentence
  (`"กรุณากรอก รหัสสมุดรายวัน (Prefix), เลขประจำตัวผู้เสียภาษี ก่อนบันทึก"`).
- Thai layout holds: no overflow or clipping in the label column despite the longer strings.

**Known gap, not fixed here:** `review.jvDeptPlaceholder` / `review.jvAccountPlaceholder`
are `'Department'` / `'Account'` in *both* `en` and `th` — a pre-existing untranslated pair
on the AR settings screen, which the next ticket rewrites anyway.

Responsive pass (Playwright, 375 / 520 / 640 / 768 / 1440, both languages). **Thai never
renders worse than English at any width** — at the 520px threshold EN clips 5 elements
(worst 57px over) while TH clips 1 (3px over), because the Thai labels are the shorter
ones (`รหัสแผนก` vs `Department Code`). ≥640px both languages are clean in both.

That measurement exists to attribute a defect the pass also found, which is **pre-existing
and not caused by this ticket**: below ~520px the two form sections are clipped and
unreachable. `pages/mapping.css` contains **zero** `@media` rules, `.form-grid` is a hard
`grid-template-columns: 200px 1fr`, and `.container` is `overflow-x: hidden` — so in a
224px content box the value column gets ~8px and what spills is cut off with nothing to
scroll. Inputs render ~40px wide and helper text wraps one word per line.

Two things that are *not* broken and were checked specifically: the account-code mapping
table sits in `.table-wrapper` (`overflow-x: auto`) and scrolls horizontally, and
`PaymentTypeModal` shrinks to 333px at a 370px viewport with its body scrolling — both
degrade correctly. Only `.form-grid` has no fallback. The page-level 3px horizontal
overflow present at every width is the decorative `.bg-blob-mid`.

### `04:45` — Frontend: make the mapping screen usable below 640px

Fixing the defect the responsive pass above found, rather than carrying it into the next
ticket. Reusing `ar-reconcile.css`'s existing 768 / 640 breakpoints so the shell this page
moves onto next does not introduce a third number.

- `styles/pages/mapping.css` — new "Narrow screens" block. **≤768px**: `body` padding
  3rem/2rem → 1.5rem/1rem and `.container` 2.5rem → 1.75rem/1.25rem. That is the larger
  half of the fix on its own — 144px of a 375px phone was page chrome before a field
  started. **≤640px**: padding tightens again, `.form-grid` drops to a single column with
  the label above its own field (the row gap becomes label-to-field, and the gap between
  pairs comes from the label's `margin-top`), plus smaller `h1` and `.section` rhythm.
- `styles/components.css` — `.cc-mapping-grid-container` at ≤640px narrows the type column
  70px → 56px and the label minimum 210px → 120px. The grid still overflows and still
  scrolls inside `.table-wrapper`, but the Dept column now starts inside the viewport
  instead of past it: before, a phone showed a label and blank space with nothing to say
  the row scrolled at all.

Measured before → after at 375px (TH and EN both): content clipped with **no scrollable
ancestor to reveal it** goes from 9–10 elements to **0**, and the File Prefix input from
~40px wide to **312px**. At 640px the mapping grid now fits outright (0 overflow, down
from 27px). **Desktop is untouched** — at 1440px `.container` is still `padding: 40px` /
`width: 960px` and `.form-grid` still computes `200px 662px`, identical to before.

`PaymentTypeModal` was already correct and still is (333px dialog at a 370px viewport,
body scrolling on X, footer buttons reachable) — the fix is scoped to the page, not the
portal.

Verified: `tsc` clean, build succeeds, 64 files / 761 tests pass, `eslint src` 0 errors,
`npm run styles` "every class resolves to a reachable sheet", `npm run contrast` all token
pairs meet their floor.

**Known cosmetic leftover:** `MappingSkeleton` in `pages/Mapping.tsx` is inline-styled with
three-column grids, so for the moment before data lands a phone shows a 3-up shimmer ahead
of a 1-up form. Not worth restructuring inline styles for a sub-second loading state that
Ticket 1 replaces with the `Card` shell's own skeleton.

### `06:25` — Frontend: stop asking a phone to swipe sideways to fill in a field

The `04:45` pass fixed the form but left the actual defect standing: the account-code
mapping grid and the payment-type rows are forms people fill in, and they still made a
phone user scroll horizontally to reach the Account field. Scaling padding was the trap
`/impeccable adapt` names outright — *"rethinking the experience for the new context, not
scaling pixels"*. This pass replaces the grid/modal half of `04:45` with the project's own
answer to the same question: `review-queue.css` already turns `.rq-table` into cards at
720px (`thead{display:none}`, `td::before{content:attr(data-label)}`) because a queue row
is a record, while `.jv-table` keeps its columns and scrolls because a JV is a ledger where
alignment is the information. A mapping row is the first kind — nobody reads a dept code
down a column, they fill one row at a time — so it goes to cards, not to a wider scrollbar.
Consolidates the `04:45` pair of breakpoints (768/640) into this one 720px number; three
sizes on one page was the smell.

- `components/common/MappingRow.tsx` + `styles/components/mapping-row.css` — the two
  `CustomSearchSelect`s are now wrapped in `<div className="pm-cell" data-label={…}>`. Above
  720px the wrapper is `display: contents` and generates no box at all, so
  `--pm-cols: minmax(120px, 1fr) 1fr 1fr 4.75rem` — declared once, read by the header and
  every row — is untouched. Below it `--pm-cols` redefines to `1fr`, the header hides, and
  `.pm-cell::before` supplies the label a vanished placeholder no longer can (a picked value
  overwrites its own placeholder; the label has to sit outside the input). New `deptLabel` /
  `accLabel` props, both callers (`PaymentTypeModal`, `ARMappingTable`) updated.
- `components/credit-card/MainMappingTable.tsx` + `styles/components.css` — this table had
  no per-row wrapper at all (five cells as flat children of one grid via `React.Fragment`),
  so there was nothing to turn into a card. Added `.cc-mapping-head` and `.cc-mapping-row`
  wrappers, `display: contents` above 720px for the same untouched-desktop guarantee. Below
  it: the two `.mapping-header` cells hide (headings for columns that no longer exist),
  `.cc-grid-span-3` resets to `grid-column: auto`, rows separate with a top border rather
  than becoming boxes (`.container` is already a card and nested cards are banned), and
  `.cc-section-title-container` gets `flex-wrap` — without it the heading was crushed
  against `AISuggestBar` into a mid-word break, same fix `ar-reconcile.css` already makes to
  its own card header.
- **Bug found by the browser pass, not by the plan:** `styles/components/payment-modal.css`
  had `.pm-inner { min-width: 700px }`, added when the modal's grid needed protecting from
  squeezing on a narrow desktop. Once rows stack into records at 720px, that floor does the
  opposite — it forces `.pm-body` to scroll horizontally past a layout with no columns left
  to protect, so every stacked row still measured ~700px wide inside a 333px dialog and
  overflowed regardless of the grid fix above it. Reset to `min-width: 0` in the same media
  query.
- Tap targets moved to `@media (pointer: coarse)` — `.pm-accept-btn` / `.pm-reject-btn` /
  `.pm-remove-btn`, `.cc-btn-accept` / `.cc-btn-reject`, `.btn-save-mapping`, and the payment
  modal's footer buttons all get `min-height: 44px`. A width proxy was the wrong test: a
  touch laptop needs the floor at 1440px too. Four other files (`review-queue.css`,
  `usage-indicator.css`, `admin-credit-orders.css`) already key off the pointer this way;
  `DESIGN.md`'s `max-width: 768px` line is the minority practice this leaves behind.
- Fixed at the component level on purpose: `MappingRow` and the mapping table pattern are
  shared with `#/CreditCardOCR/ar-settings`'s `ARMappingTable`, so that screen gets the same
  treatment for free — verified live, not assumed.

Measured at 375px, both languages: **0 elements clipped with no scrollable ancestor to
reveal them** (down from the grid still showing 1 at the end of `04:45`), every dept/account
field's right edge inside the viewport, and the payment-type modal's stacked rows fit its
333px dialog with labels (`"Department Code"` / `"รหัสแผนก"` etc.) surviving the
`display: contents` round trip. Swept 375 / 520 / 640 / 720 (boundary, both sides) / 768 —
clean throughout. **Desktop regression gate:** at 1440px `.container` still computes
`padding: 40px` / `width: 960px`, `.form-grid` still `200px 662px`, and
`.cc-mapping-grid-container` still `70px 210px 283px 283px 0px` — byte-identical to before
any of this started.

Verified: `tsc` clean, build succeeds, 64 files / 761 tests pass, `eslint src` 0 errors,
`npm run styles` "every class resolves to a reachable sheet", `npm run contrast` all pairs
meet their floor, prettier clean.

**Found, not fixed — out of scope for this ticket:** `ARJvPreview`'s `.ar-preview-table`
(the "JV preview" ledger on the AR settings rail) is a genuine `.jv-table`-shaped table —
DEPT/ACCOUNT/COMMENT/DEBIT/CREDIT columns that need to line up to be checked — but
`ar-reconcile.css` never gave it `.jv-table`'s `min-width: 720px` floor. Below its rail's

Pre-existing (this session touched neither the component nor that stylesheet); worth a line

### `04:10` — Planning: collapse `cc_ar_reconcile` into the credit-card flow

Decision #28 (2026-09-18) made the settlement JV's debit side identical to the fee
invoice's, which leaves the two builders differing in exactly two places — where the debit
figures are read from (`total_row` vs Σ across details, a *document-layout* fact) and how
the credit side is grouped (a *user option*). The second module, second mapping store and
second settings screen are all v1.1 artefacts of a premise that no longer holds.

Agreed shape, to be built as one atomic PR after the ticket above merges: one builder in
`cc_jv` (`ar_reconcile_jv.py` deleted, browser twin still covering only the fee-invoice
branch), `ar_reconcile_mappings` folded into `bu_accounting_mapping_entries` with a new
nullable `source` column, `banks.settlement_grouping` replacing the `SUPPORTED_BANKS` /
`RECONCILABLE_BANKS` constants, the module gate dropped (`module_id` kept so
`daily_usage_summary` still splits the cost), and `#/CreditCardOCR/ar-settings` merged into
`#/CreditCardOCR/mapping`. Detail/Summary becomes a per-bank posting option rather than a
module of its own. Full decision list in the plan file; decision-log entry #29 to be
written with the implementation.

### `08:20` — Ticket B: collapse `cc_ar_reconcile` into the credit-card flow

Implements the plan above and decision-log #29. One PR, backend and frontend together,
because a partial cutover leaves the frontend calling API shapes the backend no longer
serves. Migration is written and tested against but **not applied** — `supabase db push`
is a separate, explicit step.

**Backend**

- `services/cc_jv.py` — `build_jv_rows` gained two optional keyword arguments,
  `total_row=None` and `grouping=None`, whose defaults reproduce the fee-invoice path
  exactly. `unmapped_payment_types` took the same `grouping=` kwarg. `group_key`,
  `is_balanced`, `BALANCE_EPSILON`, `render_jv_description` moved in from the deleted
  `ar_reconcile_jv.py`. Every leg dict now always carries a `"key"` field (empty string

  this and was not touched.

  `contracts/cc-jv.contract.json` with zero edits to either the tests or the contract —
  the fee-invoice branch did not move, only the settlement branch joined it. ~18

- `services/ar_reconcile_jv.py` and `tests/unit/test_ar_reconcile_jv.py` — deleted.

- `services/email_ingest_service.py` — settlement documents now gate on
  `Module.CREDIT_CARD_OCR` while still writing `module_id=Module.CC_AR_RECONCILE` to

  `build_jv_rows(..., grouping=partial(group_key, post_type=ar_setting.post_type))`; the
  `_ar_mappings` helper (a second DB round-trip for settlement mappings) deleted —
  `config.mappings` from `get_accounting_config` covers it.
- `supabase/migrations/20260922000000_collapse_ar_reconcile.sql` — adds the two nullable
  columns above (KBANK seeded to `settlement_grouping='first_token'`); backfills
  `bu_accounting_mapping_entries` from `ar_reconcile_mappings` with
  `ON CONFLICT (config_id, field_type) WHERE deleted_at IS NULL DO NOTHING` (a code mapped
