`00:30` **Account Mapping page: audit and fixes** *(uncommitted, on `feat/detailed-cc-ar-reconciliation`)*

Full read of `#/CreditCardOCR/mapping` (page, 7 hooks, 7 components, API, backend). Existing hook tests were
green but nothing covered the page as a whole or any failure path; every defect below lived in that gap.

- **JV built from the wrong bank's rules (High, multi-bank BUs).** `useAccountingConfig()` read unscoped, which the
  server answers with whichever bank the mapping page saved last. Review queue and the manual wizard built (and
  approve posted) their JV from that. Now `useAccountingConfig(bankCode)`; `loading` holds until that bank's rules
  land; the offline localStorage copy is not used for a named bank. `ReviewQueue` passes the row's bank as `bankHint`
  so the rules load beside the document. *Behaviour change:* a bank the BU never mapped now shows blank accounts and
  cannot be approved, matching what auto-post already did (`mapping_missing`).
- **Save failed silently (High).** A failed `PUT /config/accounting` was swallowed, then the settlement grouping was
  saved and the tab closed as if it worked. Now: error modal with the server's reason, no AR PUT, page stays,
  localStorage / `accounting_config_updated` written only after success. Success is a toast.
- **Unsaved edits lost on bank switch / tab close.** Confirm dialog before a switch that drops rules; `beforeunload`
  while anything is unsaved (not while saving).
- **Company Name / Tax ID / Address** are read-only (they were overwritten from `BANK_INFO` and reached no reader).
  **Branch No** must be 5 digits, checked in the form and at `AccountingConfigRequest` (422 otherwise).
- **Try again** after a failed bank load now re-requests the settlement settings (a rejected promise was reused).
- Settlement preview debounced 300 ms (was one request per keystroke).
- AI Suggest: failures / "nothing to suggest" / "all mapped" are toasts (were console-only or a modal over the dialog).
- i18n: bank kind labels, prefix placeholder, "All options", "No results found", AI toasts (en + th).
- Keyboard: payment dialog traps Tab and returns focus to its opener. `CustomSearchSelect` (shared): ArrowUp/Down,
  Enter, Esc on an option no longer cancels the surrounding dialog, Tab closes the list, options out of the Tab order.
- **Found in the browser:** the picker closed on the first frame of the app's smooth scroll (open 15 ms, gone 32 ms),
  so a field below the fold could never be opened by focus. The list now follows its field instead of closing on scroll.
- **Tests:** vitest 989 (+60), new `Mapping.test.tsx` (page level), `AccountingReview.test.tsx`,
  `CustomSearchSelect.test.tsx`; pytest 1647 passed / 88 skipped; tsc, eslint, prettier, ruff clean.
- **Playwright, dev BU `carmen`, every write intercepted, AI canned:** load, bank switch (skeleton, Save off, parallel
  requests), failed load + Try again, description typing (1 preview request), read-only company fields, branch
  `0000` blocked, Detail/Summary, keyboard picking, payment dialog (Tab trap, Esc, search, filter, bulk apply, Done gate,
  Cancel, AI suggest/accept/dismiss/accept-all, add, remove + Undo), save payload, 500 and 400 failure modals, dirty guard.
  **Not re-driven:** 390 px / Thai pass and the review-queue request check (dev server stopped); both covered by tests.

  legacy `bank_code IS NULL` entries can't be cleared from this page (needs a migration); bulk-applying only an

`11:00` **Account Mapping: the known risks closed** *(`b8a26a59`, `26ba3366`, `4676e061`, `de9dccd1` on `feat/detailed-cc-ar-reconciliation`)*

- **Bulk account** written without a department is applied only to rows whose own department allows it; the rest are
  skipped with a toast (`cc.pmBulkSkipped`). Was: those rows turned red and only Done stopped them.
- **Picker in a scrolling box:** closes when the field leaves the box (the payment dialog's body); document scroll still
  follows the field (the smooth-scroll fix of this morning).
- **Lost update:** `GET /config/accounting` returns `version` (newest `updated_at` of the config row and the bank's
  entries); `PUT` takes `base_version` and answers 409 when the server is newer. The page asks: **Reload latest**, or
  **Keep editing** and press Save again to overwrite (that save sends no version). `bank_descriptions` is now merged per
  bank on the server and the page sends only the selected bank's. A tab with no version is accepted as before. After a
  save that leaves the page open (settlement grouping failed) the new version is kept and nothing counts as unsaved.
- **Bank-less entries retired:** migration `20261001000000_retire_null_bank_entries.sql` copies each bank-less entry to
  every bank its BU has documents for (or the config's bank) lacking its own, then soft-deletes them; the read no
  longer borrows them. Dry run (`queries.sql` item 30) on dev: carmencloud 29 × 6 banks (BAY, GHL, KBANK, KTC, PAYPAL,
  SCB) = 174 rows, nothing left alone. The SQL was EXPLAINed only — **not applied**.
  - **Deploy order: push the migration BEFORE this code**, or every bank of such a BU reads empty and documents park
    `mapping_missing`. Afterwards `select count(*) from bu_accounting_mapping_entries where bank_code is null and
    deleted_at is null` should be 0. (Opposite of #33.)
- **Tests:** vitest 998, pytest 1652 (88 skipped), tsc/eslint/prettier/ruff clean. The tenancy test
  `test_mapping_legacy_fallback.py` is rewritten but not run (it writes to the dev DB; `TENANCY_DB_TESTS=1`).
