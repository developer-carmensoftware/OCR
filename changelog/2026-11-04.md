## PMS hook: log why a key is refused (branch `fix/pms-key-refused-reason`)

`14:40` Every hook Carmen has sent has been answered `401`: about 10 calls between 10-20 and 10-28.
The live key has never been used, and we could not say why: `authenticate()` returns nothing on
purpose, and nothing was logged.

- **Backend** (`api_keys.why_refused`, called by `routers/pms.py`): a refusal now logs
  `PMS key refused: <reason>` on our side only. The same text goes on that 401's
  `performance_logs.resource_id`, so SQL reads it without the Render log. The reason is one of:
  no key, a JWT, a `cpk_` key with N chars before it, not a `cpk_` key (N chars), unknown key,
  revoked key `<prefix>`, or BU inactive. The key itself is never logged, and the caller still
  gets the same `401 Invalid API key`.
- **Not done:** returning `"Bearer cpk_…"` from `POST /keys`.
  - We already take the bare key, so a missing prefix cannot cause a 401.
  - If Carmen adds `Bearer ` itself, the header becomes `Bearer Bearer cpk_…` and fails.
  - `api_key` is the contract already sent to Carmen.
- **Tests:** a parametrised test covers each reason, and none of them repeats the key.
  The live run on local Supabase sent 9 bad header forms: each got the same 401 and logged its
  own reason, with no key text in the log. The live key got 202.
  `15:30` A re-run checked the reason lands on the 401's `performance_logs` row, and no key text
  is stored.
- **Docs:** `pms-interface/05-operations.md`, the 401 runbook row now reads the stored reason.
