# 1. บทนำ

## 1.1 วัตถุประสงค์

พนักงานบัญชีของโรงแรมได้รับใบแจ้งค่าธรรมเนียมบัตรเครดิตจากธนาคารทุกเดือน และต้องคีย์รายการทีละบรรทัดเข้าสมุดรายวันของ Carmen ERP ซึ่งใช้เวลาและเกิดข้อผิดพลาดจากการพิมพ์ ระบบนี้อ่านเอกสารด้วย AI ให้ผู้ใช้ตรวจแก้ จับคู่ผังบัญชี แล้วสร้าง JV ใน Carmen ให้ งานของผู้ใช้จึงเหลือแค่ตรวจทานและกดยืนยัน

เอกสารนี้ระบุสิ่งที่ระบบต้องทำ วิธีทำและรายละเอียดหน้าจอ ตาราง และ API อยู่ใน FRD-01 ซึ่งเป็นเอกสารออกแบบ (Software Design) ของงานนี้

## 1.2 ผู้ใช้และบริบท

- **ผู้ใช้:** พนักงานบัญชีของ BU ที่ใช้ Carmen ERP เข้าระบบผ่านเมนู AI JV Automation ของ Carmen (Carmen SSO)
- **จุดเข้า:** หน้าคิว `#/CreditCardOCR` มีปุ่ม Scan manually พาเข้า wizard และปุ่ม Mapping Settings
- **ค่าใช้จ่าย:** 1 document credit ต่อ 1 ไฟล์ จากแพ็กเกจของ BU (RS-05)

## 1.3 ขอบเขต

| ทำ | ไม่ทำ (ผู้ใช้ทำเอง หรืออยู่ในงานอื่น) |
|---|---|
| อ่าน statement ค่าธรรมเนียมของ BBL, KBANK, SCB | ใบแจ้งของ payment gateway และ BAY — RS-04 |
| แนะนำผังบัญชีด้วย AI และจำ mapping แยกตามธนาคาร | แก้ JV ที่ post แล้ว — ต้อง reverse ใน Carmen |
| ตรวจความสมดุลของ JV และกันเอกสารซ้ำ | เก็บไฟล์ต้นฉบับ — ผู้ใช้เก็บเองตามระเบียบบัญชี |
| สร้าง JV ใน Carmen | ยื่นภาษีซื้อ — RS-03 |
| เรียนรู้จากค่าที่ผู้ใช้แก้ | อ่านเอกสารที่มาทางอีเมล — RS-06 |

| BANK-F07 | ระบบต้องเก็บ GL mapping และข้อความ Description ของ JV แยกตามธนาคาร การบันทึกของธนาคารหนึ่งต้องไม่เปลี่ยน mapping ของธนาคารอื่น | ทดสอบ | §2.1, §4.4 |

| BANK-F10 | ระบบต้องสร้าง JV ใน Carmen ด้วย JV source ของธนาคาร และถือว่าสำเร็จเฉพาะเมื่อ Carmen ตอบ `Code: 0` ถ้าเป็นค่าอื่น ต้องไม่บันทึกว่าส่งแล้ว และผู้ใช้ส่งใหม่ได้ | ทดสอบ | §5, §8.4 Gate 11 |
| BANK-F11 | ระบบต้องส่งภาษีซื้อแยกจาก JV และ JV ที่สำเร็จแล้วต้องไม่ถูกย้อนกลับเมื่อการส่งภาษีซื้อล้มเหลว | ทดสอบ | §9 EC-19, RS-03 |
| BANK-F12 | ระบบต้องเก็บงานที่ยังไม่ส่งไว้ในเครื่องของผู้ใช้ และเสนอให้กู้คืนครั้งเดียวเมื่อเปิดหน้าจอใหม่ โดยไม่กู้อัตโนมัติ | ทดสอบ | §2.1, §5 |
| BANK-F13 | ระบบต้องแสดงการสแกนที่หักเครดิตแล้วแต่ยังไม่ได้ post ในคิวเป็น Not posted | ทดสอบ | §2.1, RS-08 |
