# 1. บทนำ

## 1.1 วัตถุประสงค์

โรงแรมที่รับชำระผ่าน payment gateway ได้รับใบแจ้งค่าธรรมเนียมจากผู้ให้บริการรายเดือน เอกสารประเภทนี้ไม่มีตารางแยกตามประเภทบัตรเหมือน statement ของธนาคาร แต่เป็นรายการค่าธรรมเนียม และพิมพ์ VAT เพียงครั้งเดียวที่ท้ายใบ Change Request นี้ขยาย RS-01 ให้อ่านใบแจ้งค่าธรรมเนียมของ KTC, GHL, PayPal, SiamPay และ statement ของ BAY แล้วสร้าง JV ด้วยกลไกเดิม

รายละเอียดการออกแบบอยู่ใน FRD-10 ซึ่งเป็นเอกสารออกแบบ (Software Design) ของงานนี้

## 1.2 ขอบเขต

| ทำ | ไม่ทำ |
|---|---|
| อ่านใบแจ้งค่าธรรมเนียม 4 ราย และ statement BAY | ใบลดหนี้ / คืนเงิน — แสดงตามที่อ่านพร้อมคำเตือน ผู้ตรวจแก้เอง |
| กระจาย VAT ท้ายใบไปยังรายการ และตรวจกับยอดรวม | กระทบยอดเงินที่ gateway โอนเข้าบัญชี |
| ชื่อรายการคงที่ทุกเดือนเพื่อให้ mapping ใช้ต่อได้ | สกุลเงินต่างประเทศ — JV เป็น THB เสมอ |
| JV source ต่อผู้ออก | แยก VAT ตามอัตราในใบที่มีหลายอัตรา |

| PG-F04 | ระบบต้องกระจาย VAT ที่พิมพ์ท้ายใบไปยังแต่ละรายการตามสัดส่วนค่าธรรมเนียม โดย VAT รวมของรายการเท่ากับ VAT ท้ายใบพอดี ไม่คำนวณจากอัตราที่สมมติ | ทดสอบ | §1, §10.1 |
| PG-F05 | ระบบต้องตรวจ Σ ค่าธรรมเนียม + VAT กับยอดรวมที่พิมพ์ และเตือนผู้ตรวจพร้อมผลต่างเมื่อไม่ตรง | ทดสอบ | §1, F-03 |
| PG-F06 | เมื่อไม่มีท้ายใบ ระบบต้องถือตัวเลขรายการเป็นค่าธรรมเนียมก่อน VAT ที่อัตรา 7% และแสดงคำเตือนว่าใช้อัตราสมมติ | ทดสอบ | F-03 |
| PG-F07 | ระบบต้องตัดวันที่และบรรทัดที่สองออกจากชื่อรายการ ให้ชื่อเหมือนเดิมทุกเดือน | ทดสอบ | §1, F-05 |
| PG-F08 | ระบบต้องอ่านวันที่ชื่อเดือนไทย (เต็มและย่อ) ปี พ.ศ. และ DD/MM/YY ปี ค.ศ. 2 หลัก | ทดสอบ | F-06 |
| PG-F09 | คำแนะนำบัญชีฝั่ง payment type ของกลุ่ม gateway ต้องเป็นลูกหนี้จากผู้ให้บริการ (settlement receivable) ไม่ใช่บัญชีเงินฝาก | ทดสอบ | F-07 |
| PG-F10 | JV ของผู้ออกเหล่านี้ต้องใช้ JV source ของผู้ออก (`AICCKTC`, `AICCGHL`, `AICCPAYPAL`, `AICCSPAY`, `AICCBAY`) | ทดสอบ | F-08 |
