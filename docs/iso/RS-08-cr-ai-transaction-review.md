# 1. บทนำ

## 1.1 วัตถุประสงค์

Email Automation รุ่นแรก post JV เข้า Carmen โดยไม่มีใครตรวจ และเอกสารที่ไม่ผ่านด่านหลังเสียเครดิตไปแล้วจบเป็น failed ทำให้ทางกู้คืนเดียวคือสแกนใหม่ด้วยมือ Change Request นี้เพิ่มหน้าคิวที่รวม JV ทุกใบที่ระบบเตรียมให้ BU จากสามแหล่ง (อีเมล, สแกนเอง, PMS) ให้คนตรวจและตัดสินก่อน post โดยค่าเริ่มต้นมีคนตรวจเสมอ

รายละเอียดการออกแบบอยู่ใน FRD-12 ซึ่งเป็นเอกสารออกแบบ (Software Design) ของงานนี้

## 1.2 ผู้ใช้และบริบท

- **ผู้ตรวจ:** พนักงานบัญชีของ BU ทุกคนที่มี session ของ BU นั้น ระบบไม่ตรวจบทบาทซ้ำ แต่บันทึกชื่อผู้ตัดสินไว้
- **จุดเข้า:** `#/CreditCardOCR` เป็นหน้าแรกของโมดูล AI JV Automation เปิดจากเมนูของ Carmen

## 1.3 ขอบเขต

| ทำ | ไม่ทำ |
|---|---|
| ตารางเดียวรวมสามแหล่ง แบ่ง Review และ All | ย้อนการปฏิเสธ — ต้องสแกนใหม่ |
| dialog ตรวจที่แก้หัวเอกสาร mapping และภาษีซื้อได้ | ดูไฟล์ต้นฉบับใน dialog — ระบบไม่เก็บไฟล์ |
| Approve แบบเห็นผลทันที และ Reject พร้อมเหตุผล | อนุมัติทีละหลายใบ |
| ปุ่มพาไปแก้สาเหตุ และยื่นภาษีซื้อย้อนหลัง | ส่งซ้ำอัตโนมัติ หรือแก้ JV ที่ post แล้ว |
| หยุดรับเมลเมื่อคิวเต็ม 50 ใบ | แจ้งเตือนทีละเอกสาร — กระดิ่งแจ้งเป็นยอดรวม |
