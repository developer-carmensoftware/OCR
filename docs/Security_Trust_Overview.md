# ความปลอดภัยและความเป็นส่วนตัวของข้อมูล — ภาพรวมสำหรับลูกค้า

_เอกสารฉบับนี้อธิบายว่าระบบ AI OCR ของเราดูแลข้อมูลการเงินของท่านอย่างไร เขียนสำหรับผู้บริหาร ฝ่าย IT และฝ่าย compliance ของลูกค้า — ไม่ใช่เอกสารเทคนิคภายใน ทุกข้อความในเอกสารนี้เป็นสิ่งที่ตรวจสอบได้จากการออกแบบระบบจริง_

อ้างอิงมาตรฐาน: **PDPA พ.ร.บ. 2562 · PCI DSS v4.0 · OWASP ASVS · ISO/IEC 27001 (roadmap)**

---

## 1. หลักการของเรา

เอกสารการเงิน (ใบแจ้งหนี้, statement บัตรเครดิต) คือข้อมูลที่อ่อนไหวที่สุดของธุรกิจท่าน หลักการออกแบบของเราจึงตรงไปตรงมา:

> **เราไม่เก็บสิ่งที่เราไม่จำเป็นต้องเก็บ**

ความปลอดภัยที่แข็งแรงที่สุดไม่ใช่ "เก็บข้อมูลไว้อย่างดี" แต่คือ **การไม่ถือครองข้อมูลตั้งแต่แรก** — เพราะสิ่งที่ไม่ได้ถูกเก็บ ย่อมรั่วไหลไม่ได้ นี่คือ *การรับประกันเชิงโครงสร้าง* ไม่ใช่แค่คำสัญญา

---

## 2. ข้อมูลของท่านไปที่ไหน (โปร่งใส 100%)

เมื่อท่านอัปโหลดเอกสารเพื่อให้ AI อ่าน ข้อมูลเดินทางผ่าน **บุคคลที่สามเพียง 2 รายเท่านั้น** ไม่มีรายอื่น:

| ผู้ประมวลผล (Sub-processor) | บทบาท | ข้อมูลที่เห็น |
| --- | --- | --- |
| **OpenRouter** | ตัวกลางส่งต่อคำขอ (LLM broker) | เอกสารที่ท่านส่ง (ระหว่างส่งต่อ) |
| **Google (Gemini)** | เครื่องมือ AI ที่อ่านเอกสาร | เอกสารที่ท่านส่ง (เพื่อประมวลผล) |

- ระบบของเราบันทึก **ทุกการเรียกออกไปยังภายนอก** (`outbound_call_logs`) — พิสูจน์ได้ว่าข้อมูลออกไปแค่ 2 ปลายทางนี้จริง ไม่มีปลายทางอื่นแอบแฝง
- เราเปิดเผยรายชื่อผู้ประมวลผลทั้งหมดให้ท่านทราบ และพร้อมจัดทำ **ข้อตกลงการประมวลผลข้อมูล (DPA)** ตาม PDPA ม.40

---

## 3. เราไม่เก็บอะไร (การลดข้อมูลให้น้อยที่สุด)

นี่คือหลักฐานที่แข็งแรงที่สุดของเรา — เป็นข้อจำกัดที่ฝังอยู่ในตัวระบบ:

| สิ่งที่ท่านอาจกังวล | สิ่งที่ระบบทำจริง |
| --- | --- |
| ไฟล์ภาพเอกสารถูกเก็บไว้ไหม? | **ไม่** — อ่านเข้าหน่วยความจำ ส่งให้ AI แล้วทิ้งทันที ไม่เขียนลงดิสก์ ไม่มีโฟลเดอร์เก็บไฟล์ |
| หมายเลขบัตรเครดิต (PAN) ถูกเก็บไหม? | **ไม่** — ฐานข้อมูลไม่มีช่องเก็บหมายเลขบัตรเลยแม้แต่ช่องเดียว |
| รายการ line item ในเอกสารถูกเก็บไหม? | **ไม่** — รายการธุรกรรมไม่ถูกบันทึกลงฐานข้อมูล (ระบบ ERP ของท่านคือแหล่งข้อมูลจริง) |
| ถ้าฐานข้อมูลเราถูกโจมตี จะรั่วอะไร? | **ไม่มีเอกสารการเงินให้รั่ว** — เพราะไม่มีอะไรถูกเก็บ ขอบเขตความเสียหายจึงแทบเป็นศูนย์ |

เราเก็บเฉพาะ **ข้อมูลหัวเอกสารขั้นต่ำ** (เลขที่เอกสาร, วันที่, รหัสธนาคาร, ชื่อบริษัท) เพื่อการอ้างอิงและป้องกันการยื่นซ้ำเท่านั้น

> **ข้อยกเว้นเดียว (เปิดเผยตรงไปตรงมา):** หากท่านซื้อเครดิตการใช้งานและอัปโหลด "สลิปการโอนเงิน" สลิปนั้นจะถูกเก็บไว้เพื่อเป็นหลักฐานการชำระเงิน/การตรวจสอบบัญชี ซึ่งเป็นข้อมูลคนละส่วนกับเอกสารที่ท่านนำมาประมวลผล

---

## 4. AI จะไม่เรียนรู้จากข้อมูลของท่าน — และเราพิสูจน์ให้ดูได้

เราแยกให้ชัดเจนระหว่าง "สิ่งที่พิสูจน์ได้เชิงเทคนิค" กับ "สิ่งที่คุ้มครองด้วยสัญญา" เพราะความโปร่งใสสำคัญกว่าคำโฆษณา:

**สิ่งที่เราพิสูจน์ได้ (เชิงเทคนิค):**

- ทุกครั้งที่เรียกใช้ AI ระบบแนบคำสั่ง **"ห้ามเก็บ/ห้ามนำไปฝึกโมเดล" (`data_collection: deny`)** ไปกับทุกคำขอ — บังคับที่ระดับโปรแกรม ไม่ใช่แค่การตั้งค่าใน dashboard ที่อาจเปลี่ยนโดยไม่รู้ตัว
- ระบบ **บันทึกหลักฐานของทุกคำขอ** ว่าได้ส่งคำสั่งนี้จริง และคำขอถูกประมวลผลโดยผู้ให้บริการรายใด — เราออก **รายงานการกำหนดเส้นทาง (routing report)** จากข้อมูลจริงให้ท่านตรวจสอบได้ว่า _"100% ของคำขอส่งคำสั่งห้ามฝึกโมเดล และ 0% หลุดออกนอกผู้ให้บริการที่อนุมัติ"_
- หากคำขอใดถูกส่งไปยังผู้ให้บริการนอกรายชื่อที่กำหนด ระบบจะ **บันทึกการแจ้งเตือนทันทีในระบบเฝ้าระวัง** (แสดงบนแดชบอร์ดผู้ดูแลระบบให้ทีมงานตรวจสอบ)
- สำหรับงานแนะนำผังบัญชี เราจำกัดให้ประมวลผลเฉพาะผู้ให้บริการในเขตอำนาจศาลที่กำหนด (provider allowlist)

**สิ่งที่คุ้มครองด้วยสัญญา (ไม่ใช่การพิสูจน์เชิงเทคนิค — เป็นความจริงสำหรับทุกบริการที่ใช้ cloud AI):**

- เมื่อข้อมูลถึงเซิร์ฟเวอร์ผู้ให้บริการ AI แล้ว ไม่มีระบบใดในโลกมองเห็นภายในได้ ส่วนนี้คุ้มครองด้วย **เงื่อนไขสัญญาผูกพันของผู้ให้บริการ** (เงื่อนไข API แบบชำระเงินห้ามนำข้อมูลไปฝึกโมเดล) และ **ใบรับรองความปลอดภัยอิสระของผู้ให้บริการ** ที่ท่านตรวจสอบเองได้

**หากท่านต้องการการพิสูจน์เต็มรูปแบบ:** เรามีทางเลือกประมวลผลแบบ self-host (ข้อมูลไม่ออกจากโครงสร้างพื้นฐานเลย) สำหรับลูกค้าที่มีข้อกำหนดสูงสุด

> เราเก็บเฉพาะ _คำสั่งที่ส่ง_ และ _ชื่อผู้ให้บริการที่ประมวลผล_ ไว้เป็นหลักฐาน — **ไม่เก็บเนื้อหาเอกสารของท่าน** (สอดคล้องกับข้อ 3)

## 5. ใครเข้าถึงได้ และตรวจสอบย้อนหลังได้ทุกการกระทำ

- **แยกข้อมูลระหว่างองค์กร (Tenant isolation):** ข้อมูลแต่ละองค์กรถูกแยกด้วย tenant ID ทุกคำสั่ง องค์กรหนึ่งเห็นข้อมูลของอีกองค์กรไม่ได้
- **บันทึกการตรวจสอบ (Audit trail):** ทุกการอ่านเอกสาร / ยื่นข้อมูล / เปลี่ยนการตั้งค่า ถูกบันทึกแบบเพิ่มได้อย่างเดียว (append-only) พร้อมระบุผู้กระทำ, IP และค่าก่อน/หลัง เก็บ 24 เดือน
- **บันทึกความยินยอม (Consent record):** ความยินยอมการใช้ฟีเจอร์ AI ถูกบันทึกฝั่งเซิร์ฟเวอร์ (ใคร เมื่อไหร่ เวอร์ชันใด) ตาม PDPA ม.19
- **ควบคุมสิทธิ์ผู้ดูแล (RBAC):** ระบบผู้ดูแลใช้กุญแจยืนยันตัวตนแยกต่างหาก และเข้ารหัส session token

---

## 6. การเข้ารหัสและโครงสร้างพื้นฐาน

- **ระหว่างส่งข้อมูล (In-transit):** เข้ารหัส TLS ทุกการเชื่อมต่อ + บังคับ HTTPS (HSTS)
- **ขณะจัดเก็บ (At-rest):** ฐานข้อมูลเข้ารหัสตามมาตรฐานผู้ให้บริการคลาวด์
- **ป้องกันระดับแอปพลิเคชัน:** Security headers (ป้องกัน clickjacking / MIME sniffing), นโยบาย CORS เข้มงวด (ปฏิเสธการเริ่มระบบหากตั้งค่าหลวมในโปรดักชัน), จำกัดอัตราการเรียก (rate limiting)
- ระบบตรวจจับข้อผิดพลาดถูกตั้งค่า **ไม่ให้ส่งข้อมูลส่วนบุคคลออกไป** (PII scrubbing)

---

## 7. การพัฒนาอย่างปลอดภัย

- **สแกนช่องโหว่อัตโนมัติทุกการเปลี่ยนแปลงโค้ด** (CodeQL) และตรวจสอบ dependency ที่มีช่องโหว่อัตโนมัติ (Dependabot)
- ควบคุมความลับ (secrets) แยกจากฐานข้อมูล ไม่ hardcode

---

## 8. ท่านคือผู้ควบคุม

- ฟีเจอร์ AI เป็น **ทางเลือกเสริม** — ไม่บังคับใช้ ท่านใช้งานระบบในรูปแบบปกติต่อไปได้
- ระบบ **ไม่ยื่นข้อมูลอัตโนมัติ** — AI อ่านเอกสารและแสดงผลให้ตรวจ ท่านต้องกดยืนยันเองก่อนข้อมูลจะเข้าสู่ระบบ ERP ทุกครั้ง (สำคัญมากสำหรับความถูกต้องทางการเงิน)
- ท่านสามารถขอใช้สิทธิ์ตาม PDPA (เข้าถึง, แก้ไข, ลบ) ได้

---

## 9. มาตรฐานและ Roadmap (ซื่อสัตย์ในสิ่งที่มีและยังไม่มี)

| รายการ | สถานะ |
| --- | --- |
| PDPA — การลดข้อมูล, consent record, audit trail | ✅ ปฏิบัติแล้ว |
| การบังคับ no-training ระดับคำขอ | ✅ ปฏิบัติแล้ว |
| บันทึกหลักฐานการกำหนดเส้นทาง + routing report (ตรวจสอบได้ว่าส่งคำสั่ง no-train จริง + route ไปไหน) | ✅ ปฏิบัติแล้ว |
| การสแกนความปลอดภัยอัตโนมัติใน CI | ✅ ปฏิบัติแล้ว |
| ข้อตกลงประมวลผลข้อมูล (DPA) + Privacy Notice ที่เป็นลายลักษณ์อักษร | 🔄 กำลังดำเนินการ |
| SOC 2 Type II / ISO 27001 (การรับรองโดยผู้ตรวจสอบอิสระ) | 🗺️ อยู่ใน roadmap |

เราจะไม่กล่าวอ้างการรับรองที่เรายังไม่ได้รับ

---

## 10. ติดต่อ

สำหรับคำขอ DPA, รายละเอียดเชิงเทคนิคเพิ่มเติม, หรือคำถามด้านความปลอดภัยและ compliance — กรุณาติดต่อทีมงานของเรา เรายินดีให้ข้อมูลเชิงลึกและร่วมทำแบบประเมินความปลอดภัยกับฝ่าย IT ของท่าน
